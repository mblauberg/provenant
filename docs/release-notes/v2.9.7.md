# Provenant v2.9.7

Released 26 November 2026.

Provenant 2.9.7 is a reliability release for unattended lanes. Writer lanes no longer open pull requests unless `lanes.pr` allows it, a lane's outcome comes from its refs and handoff rather than the stop path, and relaunching in a just-stopped worktree no longer races the stop. Steering a running lane queues for its next turn, re-pins successors only to a descendant head, and GC keeps a settling attempt's scratch. `output --final --to FILE` exports the full result, and `status --full` scans the host once per listing.

## Behaviour changes

- A new sourced knob `lanes.pr = never | draft | allowed` governs pull-request writes from a lane. It defaults to `never`, so an implement writer lane no longer opens a pull request (including against the wrong base); the chair publishes after settlement. Under `never` the lane's `gh` refuses PR mutations and mutating forge API calls. Under `draft` it adds `--draft` to `pr create`, permits edit, close, comment and review, and refuses other PR and forge writes. Both restrictive policies refuse unknown PR subcommands until they are classified, allow explicit GET and HEAD `gh api` queries with fields, and classify commands the same way when `-R`/`--repo` or `--hostname` selectors come first. `allowed` forwards unchanged. A graph node opts in with `attempt.pr = "draft"` or `"allowed"` (or `--set attempt.pr=draft`), and the policy travels with the node to a peer. The wrapper is installed whether or not `lanes.publish` delivers credentials. The effective value and its source appear in the writer preamble, the launch receipt and `run --explain`. The policy mediates ordinary `gh` use; it is not a sandbox, and a wrapper that cannot be installed is reported as a warning. [#3989](https://github.com/mblauberg/provenant/issues/3989)

## Additions

- Review lanes now ship the host-pinned base as the named ref `refs/provenant/review/base` in their detached view and state in the preamble that the host-supplied base and head are authoritative. A review no longer goes `inconclusive` because its detached checkout lacks `origin/<default>` and the lane cannot fetch to confirm the merge base. (#3977)

## Fixes

### CLI and install

- `provenant gc` collects eligible attempt scratch before its advisory process census and reports candidate progress, so a large census no longer consumes the collection budget. [#3966](https://github.com/mblauberg/provenant/issues/3966)
- Deferred scratch reports use the current `attempt-scratch` paths and their retained byte measurements.
- `status --full` gathers the run store, admission holders, worktree index and process census once per listing instead of once per graph, so a fleet-wide page no longer repeats the same host-wide scans for every graph. The admission summary reuses the holder reading, and the process census stays lazy for local attempts. (#3976)
- `retry N` now infers the only node of a settled one-node graph instead of refusing with `provenant retry N/NODE`; a wider graph still needs an explicit node. (#3976)
- A stale `run review --head SHA` refusal now names `--head`, says the supplied head is not the pull request's head and shows both SHAs with a repair that names the pinned head once the push is visible, instead of the generic "check the named input field and retry". (#3976)
- `output` on a settled lane that already carries a result, including a failed lane while a sibling is unfinished, no longer appends the graph's failure rows, so a completed review lane no longer ends with stale "unreadable" attempt status lines; unsettled work and lanes without a result keep their diagnostics. (#3976)
- `output --part receipt --json` now reports sourced provenance for every
  adapter: the family comes from the effective routing catalogue, including
  discovery and overlays. OpenCode Hy4 models are included alongside the
  existing DeepSeek, Z.ai and OpenAI families. The
  effort carries its applied value and source when a drop or default was
  recorded; a request alone leaves effort and its source `unknown`.
  `resolved_from` names the launch decision for dispatched
  named-route lanes. The `role` field is pinned for both reviewer and writer
  lanes. (#3978)
- `provenant output TARGET --final --to FILE` exports the complete sealed lane result, including long final messages and handoffs, even when they span output pages. The default view remains bounded. (#3990)

### Lanes and settlement

- `provenant reconcile --abandon` clears the Git registration of a writer checkout that was removed by hand when that registration proves the abandoned lane's ownership, so its branch is no longer checked out at a missing path and no later worktree create fails with `StaleRegistration`. Only that one registration is removed; a locked, ambiguous or foreign registration is left alone and warned about with the exact `git -C <common> worktree prune` remedy. (#3906)
- GC coordinates collection with the settlement driver and retains a launched attempt's scratch until settlement completes, including between retries and when ownership cannot be determined, so a writer's private Git objects and a review source checkout are not collected mid-settlement and a correct commit is no longer reported as a failed import. Existing custody diagnostics remain visible. (#3975)
- `provenant upgrade --verify --host <peer>` and `provenant run smoke --host <peer>` now stage the read node's fixture into the peer's own provider scratch and name its path in the brief, instead of relying on a caller-local fixture path the peer cannot see. A graph node may declare a small project-relative fixture; the host carries its bytes with the submission, so no sender path crosses the boundary. A remote smoke writer now runs through a peer-owned worktree: `--branch` (with optional `--base`) is carried as provisioning intent and the peer creates the worktree in its own clone, rather than skipping the write node with "remote placement does not accept caller paths". (#3979)
- Relaunch in a just-stopped worktree no longer races its release. `provenant stop` acknowledges a cancellation as soon as the stop intent is durable, while the guardian still publishes the terminal record and clears the worktree's writer reservation afterwards. A launch into that worktree now waits, within the store's sourced lock budget, when the slot shows a matching durable stop intent or a release already in progress, and wakes as soon as `writer.lock` is free. Graph launches classify a settling writer lease as bounded contention and report a retry wake instead of settling `blocked` immediately. A live holder without release evidence still refuses at the first probe, so another lane's uncommitted work is never adopted. (#3991)

### Accounts, quota and routing

- Claude lanes no longer launch on a stale login after an account switch. A recorded Claude login failure is cleared at launch only by a probe that inspects the account credential; a CLI `auth status --json` answer still names the original account after its credentials were replaced, so it cannot clear the failure. Launch selects a logged-in account or refuses with the account name and its `claude auth login` remedy. (#3974)

### Pipelines and graphs

- A lane's outcome now comes from observed refs and its sealed handoff, not from the stop path that reported it. Commits ahead of the node's input head count whether or not they were pushed, and a `done` handoff closes the brief, so a writer that committed and pushed with a done handoff no longer reports `review_required` with `outcome=declared_stop` and `cause=stopped_no_work`. (#3988)
- A stop with new commits records `writer_declared_stop`; `stopped_no_work` is reserved for a stop that left no new commit.

### Fabric

- Steering a running lane queues the note for its next turn without interrupting the attempt. When a retained session is unavailable, the configured fallback determines whether to start fresh with a handoff or leave the note without a successor. (#3959)
- A finished task no longer creates an automatic follow-up. Queued steering on a successful attempt stays accepted but resolves as not-continued, so a second task cannot refuse at preparation and hide the successful attempt. (#3987)
- A writer-lineage failure at launch is a typed `preparation_refused` outcome whose note names the retained worktree's owner, source and head to repair, instead of an "invalid run record" telling the operator to reconcile. Status keeps showing the latest successful attempt, its result path and its summary; a preparation refusal that never launched remains visible in its own operation outcome. (#3987)
- A new graph can adopt a retained writer worktree from a finished attempt in an earlier graph when the writer, terminal record, released custody and lane owner match. It inherits the tree and its commits, not the earlier graph's source and head pins. (#3987)
- A steer successor now re-pins automatically when the lane's retained writer committed after its predecessor was sealed: it adopts the descendant head, keeps the original source pin and warns with both ids. A head that moved under different custody stays a typed continuation refusal, pausing the graph for retry even when preparation refuses after admission or all nodes are settled, and a route without a resumable session still continues through `fresh_with_handoff`. (#3997)
