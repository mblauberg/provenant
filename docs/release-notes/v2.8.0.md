# Provenant v2.8.0

Released 23 November 2026.

Provenant 2.8.0 finishes the move to one build model: lanes format only, and the lane build strategies, Cargo target seeding and lane Cargo knobs are gone, so remove those keys from your configuration. It also stops a deleted registered project from refusing every later launch, a state `upgrade --verify` used to leave behind.

## Breaking changes

- Lane build strategies and Cargo target seeding are removed: lanes format only, the chair runs one warm integrated check per epic, and CI runs clippy and tests. Action: remove `build.wrapper`, `build.command`, `build.seed`, `lanes.cargo_target`, `lanes.cargo_seed_budget`, `lanes.local_cargo`, `domains.fabric.lanes.cargo_seed`, `domains.fabric.lanes.cargo_build_jobs` and `domains.fabric.lanes.cargo_debug` from your configuration; a leftover key now warns as unknown. The chair's `build.strategy = "slots"` and `[admission.build]` cap remain for the host-owned check. The writer preamble set by `lanes.verification` now tells lanes to format only and names what the chair's check and CI will run, and lanes no longer receive `CARGO_BUILD_JOBS` or `PROVENANT_BUILD_CONTEXT`. #3790

## Behaviour changes

- `provenant workflow session save --project PATH` now warns and saves under the selected project when `PATH` names a project other than the working directory's, instead of refusing with `SESSION_PROJECT_MISMATCH`. The warning names both paths in the JSON `warnings` and the human output; a session registered under another project still needs an explicit `--project PATH` to be saved from elsewhere.

## Fixes

- `provenant upgrade --verify` removes its scratch project's binding, and launch confinement, tick settlement and forge polling skip a registered project whose common directory is gone instead of refusing unrelated launches. A project with an unreadable layout now protects its root and warns, and `provenant gc` retires dead bindings after the idle lifetime. (#3792)
