# Provenant v2.8.2

Released 23 November 2026.

Provenant 2.8.2 lets a lane rebase or merge its own branch under sourced `lanes.history.*` settings, settles lanes whose result files have loose modes, and admits batch documents without pre-created slice worktrees. It also stops creating lane Cargo caches, ends the gc decode errors from retired record fields, and moves Claude answer delivery to `PostToolUse`.

From this release on, `provenant upgrade --verify` verifies with the installed binary (#3799). An upgrade from 2.8.1 still runs 2.8.1's verifier, so run `provenant upgrade --verify` once more after upgrading to check the install with 2.8.2's own verifier.

## Behaviour changes

- Claude Code answer delivery now runs on `PostToolUse` instead of `PreToolUse`:
  a Provenant hook failure can no longer make Claude refuse a Bash or Read call,
  and queued answers still reach the chair through `additionalContext`. Existing
  installs drop the managed `PreToolUse` entry on upgrade and register the
  `PostToolUse` replacement under the ownership their receipt already records,
  so an upgrade without `--hooks on` keeps native answer delivery; foreign hooks
  on either event stay untouched; Codex keeps its declared `PreToolUse` mapping. A
  hook that fails inside Provenant still abstains with exit 0, but now records
  its cause and duration under `<state>/hooks/diagnostics/failures.jsonl`. (#3803)
- `provenant help` resolves nested command paths and refuses an unknown component with an error that lists the valid commands at that level (words after a command that takes arguments, as in `help run implement`, stay that command's arguments); `help --all` lists the global options once at the top instead of repeating them in every usage block. `config path [DIR]` takes an optional directory in place of the ignored `--project` flag, and the `pr` and `worktree create --base` help now describes what they do. (#3808 #3814)
- A lane may rebase or merge its own branch. When its history diverged from the
  host lane branch, publication now merges the host branch into the lane tip and
  publishes the merge. A real conflict, unrelated histories, a configured
  `merge.*.driver` or a branch rewound behind its launch base retains the
  private commits with a typed cause, as does `lanes.history.rebase = "refuse"`.
  The unrooted decision judges the lane head before any merge, so a host merge
  cannot supply ancestry the head lacks; its `warn` and `off` values never
  override an unrelated-history refusal, and a branch rewound behind its launch
  base is judged before the unrooted tip. Four sourced settings control this:
  `lanes.history.rebase` (`allow` by default), `lanes.history.unrooted_tip`
  (`warn`), `lanes.history.conflict_markers` (`warn`) and
  `lanes.history.default_branch_rewrite` (`refuse`, host-only owner gate). Every
  warning and refusal names the setting and its source, an unrecognised value
  warns with its layer and keeps the documented default, and
  `domains.run.push_conflict_markers` is replaced by
  `lanes.history.conflict_markers`. (#3806)

## Additions

- **Start here:** the [one-page quickstart](../quickstart.md) runs a first install
  through `provenant check install`, account registration, a read-only lane and a
  first writer; the documentation index, the README and the
  [install runbook](../runbooks/install.md) now lead with it, with upgrade
  material after first install. The one-accountable-chair ownership rule now has
  its durable home in the `orchestrate` skill. #3784 #3814
- `verify.tiers[].commands[]` in `ports.json` now accepts a shell-word string as
  shorthand for a `TierCommand` table: `cargo fmt {packages} -- --check` splits
  into argv without a shell, with `stack` and `cwd` left at their defaults. A
  string that does not split warns as a malformed tier command and names its
  leaf. (#3812)
- The bundled `smoke` graph now declares `retry-probe` and `steer-probe` probes
  beside `read`, `review` and `write`, on the same free-capable `junior` tier as
  the rest of the graph. Both are overridable like the other nodes:
  `--set retry_probe=false` and `--set steer_probe=false` skip them, and
  `upgrade --verify --dry-run` lists them by node id. A failing probe is
  reported by name during `upgrade --verify`, as any other smoke node is.

  The probes check that a smoke run has a route for the retry and steer paths;
  they do not retry a failed node or steer a running lane. Driving those
  operations from `upgrade --verify` would need the verifier to launch a graph
  that fails on purpose and then invoke the controls, which this change does not
  do. (#3502)

## Fixes

### CLI and install

- `provenant gc` now protects the default branch on every retirement path. A
  remote ledger record naming the default branch is retained when no target was
  fetched, both in dry-run and when the remote default cannot be read; a linked
  worktree checked out on the default branch is never retired even when the
  primary checkout is elsewhere; and branches excluded by the retirement scope
  now report as Retained with a reason instead of vanishing from the preview.
  (#3768)
- `provenant upgrade --verify` gives the smoke graph's review nodes a real
  range: the scratch fixture now commits a base and a fixture change, and the
  launch pins the review base to that commit while the writer still starts at
  `HEAD`. The bundled `smoke` template accepts an optional `diff_base` binding;
  `--verify` and `--dry-run` supply the fixture's base so those reviews have a
  non-empty subject to inspect, while an unbound `diff_base` leaves the review
  nodes unpinned and keeps the normal no-base refusal. A healthy install
  reports `smoke: true` again. (#3798)
- `provenant upgrade --verify` now re-executes the installed destination binary
  to run its smoke verification, so the verifier that ships in a release is the
  one that checks that release; the report names the version that verified.
  Install also retires a leftover `cargo-target-seeds/` directory under the state
  root, reporting its path and size once, and the smoke fixture leaves no
  registered scratch project for `tick` to read. (#3799 #3813 #3812)
- The menu bar no longer starts twice after an upgrade. The bundled helper now
  lives in `Provenant Console.app/Contents/MacOS` and runs only from the
  `dev.provenant.quota-menubar` LaunchAgent; install removes the old login-item
  app and its launchd registration once the installed app already runs that
  helper. A kept app that predates the helper may still be launched through the
  nested bundle, so install leaves that bundle alone and `provenant check install`
  warns instead of refusing while a leftover remains. A new helper replaces a
  live older instance at startup, so an upgraded binary takes over and the
  previous menu bar process quits: it signals only a PID still running this app's
  executable, writes the marker with a temporary file and rename, and re-reads it
  after a short delay so the loser of a concurrent start exits. (#3805)
- `provenant check install` now names `provenant upgrade` (or manual bundle and
  launchd removal) for a leftover menu login item; `provenant install` never
  removed it. (#3805)
- `provenant output` now omits a result's header lines when their value is JSON
  `null`: a present key with no value no longer prints an `unavailable` line for
  the base, committed head, publication, residual tree state or changed files.
  (#3807)
- `provenant output ATTEMPT` on a running attempt now exits 0, carries
  `status: running` in the envelope and labels the page instead of refusing with
  `NONTERMINAL`: `partial` when bytes arrived before settlement, and
  `no result yet` when the result is not sealed. (#3809)
- `provenant check install` now verifies the roots recorded in the install receipt rather than targets derived from the caller's `HOME`, so a healthy install reports no findings when the check runs from a lane or any account-directory `HOME`. (#3811)
- Worktree and settlement commands no longer print an EPERM custody warning for
  other users' and system processes: only processes whose kernel credentials
  could own the checked-out worktree count towards it, and a same-user process
  that cannot be inspected still warns. An empty cohort prints nothing. (#3818)

### Lanes and settlement

- Token-budget settlement no longer promotes a truncated provider result to `Succeeded`: one gate decides success from the valid done handoff, and the decoder's completeness is kept, so a non-empty but incomplete answer settles as incomplete. An empty answer still keeps its handoff-fence substitution but settles as a review record. #3405
- A build waiter no longer fails admission when another lane's liveness scan holds its ticket lock for the moment before its own flock lands; the waiter waits out that transient hold instead of reporting a zero-timeout refusal. (#3804)
- Settlement no longer stalls when a lane leaves `result.md`, the `handoff.json`
  snapshot or its progress handoff group- or world-readable in its private
  attempt directory: settlement's own read tightens each provider-written
  settlement input through its open descriptor, warns with the path and old
  mode, and settles. The inputs are a class on `AttemptFile`, not one hard-coded
  name, so another provider-written input is covered by declaring it there.
  Host-written private records and later presentation reads still refuse an
  over-broad mode rather than repairing it. A symlinked or escaping input still
  refuses, and the stalled reason names the remedy. (#3818)

### Accounts, quota and routing

- A model-only pin whose account admission refused now records the real
  exclusion cause (provider, free-tier or mismatch) instead of exhaustion, and
  when the redraw to another account cannot serve the intent the pinned route is
  attempted once on its refused account with the recorded warning. That final
  attempt is limited to advisory recorded refusals (exhaustion, pacing or a
  provider/free-tier refusal); a missing login, confinement refusal or another
  non-advisory cause is not retried. Advisory expiries come only from a reset in
  the future, so an expired availability record cannot justify the attempt.
  (#3764)
- The routing catalogue now includes both OpenCode Go and Zen `hy4-flash-free`
  routes, marked free with zero-retention evidence, so launches that select
  them no longer warn that the model is not in the catalogue. The existing
  Go `deepseek-v4.1-flash` entry remains catalogued and paid. (#3818)

### Fabric

- A lane can now read the `status`, `output` and `trace` of any graph launched
  by its own chair session, so a repair lane sees the chair's full review output
  instead of working from its brief. The chair session sealed on each graph's
  custody record decides the scope: no new launch flag or per-graph grant. A
  graph from another chair session or another project still reads `not_found`,
  and steer, stop and retry stay confined to the lane's own graph. (#3192)
- Batch documents with local integration admit host-planned slice worktrees
  without pre-creating them, then provision both checkouts; the integrate-target
  check skips a writer that has no branch until provisioning. `worktree_missing`
  now names the path and node in its message, diagnostic and JSON error. A
  provider-relative model such as `opencode-go/<model>` is canonicalised with its
  adapter instead of producing an unnamed `invalid_input`, and every invalid
  launch input names the field and reason it rejected. Relative writer paths
  resolve from the project's primary root from every checkout, and
  `run --explain` runs the same admission checks as a launch. (#3821)

### Telemetry and providers

- OpenCode lane launches pass `--archived`, keeping lane sessions out of the
  owner's OpenCode session lists. (#3710)

- The launch policy a run resolved is dispatch state, not part of a request or
  an attempt record. `HarnessProfile` no longer has a `launch_policy` field, so
  a base-12 sealed `request.json`, which is digest-bound and never rewritten,
  still reads with the old subtree as an unknown extra field. Current writers
  no longer copy the policy, and `resume` and settlement resolve it from
  current host, project and dispatch settings; dispatch overrides remain sealed
  in the profile.
- A writable open migrates the run store from base 12 to 13. A `lane_cache`
  write grant is filtered out; another grant, an absent `write_grants` field
  and unrelated fields are left alone. An attempt row's retired
  `profile.launch_policy` snapshot is left in place because the current
  `HarnessProfile` reads it as an unknown extra field and the sealed request
  keeps the authoritative copy. The grant walk is total for any valid JSON: a
  non-array `write_grants` or a non-object element is skipped rather than
  aborting the migration. A row whose bytes are not valid JSON is skipped so it
  fails only its own decode instead of aborting every writable open. The two
  retired names `git_isolation` and `data_integrity` are no longer accepted by
  the current types, and the prior aliases and discard-on-decode path are gone.
  `gc` no longer reports a decode error for those rows and the tick agent no
  longer exits 3 every minute. A retention error now names the attempt row
  rather than its `provider-state` child path. (#3801)
- Writer launches no longer create a private lane Cargo cache under
  `Library/Caches/provenant-lane-cargo`, write its ownership marker and
  `CACHEDIR.TAG`, or export `CARGO_TARGET_DIR` and `CARGO_BUILD_BUILD_DIR`
  into it. Lanes do not build; writer Cargo uses its worktree default, and the
  formerly Stable `PROVENANT_LANE_CARGO_LINT_TARGET` is removed from every lane
  environment because its only producer, the lane cache, is gone. `gc`
  still retires existing leftovers: a cache holding only its ownership marker
  and directory tag is reclaimed in one pass whatever its owning project, while
  a cache with build output in another project is still kept as foreign.
  (#3802)
