# Provenant v1.4.0

Released 30 October 2026.

This release reworks the skills around presets, improves configuration editing, console access and lane recovery, and adds usage and quota reporting. Some changes need action on upgrade; see Breaking changes.

Provenant makes no stability promise; see [stability](../release-notes/README.md#stability).

## Breaking changes

- **A pending `run --wait` now returns `waiting` with exit 0.** Update scripts that expect `timeout` and exit 124; the output names the command to continue waiting (#2350).
- **`worktree adopt` is removed.** Use Git-created linked checkouts directly; Git's inventory now establishes membership, including checkouts recreated at a previously used path (#2162).
- **Routing schedules now use RFC 3339 timestamps.** Replace Unix seconds in `schedule.starts` and `schedule.expires` on policy rules and pacing overrides with quoted timestamps such as `"2026-11-01T00:00:00Z"`; numeric values are dropped with a warning. Consumers of `route list --json` must also read `expires` instead of `expires_unix_seconds` (#2271).
- **The `tdd` skill is renamed `test-design`.** Update personal references to `/tdd`; it still responds to requests for TDD. The retired `autopilot`, `work-map`, `grill-me` and `prototype` skills have moved into `session`, `tracker` and `scope` (#2350).

## Behaviour changes

### CLI and install

- `provenant lanes --all` lists the newest lanes first. The default listing keeps its order (#2350).
- A lane selection that matches nothing asks for a unique prefix of 8 or more characters or the full ID. When a peer is configured it also names `--host HOST` for that peer's lanes (#2350).
- `provenant disk report` prints the volume and each class total as plain key-value lines instead of an escaped JSON string. The JSON output is unchanged (#2350).
- Failed lane listings and wait summaries show the last provider error line when available. Peer `output --path` reports that paths are unsupported instead of returning file contents (#2350).

### Lanes and settlement

- An uncatalogued model, or an effort the catalogue does not record for that model, is refused at submit with the nearest catalogued IDs or the supported efforts, before any run record exists (#2350).
- A `--worktree` that is detached or whose writer is busy is refused at submit and names the HEAD or the holder attempt. A replayed operation ID still returns its original run (#2350).
- A launch failure says which step failed, such as "launch preparation failed: publication reservation: ...", instead of the bare cause (#2350).

### Git and safety

- Managed worktree creation and status now accept a tracked gitlink whose checkout is not initialised, because it has no nested Git configuration to run. An initialised gitlink still reports unknown and requires review (#2284).

### Accounts, quota and routing

- Bundled model policy now supplies routing defaults, and `[domains.routing.writer_advisory]` can override writer cost advice. Existing configuration and account rules take precedence (#2272).
- Free models are ordinary pool members and need no opt-in. The junior pool favours free OpenCode DeepSeek V4.1 Flash and GLM-5.3 Flash when available (#2309).
- Explicitly selecting an OpenCode model outside the four catalogue routes is refused, and the refusal names the four admitted routes: the free and Go DeepSeek V4.1 Flash and GLM-5.3 Flash variants. Other OpenCode models, including GLM 5.2, are no longer catalogued (#2350).

### Pipelines and graphs

- Projects can opt into stable work-item assignments across preset control and candidate arms, record the experiment seed and arm on graphs, run shadow assignments on the control preset, and inspect stratified offline outcome comparisons with `telemetry experiments show` (#2210).
- Automatic preset selection accepts `--task-id`, so a work item can take part in an experiment. `--preset` still cannot be combined with `--task-id` (#2210).
- Plan nodes can offer typed, allow-listed patterns for fragments to instantiate (#2212).
- Planner fragments now require a literal `write_scope` only for writer children. Read-only children may omit it, while a writer without a scope is still refused (#2284).

### Chair, inbox and console

- `chair log append` now reports the stable error code `IN_LANE` when a lane tries to append, matching `workflow session save`. It was `CHAIR_LOG` (#2273).
- `pr open` and `pr contributions --bind` now report specific error codes (`PR_FILE_UNREADABLE`, `PR_SUMMARY_EMPTY`, `PR_ATTEMPT_STATE`, `PR_PROJECT_UNBOUND`) where they reported `PR` or `PR_CONTRIBUTIONS` (#2273).
- `workflow session` commands now report `SESSION_PROJECT_MISSING` or `SESSION_PROJECT_MISMATCH` when the project cannot be resolved or does not match, and `INVALID` for an unusable checkout or state root, where they reported `ROOT` (#2273).
- A lane may now change the bounded viewer presentation fields `seen_revision`, `snoozed_until` and `dismissed` for a request. It still cannot answer, resolve or unblock the request, and summary baselines remain outside a lane (#2284).

### Fabric and MCP

- Local stores now set one SQLite busy timeout when they open and wait inside SQLite instead of retrying each call under a per-call budget. A contended store waits up to `domains.fabric.limits.store_busy_timeout_ms` (30 seconds by default; 0 fails fast) before it reports contention, and the stores' advisory locks share that bound. Hook delivery still stops at its own deadline (#2163).
- Peer code transport fetches committed heads with `git fetch` into `refs/provenant/transport/<operation>/` refs, with `fsckObjects` and a forced `index-pack`, instead of writing and verifying bundle files. Commits over 64 MiB now transport; corrupt, missing, duplicate and malformed objects are still refused (#2166).
- The macOS peer agent no longer caps concurrent requests at 16 or answers a busy frame; every accepted request is relayed (#2166).
- `--set key+=value` appends to a list preset parameter and is refused on scalars. Expansion refuses a composite `inputs` or `exports` selection that its source node cannot supply, naming both nodes (#2280).
- Lanes send Fabric messages, tasks, notes and advisory claims through their host under their attempt identity, without write access to the Fabric database. Lane CLI `fabric ... send` remains refused (#2285).

### Telemetry and providers

- `provenant telemetry stats` now names the project its figures cover and how many queued or running attempts it leaves out, and says how to see other projects. Its `--by` groups with no work context are labelled `unattributed`. Reasoning tokens get their own line when a provider reports them. A host chair cost is no longer shown as complete while some chair sessions could not be read (#2350).

## Additions

### CLI and install

- Linux install and upgrade configure a systemd user timer to run `provenant tick` every 60 seconds; uninstall removes it (#2237).
- `config schema --json` lists editable fields and their effective values, and `config show --json` reports a revision. `config apply --file PATCH.json --expect-revision REV [--dry-run]` validates an atomic patch and refuses stale revisions; `config history` lists applied changes with secret-looking values redacted (#2310).

### Lanes and settlement

- `provenant output --to FILE` writes the selected range to FILE, replacing it, so a large part can be saved without printing it; page on with `--offset`. `provenant output --path` prints where the attempt keeps its `result`, `prompt` or `stderr` file, for `--part` result, prompt or stderr (#2350).
- `provenant output RUN` and `provenant output RUN/TASK` read the newest settled attempt of that run or task and name the attempt they chose. A run that has several tasks asks for RUN/TASK. A failed attempt's output names the last line of its provider error and its result path (#2350).
- `provenant lanes --json` rows gain `handoff`, the attempt's parsed handoff block or null, and `settlement`, which holds the settled `reason` for a settled lane and is null otherwise (#2350).
- A `review_required` lane prints `next: provenant lane deliver --accept-review ATTEMPT` with its own attempt ID, so the chair can see how to accept the review (#2350).

### Git and safety

- Set `[domains.run] push_conflict_markers = false` to turn off the advisory literal conflict-marker check in the Git pre-push hook, for fixtures that intentionally contain markers. Default-branch deletion, non-fast-forward updates and linked-worktree default-branch pushes are still refused (#2284).

### Accounts, quota and routing

- Route pacing `--starts` and `--until` accept weeks and compound durations such as `1w` and `1h30m`, matching the duration suffixes used for provider reset messages and quota windows (#2271).
- Provider quota windows and reset messages recognise additional duration suffixes, including compound windows, seconds and weeks (#2271).
- `[domains.quota.polling_intervals.<adapter>]` sets `timer_seconds` and/or `panel_seconds` for each registered adapter. Omitted values keep the provider default. Quota ticks, `quota show` staleness and routing admission use the configured values. See the [configuration runbook](../runbooks/configuration.md#quota-polling-intervals) (#2272).
- `[domains.quota]` now accepts `max_parallel` up to 16 and `wall_budget_seconds` up to 600, so a host can raise the probe batch size and wall budget above the unchanged defaults of 3 and 55 (#2284).

### Pipelines and graphs

- Optional `host-native` routes can run a configured Claude Code agent as a fresh lane, including the `deliver` repairer. Graphs require an ordinary fallback route, and repaired commits still pass the CI gate before review or land (#2244; see [host-native repairs](../runbooks/presets.md#host-native-repairs)).
- Fabric graph checkpoints include optional `pause_code`, node `advance_error_code` and `loop_pause_code`, and answer `rejection_code` fields so callers can identify refusals without parsing the accompanying messages (#2273).

### Chair, inbox and console

- `provenant steer` and `provenant chair message` queue a bounded, idempotent control message, and `provenant help --all --json` publishes a `provider_controls` capability matrix per adapter and launch kind. Chair messages go to the exact registered session as Fabric mail; steering refuses with `control_unsupported` because no lane adapter offers live control. Neither can approve a gate, merge or landing. `fabric_inbox` gains `steer` and `chair_message` (#2311).
- `provenant fabric mail read` and `mark-read` take `--session` (MCP `fabric_mail` takes `session`) to read a chair session's control mail with its own cursor, so sessions that share an agent label cannot read or consume each other's messages (#2311).
- `console detail` shows an attempt's routes, usage, trace, timings and artefact sizes. `console search` searches local prompts and results with bounded scanning and cursors; both are available through `fabric_console` (#2312).
- `console changes --json` reports owner-issued local change generations so console clients can refresh when state changes (#2313).
- A committed Fabric, quota, configuration, chair or log write no longer fails when its change signal cannot be published. The signal is only a hint, and a stray signal file is replaced by the next write (#2313).
- A native console app opens an inbox window over the shared Swift client. It lists pending decisions, assumptions and questions, answers them with `--expect-revision` on the `console` channel, and refreshes on window focus and on request. `provenant console open` opens it on macOS and gives an install hint when it is absent (#2314).

### Telemetry and providers

- `provenant telemetry stats --suggest` compares pipeline patterns, lenses and models using verified findings per dollar, false-positive rates and escaped-defect rates. Advisory suggestions carry evidence, intervals and an expiry; no policy is changed automatically (#2011).
- `provenant telemetry stats --outcomes` attributes local reverts, line-overlapping follow-up fixes and an optional recorded main-branch CI export to originating pipeline evidence within a configurable 14-day window. Missing CI input is reported as unmeasured (#2211).
- `provenant telemetry ingest` records native Claude chair, sub-agent and lane usage per account from `~/.claude*` transcripts, keyed by session and message so a re-run adds nothing, and the chair's SessionStart hook runs it automatically within a three-second budget. Usage is attributed by config directory; unregistered directories are reported as `unattributed` rather than dropped, and no prompt or reply text is stored (#2239).
- `provenant telemetry mileage` reports the API-equivalent cost of a quota percentage point and a full window from quota history and ingested usage, splitting runs at resets, drops and plan changes and flagging capacity step changes only with enough priced segments. It also reports potential and realised effective rates per token bucket, with the latest used percentage, sample size, priced coverage and a lower-bound note on every effective report, since ingest coverage is not checked (#2240).
- `provenant telemetry prices refresh` fetches OpenRouter and LiteLLM prices and writes a proposed diff with source URLs and fetch time, reporting cross-source discrepancies without resolving them; it never edits the price sheet. Price rates take optional `effective_from` and `effective_to` dates, and `telemetry stats` flags a sheet reviewed longer ago than `max_review_age_days` (#2241).

## Fixes

### CLI and install

- `provenant config apply` now refuses a patch when any proposed domain value is invalid, instead of publishing the TOML and letting the effective configuration recover it. `config schema` lists the complete typed field set, including owner bounds, enum choices and keyed settings such as quota polling intervals and project GC policy. Configuration history redacts secret-looking values nested inside arrays of objects (#2310).
- `install` and `upgrade` maintain shared instructions and their harness guide, including symlinked directories. They link `~/.agents/AGENTS.md` to the installed instructions; use `install --adopt-existing` or move an existing user file aside, and use `check install` for repair guidance (#2350).
- A `domains` value that is not a table, such as `domains = false`, now refuses to load for the settings that control a boundary, such as `[domains.run]`, instead of silently using their defaults. The error names the config file and the `domains` key (#2350).
- A single `config apply --file` patch can now create a calibration entry, such as `domains.quota.calibration.<account>.five_hour` with its `expires` timestamp. `config schema` lists the calibration fields with their 0 to 100 bounds (#2350).
- Configuration warnings, including invalid model fallbacks, are shown once per file revision and stay silent in Claude pre-tool-use hooks. Retired schedule keys now name their replacements and how to edit the configuration (#2350).
- CLI help now points to advanced options, and JSON help includes descriptions and missing requirements (#2350).
- `--model junior` now says "did you mean --route junior?" instead of only "model must be ADAPTER/ID" (#2350).

### Lanes and settlement

- Lane stdout, stderr and result files now mask known credential shapes before storage. Result digests identify the stored, redacted bytes (#2289).
- `run` with neither `--mode` nor a target (`--worktree`, `--branch` or `--worktree-branch`) is refused from a registered linked worktree, and the refusal names both repairs: `--worktree <path>` for a writer or `--mode read-only` for a reader. An explicit `--mode read-only` dispatches as before (#2300).
- A lane whose final handoff declares `stopped_early` or `blocked` now settles as `review_required` when it would otherwise succeed, so `run --wait` and `lanes` show the unfinished work. Its partial work is still delivered. The graph counts any outcome other than `succeeded` as a failed node, so such a lane fails its graph node (#2300).
- Settlement masks known credential shapes in Codex rollouts and history and Claude project sessions and tool results. Codex SQLite databases, Agy history and Claude state outside `projects/` are not scrubbed; result-only orphan recovery can retain unredacted bytes until evidence is pruned (#2303).
- A redaction failure no longer prevents settlement: a result failure withholds the result, and a session failure retains the filtered result while reporting the failure (#2303).
- `reconcile` now settles an attempt left in settlement after its guardian and provider exit without a durable result or writer lock; it reports `lost` with the reason `no live holder` (#2308).
- `lanes`, status and waits now recover lanes whose guardian stopped, including cancelled lanes that never launched. `lanes --json` reports `overdue` and `stale` for these attempts (#2350).
- Run operations that return `RunError` now report a missing Git executable as "Git executable unavailable" with the `GIT` code. Launch handoff reports the reason as a handoff refusal (#2350).
- Cancelled lanes report their cancellation reason, identity failures include requested and observed models, and failed lanes retain declared-stop signals (#2350).
- Model lanes that finish without a final handoff record `handoff_missing` without changing their outcome; command lanes and failed lanes do not. Contradictions between a done handoff and cancellation or required review are noted (#2350).
- Claude identity is taken from the assistant message matching the final answer, so an earlier helper model does not mask the answering model (#2350).
- OpenCode HTTP 500 responses that explicitly report overload are classified as provider capacity; other 500 errors remain generic failures (#2350).
- A run-store contention refusal tells the caller to retry the same command with `--operation-id`, so a retry cannot admit twice (#2350).

### Git and safety

- Repository path discovery ignores inherited Git directory redirects, including for session handoffs, pull request landing and source inventory (#2271).
- Repository-root protection stays active when a Git marker is malformed (#2271).
- Delivery reads repository metadata from the writer project rather than the writer worktree (#2271).
- Git repository path discovery is bounded to ten seconds, restoring the Git context capture deadline (#2357).

### Accounts, quota and routing

- RFC 3339 configuration instants accept fractional seconds, including nanoseconds; finer precision truncates towards zero to stored microseconds. Policy schedules honour fractional starts and expiry, matching pacing. Settlement retries use the injected clock, and `route pacing` prints every active override (#2271).
- Review shape selection keys on the four risk tiers: routine selects the quick shape, substantial the standard shape, and crucial and terminal the deep shape. Before this, every tier fell back to the standard shape. Terminal-tier work also gets the adversarial lens in `review-council` (#2350).
- The `review.extra_reviewers`, `review.cross_family`, `review.rereview_scope` and `review.polish` knobs are marked not wired; setting them has no effect (#2350).
- A result fallback that the effective routing policy drops is now reported once for the route being launched, and only when it is actually dropped. A rule overlay that makes the fallback valid no longer produces a false "dropped" warning (#2350).
- The `deep` review shape now names lenses that exist (`correctness-spec`, `security-privacy`, `concurrency-data-errors`, `tests`). Before, three of its four lens names matched no lens prompt and silently used the generic lens (#2350).
- Quota summaries no longer flag healthy accounts for refresh, and oversized history reports suggest supported filters and the correct limit (#2350).

### Chair, inbox and console

- A session checkpoint now warns only above 8 KiB, and the warning names the project's `checkpoint_soft_bytes` budget. A project with a raised budget stays quiet until its own budget is exceeded. Before, the setting had no effect and a project budget larger than 8 KiB still warned while claiming the shared 2 KiB default (#2350).
- The session-start and compaction state block omits lane sections that have no lanes, and prints nothing when there is no lane or pull request state to show. Before, it listed `Lanes in flight (0)` even when nothing was in flight (#2350).
- The save command that hooks inject names the checkout the hook ran in with `--project`. A save from a scratch directory outside that checkout now reaches the same project, where it failed before (#2350).
- The menu bar now shows errors and repair guidance when quota or overview reads fail (#2350).

### Fabric and MCP

- `hosts doctor NAME` now uses the configured peer transport, including forced-command keys, and refuses unknown hosts and malformed reports. Configure the same Fabric peer key on both hosts (#2329).
- `fabric_mail` `send` accepts a call without `artefacts`, which now means no artefacts, and `fabric_context` with no `op` runs `inspect`. MCP `invalid_input` errors include a `field` when the rejected field is known, and continuation generation conflicts include `current_generation`. An invalid Fabric input from the `fabric` command now names the flag it rejected, such as `--to` (#2350).

### Telemetry and providers

- Native Claude subagent usage ingest now skips unrelated `.jsonl` filenames instead of aborting the report; a non-regular `agent-*.jsonl` file is still refused (#2284).
- Usage reports now include recent events from rotated logs and count one-hour cache creation in native usage (#2350).
