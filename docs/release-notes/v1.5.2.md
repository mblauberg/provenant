# Provenant v1.5.2

Released 3 November 2026.

This patch release lets lanes bind Unix sockets, stops sibling `git worktree add` runs and processes that exit mid-census from refusing launches and cleanup, makes writer resubmission on an existing branch work, and installs pnpm dependencies for writer lanes before they start. Graph nodes can read their upstream nodes' full results from files, planner fragments fall back cleanly when invalid, and `PROVENANT_DURABILITY=relaxed` speeds up test and throwaway state.

Provenant makes no stability promise; see [stability](../release-notes/README.md#stability).

## Behaviour changes

- Writer lanes in a pnpm project start with dependencies installed. Before the provider starts, Provenant runs `pnpm install --frozen-lockfile` on the host for a writer worktree that has a pnpm lockfile and no completed install. Set `lanes.prepare_deps = false` to skip it (#2657).

## Additions

- `PROVENANT_DURABILITY=relaxed` replaces full-device flushes with ordinary `fsync` for Provenant's own state files. It is meant for tests and throwaway state; the default remains full durability. Each file is also flushed once rather than twice when it is written (#2653).

## Fixes

- Resubmitting a writer on an existing branch reuses the clean worktree of a finished writer lane, keeps the requested base, and explains a `--base` that conflicts with the existing branch instead of refusing with an unactionable error (#2660).
- Lanes can bind Unix domain sockets. Lane `TMPDIR` now points at a short `/private/tmp/pv-<id>` alias of the attempt's temporary directory, which keeps socket paths under the macOS length limit, and writer lanes may bind and connect sockets in their scratch (#2661).
- Concurrent lane scratch setup no longer fails intermittently on macOS when opening a lock file races with its creation (#2671).
- A process that exits while the worker census is inspecting it no longer blocks worktree cleanup or `provenant land` (#2675).
- A running lane no longer loses its repository authority when someone runs `git worktree add -b` beside it. Branch tracking entries that Git appends to the shared config for other branches are accepted, and any other refusal now names the underlying repository error (#2528).
- Review council synthesis accepts findings written as an object keyed by finding ID as well as a list (#2509).
- Planner fragments accept shorthand result inputs and use a configured static fallback when an emitted fragment is invalid. Human status, graph status, resume and output include the relevant bounded reason (#2650).
- A graph node can read the full result of the upstream nodes it selects, not only the bounded prompt excerpt. Each result on this host is written, redacted exactly as `provenant output --full` shows it, to a read-only file in the node's own inputs directory, and the prompt lists the path beside the excerpt. The node is granted read access to that directory alone, up to 2 MiB of results in total; a result cut at the limit ends with a marker and the prompt names it. A result on another host is named unavailable and the node still runs; remote materialisation is tracked in #2665 (#2663).
- The SessionStart save command works when the session's directory is not a Git checkout, and the saved checkpoint is found by the next session start (#2669).
