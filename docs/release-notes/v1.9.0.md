# Provenant v1.9.0

Released 11 November 2026.

This release removes the unattended PR service, the `provenant bench` verb, the `provenant fabric landing` verbs and cloud job tracking, and replaces them with a thin `provenant cloud launch` and `collect`. It also folds the global agent instructions into one file, merges the process skills, and fixes OpenCode 2.x settlement and several launch, retry and telemetry failures; read Breaking changes before upgrading.

## Breaking changes

- **The unattended PR service, `event-intake` and `pr-reconciler` are removed, with the service's settings, its launchd unit and the `PROVENANT_INTAKE_*` variables.** Release archives no longer carry `bin/pr-reconciler`, and `package-release` no longer takes `--pr-worker`. `provenant pr watch`, `pr status` and `provenant land` are unchanged, and old intake or service state directories are ignored. If you loaded the PR service unit, unload it once with `launchctl bootout gui/$(id -u)/<its label>` (labels start `dev.provenant.pr.`), or it keeps relaunching the missing worker (#3224).
- **Cloud jobs are replaced by one thin launch.** Use `provenant cloud launch --file BRIEF` to submit a brief to a Claude or Codex cloud session and print its link, then `provenant cloud collect KEY` to put the pushed branch, or the Codex diff, in a new worktree; setup is in `docs/runbooks/cloud-launch.md`. Provenant no longer tracks, polls or cancels cloud work. Removed: the `attempt.cloud` and `attempt.placement` graph and `--set` fields (now refused with a pointer to the launch command), the `providers.codex.cloud.transport` and `.command` settings, `domains.lanes.cloud_targets.*` and `projects.*.cloud_target`, the `cloud_*` lane states, the `cloud`, `cloud_state` and `cloud_jobs` status fields, and `scripts/cloud-environment` and `scripts/cloud-verify`. Delete any `[providers.codex.cloud]` table from host configuration; it is now ignored with a warning (#3225).
- **The `provenant bench` verb and the `provenant fabric landing` verbs (`push`, `reconcile`, `acquire`, `renew`, `verify`, `release`, `wait`) are removed.** `scripts/bench` remains and is now the entry point for the bench runbook. The `landing_*` operations of the `fabric_lease` MCP tool and the `PROVENANT_LANDING_TOKEN` variable are removed too; the work-claim operations remain (#3226).

## Behaviour changes

- Install now writes one instruction file per harness: the global rules, under 800 words, absorb what still applied from `HARNESS.md`, which is no longer shipped, and an upgrade removes the `HARNESS.md` links an earlier release installed. The rules now say to act on recorded assumptions and ask only at one-way doors, to read a rough request for its intent and root cause, and when to use native sub-agents rather than lanes. (#3210)
- The installer no longer ships the `rust`, `typescript-clean-code`, `vitest`, `zod` and `react-performance` library skills, which restated general knowledge. An upgrade removes their links from each harness's skills directory; `tanstack`, `playwright` and `d2-diagrams` remain (#3211).
- The generated reference under `docs/reference/` is no longer tracked, so a command change no longer needs it regenerated. Read `provenant help --all` and `provenant config schema`, or run `scripts/generate-reference` to render it locally; CI only checks that it generates (`--strict`) and uploads it as an artefact, and `--check` is gone (#3214).
- The `engineering-docs` skill now asks for specs written as invariants pages: each entry states what must hold, with a one-sentence reason, the test that pins it and its owner, kept near 2,000 words a page. It replaces the old 999-line, 100 KiB size limit (#3215).
- The runbooks are cut to the procedures the tool cannot make obvious. `model-routing`, `model-policy` and `presets` merge into `routing-and-templates`, `disk` into `gc`, and `agy-authentication` into `providers`; `docs/runbooks/README.md` indexes the rest. `scripts/check-doc-truth` now fails on a command or flag in a runbook that `provenant help --all --json` does not list (#3216).
- The process skills are merged and given shorter descriptions, taking the `skills/` directory from 20 skills to 15. `implement` and `refactor` fold into `deliver`; `retrospect`, `evaluate` and `skill-craft` into `improve`; `natural-writing` and `engineering-writing` into `writing`. `legal-writing`, `ui-ux-design` and `session` are trimmed, and per-skill trigger fixtures and `scripts/check-skill-negatives` are gone. An upgrade removes the retired skill links from each harness (#3217).

## Fixes

- A misspelt or invalid knob in `config.toml` now warns, naming the file, line and key and suggesting the nearest valid knob, instead of refusing `status`, `config show` and every launch. A knob that grants authority, such as `lanes.publish`, takes its restrictive value on an invalid entry, and a configuration problem is reported as `CONFIG` rather than `IDENTITY`; `config set`, `config apply` and `config unset` validate names before writing (#3206).
- A review result now settles on its one `VERDICT:` line wherever it sits, ignoring fenced blocks and prose, and a rejected verdict names the lines it saw instead of a generic message (#3193).
- A review child launch that names an unknown `tier` is now refused under the default advisory diversity as well as under `strict`, with one usage error that names the tier and lists the valid tiers, instead of a graph compile error (#3149).
- `provenant retry GRAPH --brief TEXT` now replaces the brief of a graph's only node instead of refusing the field; a graph of several nodes asks for `--node`, and a container built from a template with no `brief` parameter names that field and template. A template-derived acceptance check follows the new brief (#3202).
- Several launches submitted at once in one repository no longer fail with `io` ("graph input could not be processed"): preparing project scratch waits up to 30 seconds for the repository exclude lock instead of spending the launch's `--wait`, and a lock that stays held is reported with its cause (#3232).
- OpenCode lanes no longer settle `identity_unobserved` after the model answered. OpenCode 2.x records a session only in `session_v2`, but settlement and resume looked only in the older `session` table; either table now names the session, and the answering provider and model are still read from it, so a Go-model lane must still show the Go provider (#3152).
- Transcript ingest now keeps one segment per day, so `telemetry mileage` and chair and sub-agent spend keep working as history grows instead of failing at a fixed store size; an existing single-file store is split on first use. `telemetry stats --json` returns the summary the human view shows (per-attempt rows need `--detail`) and, when a result is still over 1 MiB, refuses it with `RESULT_TOO_LARGE` without leaving a file in `tmp/results`; a message streamed across UTC midnight is counted once, an old store's over-long lines keep the file as `ingest.jsonl.unmigrated` instead of being dropped, and stale ingest staging files are removed (#3205).
