# Provenant v2.5.2

Released 20 November 2026.


## Behaviour changes

- `config/ports.json` tier commands are now `{stack, cwd, argv}` objects. A binary older than this release reads the new shape as malformed and ignores the whole project port layer (verify, land and admission), warning "malformed port layer ignored", until the host is upgraded. (#3654)
- A writer that declares `status: blocked` can now say what blocked it with the optional handoff field `blocked_on` (`owner_decision`, `capability`, `environment` or `dependency`). The field is additive and never refuses a handoff; an unknown value, or one given with another status, is kept and warned about. Only `owner_decision` and `capability` blocks read as an owner decision or a missing capability. An `environment` block retries once on the same route in a fresh session, then pauses for the chair worded as an environment problem; a `dependency` block pauses as a wait; a blocked handoff with no `blocked_on` reads as plain "blocked" and no longer claims an owner decision is needed. The new `blocked_environment` and `blocked_dependency` stop causes can be set in a node's `on_stop`. The lane preamble and the routing policy's guidance now share one statement of the status rules, which tells writers to retry or work around environment trouble before declaring it. (#3633)
- Redaction now defaults to `off`, keeping model and route metadata visible. Set `redaction` to `secrets` to mask credentials at egress or `full` to also mask local text. `config show` reports the setting and source. (#3688)
- OpenCode lanes now use the host XDG profile and service by default, with an isolated `providers.opencode.profile = "lane"` option. Host mode grants access to the OpenCode credential stores and attached tools run in the host service process. (#3703)

## Additions

- `provenant status --json` attempt rows now include `provenant_version` and `release_source_digest` read from the attempt's stored trace, so an operator can tell which build ran a lane without reading SQLite. Both keys are omitted for older attempts that recorded no such observation. (#3634)
- Each attempt's `launch.json` now carries a `build` object with the launching binary's `version` and `source_digest`. The digest is handed to the guardian by the running binary, so a launch names the build that actually launched it even when an upgrade lands while the attempt is queued. The field is additive: custody recovery still reads launch records written before it existed. (#3634)
- Build commands are configured per repository, with no files in the repository's tree. A host-project config layer declares build ports and test tiers, and pure stack detection fills in sensible defaults, such as a pnpm root with nested Rust. A malformed tier command warns and falls back to the next lower layer, naming where each value came from. (#3654)
- `build.prepare` takes a list of argv arrays and runs from the checkout root before seed builds. Seeds that are failed or stale now warn at lane start and in `provenant worktree doctor`; `build.seed.stale_after` sets the staleness threshold. (#3676)
- Affected selection reads `cargo metadata` JSON and limits test tiers to the changed crates and the crates that depend on them. It falls back to the full suite for broad changes and periodically. (#3668)
- Seed builds hold dependency units only, build check-mode units and the lint target independently, and identify a seed by its effective dependency inputs: the lockfile, the dependency-deciding parts of each manifest, the profile tables, the effective build profile and the toolchain. A seed can be rebuilt more often than strictly needed but is never reused when stale. Refresh requests carry the lane's commit. (#3671, #3672, #3673)

## Fixes

### CLI and install

- `config/harness-knobs.json` now declares every setting published by a domain's field metadata, including all `domains.wait` settings and `domains.fabric.steer.fallback`. A parity test fails and names any domain field the registry lacks, so new settings cannot ship undocumented. (#3509)
- `provenant gc` (preview and apply), `provenant hosts doctor` and `provenant worktree doctor` now name every process still holding a settled lane worktree or attempt directory, with its pid, command and the cwd, executable image or open file that placed it. One time-bounded census per pass supplies the report; the caller's session and verified ancestors are excluded, only terminal, custody-released attempts contribute, and a path observation is never used to signal a process. A cut-short census warns that results may be missing, and locally produced reports cap the row list at 128 with a "more not shown" line. (#3564)
- `upgrade --verify --dry-run` now previews the smoke graph against its scratch repository instead of the home directory, and graph readers default to their selected project. (#3683)
- `config set` warns about unknown configuration keys and preserves them instead of refusing unrelated edits. (#3689)

### Lanes and settlement

- Review verdicts accept common approval and changes-requested wording with a normalisation warning. Review launches warn about conflicting verdict instructions, and results report the reviewed head. (#3536)
- `status` shows admission holders and waiters from every project sharing the host state root, naming each project and lane so a build waiting on another project has an attributed holder. (#3546)
- A writer that stops early (`stopped_early`), loses its lane token or reaches a context handoff on a node with no different route now continues on the same route in a fresh session, on the same branch with its handoff carried over, instead of pausing for the chair. A different route is still preferred when one exists, and a node `on_stop` entry still wins. The fallback is bounded by `limits.continuations` and needs progress between rounds: a round that adds no commit and leaves `remaining[]` unchanged pauses for the chair. Restart and pause reasons name the limit, its value and where it comes from. The lane preamble now says a fresh session continues from the handoff, so commit and push first. `lanes.context_handoff_tokens` text now says providers without per-call context, such as codex, never trigger it. (#3632)
- Seed builds clear inherited compiler-selection environment variables (`RUSTC_WRAPPER`, `RUSTC_WORKSPACE_WRAPPER`, `RUSTUP_*`) instead of refusing to run. (#3678)
- Lane Cargo debuginfo and incremental defaults now come from a single source. (#3669)
- Custody regression checks wait for the guardian census record using its publication cadence and report the last reservation on timeout, reducing timing-related CI failures. (#3686)

### Git and safety

- The macOS release smoke launches a confined read-only lane against retained previous-release custody evidence. (#3682)

### Accounts, quota and routing

- Monthly pacing uses available ledger usage and an inferred cycle when cycle evidence is missing, with a sourced warning instead of holding an account on uncertainty. Refused launches now explain the route and pacing hold. (#3690)

- Account pacing overrides also apply to the final allowance reservation, and `config set` accepts documented typed settings such as the OpenCode Go allowance preference. Unprobed OpenCode accounts remain eligible with a warning. (#3690)
- OpenCode quota refusals honour the provider's retry-after, and the newest refusal for a pool wins. `quota` names where a refusal's expiry came from (provider retry-after or provider reset), using adapter registry data. (#3700)

### Chair, inbox and console

- `provenant status` now counts and lists a lane with a live attempt as running instead of reporting the graph checkpoint's pending status; the compact summary, the listing rows and the `status NAME` detail derive their state from the same node and attempt facts, so a graph waiting for admission still reads as pending. (#3651)

### Telemetry and providers

- `provenant check providers --live` no longer reports `worktree_busy` for one route when several routes are probed together: live probes on the same checkout run one at a time, so each route settles with its own cause rather than a probe refusing its sibling for custody of the shared worktree. (#3715)
