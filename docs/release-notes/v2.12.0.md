# Provenant v2.12.0

Released 28 November 2026.

Provenant 2.12.0 is the first batch of the agent-native epic (#4121). Host reads (`status`, `output`, `result`, `events`, `gc`) accept `--host all` and keep answered hosts when a peer is unreachable; a launch that never reaches its guardian settles as a never-spawned local refusal with its exit kept as evidence, never `LAUNCH_UNKNOWN`; read-only lanes on `--source default_branch` read a private view of the pinned commit; and checkpoint saves check the session template. Live record formats change, so drain live lanes before upgrading each host.

## Behaviour changes

- The global Checks rule now forbids cold builds only in leaf lanes. An integrator working on an integration branch, a large batch or the default branch may build cold when no warm cache exists, instead of waiting on CI. The host's resource limits (cores and free memory) admit the build, not a fixed count. These are defaults that a host or project can replace with its own build, cache and verification policy. (#4141)

## Additions

- `status`, `output`, `result`, `events` and `gc` now accept repeatable `--host` names or `--host all`. Results retain each host's command status and data in one aggregate; human output has a section per host. If one peer cannot be reached, its `Unavailable` status remains the worst outcome, while answered hosts are retained with `partial: true` and a `PEER_UNREACHABLE` warning. (#4121)
- `output --final --to` pages each selected host's sealed result over the peer transport, validates the stable attempt, digest and contiguous offsets, then writes the collected content at the caller's destination. Event consumer cursors advance only after the represented host page is delivered successfully. (#4121)
- `workflow session save` checks the checkpoint against the `session` skill's template and warns, without refusing, on each gap: missing `provenant_standing` frontmatter, a missing `## Intent` section, or a body over the advisory 2 KiB budget (separate from the configured soft budget, floored at 8 KiB). `workflow session save --from-template` scaffolds every template section from the previous revision, overridden per section by `--file` (`-` reads stdin), and carries the typed standing record forward under the checkpoint lock; hooks restore only sourced, unexpired grants from that record. `workflow session show` now prints the whole checkpoint by default; `--json` is unchanged. (#4029)

## Fixes

### CLI and install

- Batched `pr status` readings and their GraphQL fallback exclude declared review gates from CI counts, so a pending review gate does not make passing CI appear pending. (#4042)
- A declared review-gate context no longer keeps `wait`, `pr status` or landing pending when branch policy also requires that context. (#4042)
- Preserve single-host placement for `run smoke` and reject aggregate host targets. (#4121)
- `config explain KEY` reports string-valued settings from `config.toml` and rules from a project's `.provenant/policy.toml` as candidates with their layer and origin. (#4121)
- Reinstalling an unchanged target is reported as a no-op from the current receipt under the install lock, so owned files are not rewritten. (#4121)
- Worktree writer contention keeps the recorded holder in the refusal; other custody refusals keep their typed detail instead of being reported as filesystem failures. (#4121)
- Keep the observed pull request head when it has moved, and show repeated error remedies once. (#4121)
- Host-selected reads retain session-stream rows as a JSON array and use the remaining timeout for local reads. (#4121)
- A host clock failure during a run-store call is reported with the `TIME` code and its leaf cause instead of failing to convert into the run-store error contract. (#4121)
- `upgrade --host` and `upgrade --verify-host` now parse independently, so help and the generated reference can render while upgrade targets and smoke placement remain separately selectable. (#4121)

### Lanes and settlement

- Moved worktrees with stale Git registrations can be repaired when no live lane holds the registration; live custody still protects it. (#4121)
- Oversized quota results now return a warning and a pointer to the complete result. (#4121)
- A lost lane token now retries on the same route and keeps its `lane_token_lost` cause; a pinned read-only reviewer is no longer reported as `auth_required` or `fallback_route_pinned`. The advance code comes from the sealed stop through one table. (architecture review F5, 26 Nov)

### Pipelines and graphs

- A preparation refusal held for the chair keeps its actionable reason while respecting the sealed stop's routing decision. (#4042)
- Pre-launch refusals now respect the sealed stop cause when deciding whether to try another route, including causes that return control to the chair. (#4042)
- Graph waits avoid a stack overflow during advancement. Failed writer bindings and launch warnings retain their correct status and codes. (#4121)
- Oversized results point to the private report named in the warning, and route refusals retain permission diagnostics. (#4121)
- A graph wait reports thread creation failures and a retry step instead of panicking; the work continues. (#4121)
- Review panels preserve an authored success minimum, status reads share their invocation deadline, and quota errors retain their retry time. Shared lanes with an empty write scope commit their work, and policy reports identify the source of dispatch settings. (#4126)
- A launch whose guardian never received the whole launch message, or refused it, settles as never spawned instead of a fenced, unconfirmed handoff. A lane whose deadline is warn-only or unset launches with no enforced wall bound instead of being refused. (#4126)
- A read-only lane launched with `--source default_branch` now reads an attempt-private detached view of the commit its record pins, including under the default `host` access. Previously the recorded pin could name the fetched default while the lane still read the live checkout. The tree a pinned reader gets no longer depends on an access grant flag, and `lanes.read_source` reports a commit for every choice except `live` (#4136).
- A failing node keeps its sealed stop's advance code when an explicit `on_stop` override suppresses a same-route stop, when fallback is denied and when a route is pinned, so a lost lane token is no longer reported as `auth_required`; run receipts and refusal details still show the preparation refusal. (#4139)

### Chair, inbox and console

- Template-backed checkpoint saves retain omitted frontmatter keys from the previous revision while input values override matching keys, preserving structured summaries (#4029).
- `wait --until complete`, `pr status` and landing now share one CI completion definition. A merged or closed pull request settles the wait before a pending check, review-gate contexts declared in the `ci_observation` port are no longer counted as CI, and an open pull request with no observed CI checks does not report a passing `0/0`. (architecture review F4, 26 Nov)

### Fabric

- Host reads and garbage collection preserve their command results in peer responses without colliding with the response type tag. (#4121)
