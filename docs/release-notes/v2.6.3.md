# Provenant v2.6.3

Released 21 November 2026.


## Behaviour changes

- Redaction now has only `off` (the default) and `secrets`: local output, diagnostics and captured command tails stay raw, while `secrets` masks known credential values and token shapes in text published off the host, such as forge bodies and comments. A config value of `full` no longer masks locally or scans assignments; it warns with its config source and is treated as `secrets`, and no command is refused for it. (#3758)

## Additions

- Bundled `agy` catalogue and pool support for the Gemini 4 family (`agy/gemini-4-hydrogen` in `junior`, `agy/gemini-4-neon` in `senior` and `principal`, `agy/gemini-4-argon` in `principal`) and Claude 5.5 (`agy/claude-sonnet-5-5` in `senior`, `writing` and `design`; `agy/claude-opus-5-5` in `principal` and `design`), with lower default pool weights (`weight = 1` on `agy` and `cursor` members against the standard bundled weight `2`) and efforts for usage pacing, family aliases (`agy/hydrogen`, `agy/neon`, `agy/argon`, `agy/flash`, `agy/sonnet`, `agy/opus`), and per-account `superseded_by` filtering so accounts offering Gemini 4 or Claude 5.5 omit `agy/gemini-3.8-flash` and Claude 4.6 from automatic pools while accounts on older model sets retain them. (#3762)
- `agy` cached offered-model probes now invalidate when the account keychain stamp changes, and the `HOME` login falls back to canonical models from `model-discovery/agy.json` when no identity probe record exists yet. Bare `claude-sonnet-5-5` and `claude-opus-5-5` model selectors now require an explicit provider prefix (`claude/...` or `agy/...`) because both providers offer them. (#3762)

## Fixes

- `provenant config check` now warns when a port declaration sits in a file the port reader never reads, naming the file and dotted key: a `build.prepare` table in `.provenant/config.toml`, or a host-project `ports.json` filed under the obsolete 64-digit target-seed key instead of the ProjectId binding directory reported by `config path --project`. `config ports --json` reports the effective `build.prepare` value with its own leaf source, so a misplaced declaration can be diagnosed before a seed build fails with E0583; warnings never refuse a command. (#3729)
- Concurrent `provenant run implement --branch B --base origin/<branch>` launches in one repository now share a per-repository base-fetch lock, so their Git fetches no longer contend on the remote-tracking ref lock. A transient ref-lock collision is retried a bounded number of times and reported as launch contention rather than as an invalid base, so parallel launches resolve the same advertised commit that sequential launches do (#3748)
- A launch that fails while resolving its writer base now settles the graph node as failed in the persisted checkpoint at once. `provenant wait` and `provenant status` report the failure immediately instead of showing the launch as still running until the wait budget expires (#3748)
- Seed-clone `build.prepare` commands now receive `PROVENANT_SEED_ORIGIN`, the absolute path of the origin checkout, as an explicit environment marker; the verify-base Cargo path that sets `CARGO_TARGET_DIR` does not. Consumers can tell a standalone seed clone from an ambient target directory and share tool caches with the origin checkout. (#3753)
