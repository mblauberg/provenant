# Provenant v1.7.1

Released 10 November 2026.

This release trims the agent command line output, adds an opt-in context handoff for long Claude writers, and drops the text handoff reader. A 1.7.1 host cannot exchange handoffs with a peer on an earlier release, so upgrade hosts together (see Breaking changes).

## Breaking changes

- **A graph reads a peer's handoff only from the sealed handoff in the peer's status, not from its answer text.** A peer on an earlier release returns no sealed handoff, so a 1.7.1 host cannot exchange handoffs with it. Upgrade all hosts together. (#3122)

## Behaviour changes

- `provenant run` prints two lines instead of the whole graph document: the graph handle with its state, model and worktree, then `next:` with the command to run. `--json` and `--full` still return the full document. `provenant status --target ID` no longer needs `--wait` and reports each target's current status once. (#3124)
- Lane rows in `status`, `output`, `cancel`, `land` and Fabric results carry one route receipt, `applied_route`; the identical `resolved_route` copy is gone. Scripts that read `resolved_route` should read `applied_route`. (#3124)
- `provenant land` reports a merged pull request as one line and exits 0 even when cleanup is outstanding; the sweep finishes the cleanup. (#3124)
- `provenant check release --base` and `--head` accept any unambiguous revision, such as a tag. (#3124)
- A failed run read names its cause in the error. `telemetry stats` reports an unreadable plan-value or partial-signal source as an `unavailable` field with its cause instead of failing the report. (#3124)
- Lane preambles print limits as plain numbers, and `quota history` returns the newest 50 readings by default. (#3124)
- Skills and runbooks teach `run --branch NAME --base REF` for a single writer and say a ref is enough for a review base. (#3124)
- A writer can hand off before its context grows costly: set `lanes.context_handoff_tokens` (suggested 200000) and the host stops a Claude writer once one call's context reaches it, settling the stop with the writer's latest progress handoff so the graph's restart continues it fresh on the same worktree with commits and edits kept. It is off by default (0) until a trial shows restart does not lower completion; providers that report no per-call context are unaffected. `provenant telemetry stats` now reports spend by context band (`context_bands` in `--json`) so windows before and after can be compared. (#3076)
