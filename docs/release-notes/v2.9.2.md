# Provenant v2.9.2

Released 24 November 2026.

Provenant 2.9.2 lets `reconcile --abandon` settle a lane past unreadable system processes without freeing a worktree a process may still hold. `upgrade --verify` failures are now readable, smoke and verify launches use exact model routes, and an empty or malformed Git remote name can no longer reach Git.

## Fixes

- `provenant upgrade --verify` now names each failing host once in the `UPGRADE_FAILED` message with a bounded, one-line reason, and leads the human view with one `upgraded` / `verified` / `failed - reason` line per host. The verify child is run with `--json`, so a failed host shows its innermost error code and message instead of nested `Command failed` wrappers, and the smoke host prints its graph verdict instead of raw envelopes; repeated capability notices collapse to a count unless `--full` is given. On failure the renderer drops human text, so run `provenant upgrade --verify --json` for the full per-host detail. Running the verification from outside a Git checkout no longer fails the smoke host just because the selected project is not a checkout. (#3877)
- A writer launched from a template (`provenant run implement --branch` or `--base`) no longer takes the read-only default source: a primary checkout behind its upstream neither warns nor pins the launch, and the launch identity comes from the writer's base. (#3870)
- `reconcile --abandon` no longer reports `ABANDON_BLOCKED` for an unreadable host process that the census can prove is not a lane writer. A process whose readable cwd or descriptor lies inside a lane root still blocks, and so does every unreadable process while a root's own identity cannot be read. Otherwise a listed service uid, an owner-run platform daemon under `/usr/libexec`, `/System/Library` or `/usr/sbin` with its cwd outside every root, or a `confinement.census_ignore_unreadable` entry excuses the process with a warning naming its PID and path. Human uids and the owner are never excused through the uid list. (#3891)
- An empty or malformed Git remote name can no longer reach Git. A configured `git.remote` that is not a usable remote name is refused naming the value, `provenant gc` names the repair, and a stopped local-integration lane keeps its stop-publication remote. (#3888)
- `provenant run smoke --route <adapter/model>` and `provenant upgrade --verify --route <adapter/model>` accept a short or full catalogue model id instead of refusing it as an invalid alias, and relay controls no longer rewrite an exact-model route. A graph refused at admission now names the node and the validator's reason in `dispatch_refused`. (#3867)
- `provenant run review --pr N --set review_base=SHA` is accepted: the review keeps its pull-request binding and diffs `review_base...head`, so a repair re-check stays linked to its pull request. (#3878)
- A peer-placed graph node whose project cannot be projected across hosts (for example the `upgrade --verify` smoke fixture in a scratch directory outside the home) no longer fails with an unattributable `confinement_refused`. The refusal now names the confinement rule and the path that could not be projected, in the node result. A peer binding its own read-only source checkout names the rule and path when the checkout cannot be anchored or fingerprinted; a checkout that cannot be resolved keeps its own typed cause. (#3868)
- `scripts/prepare-release` refuses to cut a release whose `_intro.md` repeats the previous release's intro, so a stale summary cannot ship; the intro file stays in place between cuts. (#3879)
