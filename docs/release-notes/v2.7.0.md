# Provenant v2.7.0

Released 22 November 2026.

Provenant 2.7.0 makes refusals actionable, turns more guardrails into warnings and gives quota, readiness and route admission one shared derivation. It drops the 1.x install cleanup and the retired `redaction = "full"` value: set `redaction` to `off` or `secrets`.

## Breaking changes

- Install and doctor no longer remove or report 1.x MCP entries, obsolete LaunchAgent plists or retired agent labels. A fresh default root still receives `config.toml` and `host-id`; configure harnesses through the current managed declarations. #3782
- `redaction = "full"` is no longer accepted. An unrecognised `redaction` value now warns and falls back to the restrictive `secrets`, not the registry default `off`; only an absent setting takes `off`. Use `off` or `secrets`. #3782

## Behaviour changes

- A stored `providers.opencode.profile` and the retired Cargo cache keys now produce the same generic finding as any unknown key or value, naming the path and line instead of a key-specific hint. #3782
- `console sessions` publishes its one-line display text as `summary_line` and the source as `summary_source` on each row; the top-level string `summary` is gone and the structured summary stays at `record.summary`. The sessions data schema version stays 2: this is an additive rename on an evolving envelope (#3785).
- CLI refusals now always carry a concrete next step in `error.repair`: the exact command or flag to run, or the condition to wait for. The renderer no longer substitutes a circular `provenant help <command>` when a repair is absent, and a new `domains.wait.preflight_busy_timeout_ms` (default 2000) lets a wait tolerate a momentarily busy store during preflight while the final snapshot stays nonblocking.
- `provenant gc` no longer runs the one-time retirement pass for old shared Cargo targets; shared targets are collected under the ordinary cache budget. #3782
- A nested lane deeper than `domains.run.max_lane_depth` now warns and proceeds, naming the setting; `policy.LANE_DEPTH=refuse` restores the stop (#3551)
- Requesting hooks when no selected harness supports them now warns and skips hooks instead of failing the install; `policy.INSTALL_HOOKS_UNAVAILABLE=refuse` restores the stop (#3551)
- A PR opened over an attempt in an unexpected state now warns, naming the attempt and its state, and proceeds from the recorded branch and head (#3551)
- A hook worktree branch name that is not a valid ref is sanitised with a warning instead of refused (#3551)
- Policy rules now name their class precisely: immutable typed operation errors (identity, consistency, malformed input) are `operation_error`, no longer labelled as boundaries, and git-isolation rules are `other_work`; only credentials, other work and authority remain boundaries (#3551)
- Refusal messages for PR landing, publish and worktree removal now say what to do next (#3551)
- Lanes can now read account and routing state with `quota show`, `quota history` and `route resolve`. Mutating quota commands (`quota tick`, `quota clear`, `quota display`) stay refused inside a lane because they run provider probes with the chair's credentials and write the chair's quota record; each refusal names the command to run from the chair's session.

## Additions

- `PROVENANT_APPS_DIR` sets the directory for the bundled macOS app; it defaults to `~/Applications` (#3773).
- Extend the model catalogue from host and project config: new models, pool membership, capability weights and removals, with each fact's layer shown in `route list` and `route resolve`; invalid entries are skipped with a warning. See routing and templates (`docs/runbooks/routing-and-templates.md`, "Catalogue and price overlays").
- Overlay telemetry prices from host and project config, replacing or removing entries by provider and model, with the source of each overlaid price shown in `telemetry stats`; invalid entries are skipped with a warning. See routing and templates (`docs/runbooks/routing-and-templates.md`, "Catalogue and price overlays").

## Fixes

- Upgrade and install now report the installed Provenant Console app version, and upgrade, install and `hosts doctor` warn when a read version trails the CLI. A bundle that is not installed is reported as missing, without a version comparison; a missing or damaged app asset is a warning rather than a failed CLI upgrade (#3773, #3785).
- `pr open` no longer asks to approve the merge in every pull request body: a `Decision requested` section appears only when the caller passes an outstanding decision, and the findings row is now `Unresolved blocking findings`. `provenant gc --help` states the real `gc.free_floor` default of 1% of the state volume, capped at 5 GiB (#3783)
- A prepared Git reference transaction now names one abort cause. A requested commit the deadline alone suppressed sets `timed_out`; one cancellation suppressed sets `cancelled`, so `validate_outcome` reports cancellation and callers keep the retirement pending; a callback refusal sets neither, leaving the prepared check to decide between a checked-out reference and its real error. Previously Git could write `abort: ok` and exit before the stop-signal path ran, leaving the outcome to report neither expiry nor cancellation and making a deadline indistinguishable from a refusal; the reference was still kept. (#3646)
- Writer delivery failures now carry a typed cause beside their stage: a failing `git` or `gh` step reports its exit status and a bounded tail of its standard error (the tail, because a command's fatal line is last), while I/O and parse failures carry their own detail. The cause is rendered in the error, the failed delivery receipt and the JSON error envelope, so agents can tell a 422, an authentication refusal, a network failure or a rate limit apart without inspecting the host. Redaction remains off by default by owner decision, so the stderr tail is passed through unchanged
- Quota status, readiness and route admission now use one effective-status derivation, one configured freshness policy and typed readiness scopes; `quota --json` reports each account's servable models and the reason for every exclusion.
- State writers with only the state directory (provider settlement, launch reservation) read `domains.quota.freshness` through the state-keyed reader, so a `config.toml` that sets just the freshness keys expires the readiness they publish under those keys instead of the compiled defaults.
- A confirmed, worth-fixing `should-fix` on a default path now starts a repair writer instead of being neither repaired nor blocking. Only `blocking` severity or a blocking class (`acceptance` or `default_path_defect`) contradicts PASS; notes are reported, never repaired. One vocabulary map translates the severity words external reviewers use, and an unrecognised word is warned and kept as a repairable `should-fix` rather than invalidating the review (#3783)
