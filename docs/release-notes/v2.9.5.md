# Provenant v2.9.5

Released 25 November 2026.

Provenant 2.9.5 is a reliability release. Lanes no longer get stuck in settlement when a provider writes its own `handoff.json`, and review lanes no longer check out the PR head in the project's primary checkout. A setuid `/usr/bin/login` with an unreadable working directory no longer blocks writer removal. Settlement also tolerates prose after a closed handoff, and concurrent launches wait out writer-lock contention.

## Fixes

### CLI and install

- `provenant output --full GRAPH/NODE#N --host` now prints the peer's real committed head and publication from its lane projection instead of omitting them; read-only and unpublished lanes still omit non-applicable headers. (#3807)

### Lanes and settlement

- Settlement owns the attempt's handoff snapshot. A provider-written `handoff.json` is kept as `handoff.provider-written.json` (or `.unsafe` for a non-regular entry), and the lane settles from its captured answer instead of retrying forever. A slot read error no longer hides `result.md`. (#3942, #3844)
- A single closed handoff followed by ordinary prose settles, including a prose line over 12 KiB and prose after a handoff-shaped `json` fence. Repeated blocks and verdicts after prose stay strict. (#3916, #3932, #3946)
- Git setup refusals have their own typed cause. Writer IO failures carry their operation and path into node diagnostics. (#3937, #3940)

### Writers and worktrees

- `--pr` and `--branch` reuse the branch's free linked worktree instead of refusing. A held writer names the attempt to reconcile, with a command the CLI accepts. (#3934)
- Writer dirtiness is observed fresh at launch, and a launch retries instead of refusing on a stale clean or dirty reading. (#3939)
- Concurrent launches wait out writer-lock contention instead of failing. (#3925)
- The process census excuses a setuid `/usr/bin/login` only when it started before the removed root was created, so it no longer blocks removing a writer checkout. (#3924)
- Unmatched remote refs are compared as they are. (#3915)

### CLI and output

- `status --full` keeps graph rows whole; only compact output is bounded. (#3920)
- Human `result --full` renders finding details. (#3919)
- Writer headers print even when the base is unobserved. (#3918)
- Peer release downloads resume and retry during `upgrade`. (#3917)
- `wait --pr` waits for required checks. A route refusal names its reason. (#3927, #3921)

### Pipelines and graphs

- `provenant run review --pr N --head SHA` now launches in an attempt-private, read-only detached view of that head and its prompt says the subject is already checked out there, so a review lane no longer checks the PR head out in the project's primary checkout and displaces concurrent writers. (#3943)
