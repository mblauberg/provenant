# Provenant v2.8.3

Released 23 November 2026.

Provenant 2.8.3 makes the batch template usable again: a slice whose `integrate:<branch>` delivery completed now settles as succeeded and starts the slices that wait on it. It also makes a resumed settlement converge on the merge its own publication made.

## Fixes

- Resuming settlement after a publication that merged a diverged host branch now
  converges the lane worktree on that merge and clears its import pins. Before
  the branch ref moves, publication durably records the OID it plans in the
  attempt's settlement progress; on resume the worktree advances only when the
  branch tip is that recorded OID (or the verified head), so a foreign two-parent
  merge of the head in either parent order is left alone with its pins intact.
  (#3831)
- The branch-rewound publication refusal no longer claims the lane tip descends
  from its launch base: that path checks only the host branch's position and
  never inspects the head's ancestry, so the message now states only what was
  checked. (#3831)
- A merged publication records the ancestor it established on the judged lane
  head, not one inferred from the merge's host parent. A cleanly merged unrooted
  head is recorded as unrooted in `publication-ancestor.json`, agreeing with the
  warning already written about it, instead of being mislabelled as descending
  from the lane branch. (#3831)
- A batch slice whose `integrate:<branch>` delivery completed now settles as
  succeeded and starts the slices that wait on it with `after`. The run status
  view re-derives the delivery receipt from `delivery.json` even when its head
  differs from the sealed writer head, and the delivery settlement effect is
  marked done from that same receipt. Previously the pre-integration
  `not_attempted` snapshot was kept, the slice settled `other_failure`, and the
  terminal-effects delivery stayed pending with its worktree retained. The
  head-mismatch allowance is scoped to integrate deliveries: a `push` or `pr`
  receipt must still name the sealed head, a receipt for another branch or
  remote is ignored, and a failed receipt stays failed. A conflicted
  integration still reports blocked with the conflicting files. Runs already
  stuck in this state under v2.8.2 still need `provenant retry`; this change
  does not re-derive already-settled failed nodes on reconcile. (#3846)
