# Provenant v1.6.16

Released 8 November 2026.

Lanes now run with ordinary host access by default on macOS, with credentials, Provenant state, shared Git metadata and other worktrees still denied. Read [Breaking changes](#breaking-changes) first: run schema 10 locks out older binaries, so upgrade all hosts together.

## Breaking changes

- **Run schema 10 removes the attempt record length limit.** Once a release from this version on opens a host's run database, older binaries cannot open it. Install on every host and restart its sessions together.
- **Attempts from before this release using Cursor, OpenCode or read-only Claude cannot resume.** These adapters now require attempt-private session state. Start a new lane.

## Behaviour changes

- Default CLI help and the CLI reference now focus on the ten core verbs and everyday options. Use `provenant help COMMAND --all` or the complete CLI reference for specialist options; all flags remain accepted.
- Read-only lanes can fetch Git updates into private metadata while the host checkout remains unchanged.
- Lanes with large grant counts, sandbox profiles or write-grant ledgers now warn at the configured thresholds and retain their full diagnostics. Backend and enforcement failures still refuse launch.
- Lanes do not read login shell startup files, such as `~/.zshenv` and `/etc/zprofile`. They keep the `PATH` of the environment that launched them, so their Git wrapper stays first.
- Lanes now have ambient access to ordinary files, tools, caches, terminals,
  sockets, databases and open networks on macOS. Credentials and preservation
  archives, Provenant host state, shared Git metadata, read-only sources and
  other owned worktrees stay denied, apart from selected authentication,
  the GitHub CLI on open networks (its token can write to GitHub, so a read-only lane is read-only only on this machine) and narrowly scoped attempt inputs and private
  state. The host can further restrict reads, writes and network through
  `[domains.run.host_policy]`; Linux refuses launch because it has no enforcing
  backend. Cursor, OpenCode and read-only Claude attempts created under the old
  layout cannot resume, and no compatibility shim is provided.
- Review verification and synthesis now get their output protocol from the review template, leaving the role prompts focused on evidence and judgement.
- A lane's commands can read Provenant's `config.toml`, `host-id`, project indexes and Fabric database, because its Fabric server reads them directly. These stay immutable to the lane, and ADR 0040 records this limit.

## Fixes

### CLI and install

- `gc` now reclaims attempt temporary directories with unreadable owner permissions while leaving symlink targets untouched.

### Lanes and settlement

- Lane launches no longer warn about the credential inventory limit because of large session stores in OpenCode's default data directory. Credential links in other stores remain protected.
- Repeated read-only command and model-provider preparation uses fresh private Git scratch space, avoiding a file-exists refusal and keeping snapshots from different checkouts separate.
- Lanes are told to update their progress handoff by renaming a temporary file, because hard links are denied, and that a failed update never blocks the work.
- macOS lane launches apply the complete sandbox profile, including large profiles. Profile transport failures refuse launch.
- Lanes can launch when a Cargo credential path has a non-directory ancestor,
  and an unusable optional host restriction no longer discards valid siblings.
- Retained OpenCode sessions can resume when their model telemetry is absent or
  contains multiple models.

### Git and safety

- Concurrent writer launches coordinate all preparation config snapshots, including the initial repository open, with sibling updates, avoiding transient metadata refusals on Linux while keeping origin fetches concurrent.

- Git config normalisation reports execution, timeout and output failures separately from unsafe-directory metadata.

- Repeated verification of an unchanged config snapshot reuses its successful canonical parse, reducing competing Git subprocess launches. Cache misses parse outside the shared mutex so a slow parser does not queue other readers.
- Lane Git commands select other repositories and scratch clones normally. `PROVENANT_GIT` uses the lane wrapper, keeping fetches on the lane repository in private Git state.
- Lanes retain process custody and protect credential symlink targets and other projects' later worktrees while keeping ambient access.

### Pipelines and graphs

- `status` now explains how to retire an unreadable graph record while other graphs remain available.

### Telemetry and providers

- The steward paces its issue searches, so a tracker sweep no longer stops at GitHub's search rate limit.
