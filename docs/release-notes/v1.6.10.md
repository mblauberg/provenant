# Provenant v1.6.10

Released 7 November 2026.

This release improves lane settlement and refusal reporting, strengthens Git safety, and adds worktree diagnostics.

## Additions

- `worktree doctor PATH` explains a checkout's state and suggests a command to resolve a refusal. Unknown occupancy includes its scope and evidence (#2355).

## Fixes

### Lanes and settlement

- Peer invalid-input refusals disclose details only when accompanied by a validated typed cause.
- Launch preparation and handoff refusals retain their typed security boundary when available.
- Resource refusals retain their typed limiting setting and source in retained lane status after preparation, handoff or guardian admission, including argv prompt limits.
- Continuation copy limits are configurable under `[domains.run]`; refusals name the limiting setting, its source and a corrective action (#2820).
- Host-added prompt preambles above 1 MiB warn and continue; raw prompt admission and nested argv confinement retain their bounds.
- Cancelling a lane that has not launched now settles it as cancelled and frees its queue place and writer before `cancel` returns, a launcher waiting on setup stops at once, and a `starting` attempt whose launcher died settles by itself.
- Read-only lanes accept `--base` as the diff base when `--head` pins the commit. A read-only lane warns when the checkout it reads (the `--worktree` named, or the caller's checkout) is behind the default branch of `origin`, from the last fetched refs or the remote's advertised HEAD (#3002).
- The writer token budget does not stop Codex writers: `codex exec` reports usage only when its one turn has finished. A budget stop leaves a cherry-pick, revert or rebase in progress uncommitted, with a settlement note, as it already did for a merge. Skipped and failed commits remain reported alongside the budget outcome (#2992).
- Report all-refused lane batches as failures and reconcile an already-published delivery before retrying the push.
- Preserve unsupported adapter capability refusals made by the run service so they can be inspected in status and lanes.
- Notify the bound chair of a recorded refusal, recover pending notices with reconcile, and allow notices to be turned off.

### Git and safety

- Host delivery now applies the command's repository-fact limits consistently and reports when a fact exceeds its limit (#2877).
- Lanes can reach and push to the remote on a host using Apple's `git`, using the lane's own GitHub token. A disk refusal no longer claims uncommitted edits, and one sample of uninterruptible sleep no longer marks a lane stalled.
- Adding lane GitHub credentials preserves inherited Git configuration, including author identity, signing and hooks.
- Lane status pages sample host process capacity once per view instead of once per lane.
- New writer branches start from the fetched remote default branch, with a warning and local fallback when it is unavailable (#2998).
- Lane commits use the host's configured Git identity when the repository has no local identity, including when Git is invoked directly. A commit is refused if neither identity is configured. Writer lanes inherit host Git configuration; the lane GitHub token takes precedence over inherited credential helpers (#3001).
- Integration refuses a destination checked out in another worktree after lane preparation.
