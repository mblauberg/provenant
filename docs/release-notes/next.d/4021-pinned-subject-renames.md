## Behaviour changes

### Pipelines and graphs

- The pinned-subject, read-source and smoke work uses one vocabulary at every layer. Renamed spellings: `SubjectOrigin::Commit` is `SubjectOrigin::Explicit` (kind `explicit`); `PinnedSubject.observed_at` is `pinned_at`; `GraphSubject` and `resolve_graph_subject` are `SubjectAdmission` and `admit_subject`; `ReadOnlySourceRef` is `ReadSourcePin` (field `head` is `checkout_head`) and `read_only_source_ref` is `resolve_read_source`; `ReadSourceChoice.value` is `source`, a typed `ReadSource`; `run --source local|upstream` takes any `lanes.read_source` value (`auto`, `live`, `default_branch` or a Git ref); the `lanes.read_source` value `checkout` is `live`; `domains.wait.pr_head` is `domains.wait.pr_head_policy` (with `wait --pr-head-policy`); `Source::Pr.seen` and `watched_head` are `pinned_head_seen` and `pinned_head`; `UpgradeRunner` is `ChildRunner`; `verify_graph_name` and the `smoke-verify-` graph prefix are `smoke_graph_name` and `smoke-`; `PullSubject` is `PullSnapshot` and `ReviewSubject` is removed; `SMOKE_FIXTURE_UNVERIFIED` is `SMOKE_PEER_FIXTURE_UNSUPPORTED`; smoke parameters `smoke-write`, `smoke-retry` and `smoke-steer` are `write`, `retry_probe` and `steer_probe`; smoke nodes `retry-route`, `steer-route` and `review` are `retry-probe`, `steer-probe` and `review-write`; the wait cause literal `head_moved` is the declared constant `HEAD_MOVED`.
- One install migration, `read-source-live`, rewrites `lanes.read_source = "checkout"` to `live` in the host config and in each host-project config. A repository's own `.provenant/config.toml` is never rewritten: the resolver and `provenant config check` warn `READ_SOURCE_VALUE_RENAMED` and use `auto`. Every other rename touches only names that never shipped, so no other migration exists and the old spellings are not read, aliased or accepted; a script, config file or `--set` using one is refused as an unknown name.
- A `--branch` writer with no `--base` is created from the admitted `writer_base` commit, not from a ref re-read when the worktree is made; `lanes.writer_base = "checkout"` now pins the caller HEAD at admission. A peer reader reads the initiator's pinned head rather than its own checkout HEAD. A smoke graph's subject records its fixture origin with the fixture nonce. A PR wait honours `domains.wait.pr_head_policy` instead of always pinning.
