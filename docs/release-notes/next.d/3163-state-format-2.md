## Breaking changes
### CLI and install

- **Installing 2.0.0 resets format-1 state and needs your acknowledgement.** The install is blocked with `STATE_FORMAT_BREAK` until you pass `--reset-state` (`--yes` does not count), and while a lane process is live. It deletes the run store and run files, attempt tmp, graph journals, mail, claims, the host Fabric index with its chair bindings, the work index and PR contributions. With receipt none or 1 and positively identified old state, the old usage ledger is archived to `usage-history/format-1/`, schema-1 `ingest/` to `usage-history/format-1-ingest/`, and `ingest-cursors.json` to `usage-history/format-1-ingest-cursors.json`. Format 2 has no reader for those records. Receipt 2 leaves telemetry untouched. Provider history is relocated to `provider-history/format-1/`. Existing archive destinations refuse during preflight. Quota history, session checkpoints, chair log, worktrees and branches are untouched. Copy the state directory first if you want an archive. (#3163)

- Reset classifies each store separately from its receipt and header, preserving healthy format-2 stores. A format-1 receipt accepts interrupted 1.x migration versions below each store's current schema, but refuses current/newer stores or garbage. Failed installs list stopped agents and failed shutdowns as "may still be running", print the quoted state directory and ask you to rerun your original install command with its original options; only a reset plan adds `--reset-state`. Empty stores and complete version-zero headers with at most one page supply no format evidence. (#3078)
