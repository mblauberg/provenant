## Fixes

- `reconcile --abandon` no longer reports `ABANDON_BLOCKED` for an unreadable host process the census can prove cannot be a lane writer. Before excusing anything, the census places each process's readable cwd and descriptor paths against every root by directory identity: a cwd equal to or beneath a root is inside it and a cwd of `/` is outside. Two causes stay distinct: a process whose own occupancy path cannot be placed (for example a descriptor beneath a non-directory, such as launchd's) is one excusable failure, while a root whose own identity or metadata cannot be read makes placement undecidable for that root — it fails closed for every arm, configured included, blocks every excusal, and keeps that root Unknown. Three typed policies may then excuse: a listed service uid (all three credentials system uids foreign to every readable root owner), now consulted for every unreadable failure class but still never for a human uid or the owner; an owner-uid process with EPERM-unreadable descriptors when platform-signed (`team_id=platform`), running from `/usr/libexec/`, `/System/Library/` or `/usr/sbin/`, with a readable cwd outside every root — all three credentials must be owner uids, so a setuid-root binary launched by the owner is not excused, and `/bin` and `/usr/bin` shells are not excused by this default; and a configured `confinement.census_ignore_unreadable` entry (canonical path plus team id) extending both to every unreadable failure class. Each excusal warns with the PID and path. Unreadable root identity fails closed and keeps the root Unknown; a listed uid the kernel will not reveal, such as `launchd` (pid 1), cannot be evaluated and is excused only by a configured entry or a listed uid whose credentials the code can actually read. Every other unreadable process, including human uids and the owner through the uid listing, still blocks with its PID named. The production configured matcher reads live macOS signing state; a unit test instead pins that the policy observer forwards its non-empty configured entries to the matcher it calls. (#3891)
