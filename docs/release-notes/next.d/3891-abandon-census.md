## Fixes

- `reconcile --abandon` no longer reports `ABANDON_BLOCKED` for an unreadable host process that the census can prove cannot be a lane writer: the listed-uid policy now also excuses an unreadable occupancy path or root identity (e.g. `launchd`, uid 0), and an owner-uid process with EPERM-unreadable descriptors is excused only when it is platform-signed (`team_id=platform`), runs from `/usr/libexec/`, `/System/Library/` or `/usr/sbin/`, and has a readable cwd outside every scoped root. `/bin` and `/usr/bin` executables and unreadable-cwd processes still block. A configured `confinement.census_ignore_unreadable` entry (canonical path plus team id) extends these defaults to every unreadable failure class. Each excusal warns with the PID and path; every other unreadable process, including human uids and the owner through the uid listing, still blocks with its PID named. (#3891)
