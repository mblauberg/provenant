## Fixes

- `reconcile --abandon` no longer reports `ABANDON_BLOCKED` for an unreadable host process the census can prove cannot be a lane writer. Before excusing anything, the census places each process's readable cwd and descriptor paths against every root by directory identity: a cwd equal to or beneath a root is inside it and a cwd of `/` is outside, and any positive placement — or an undecidable root — wins for every policy arm, including a configured entry. Three typed policies may then excuse: a listed service uid (all three credentials system uids foreign to every readable root owner) for an unplaceable path; an owner-uid process with EPERM-unreadable descriptors when platform-signed (`team_id=platform`), running from `/usr/libexec/`, `/System/Library/` or `/usr/sbin/`, with a readable cwd outside every root — all three credentials must be owner uids, so a setuid-root binary launched by the owner is not excused, and `/bin` and `/usr/bin` shells are not excused by this default; and a configured `confinement.census_ignore_unreadable` entry (canonical path plus team id) extending both to every unreadable failure class. Each excusal warns with the PID and path. Unreadable root identity fails closed and keeps the root Unknown; a listed uid the kernel will not reveal, such as `launchd` (pid 1), cannot be evaluated and is excused only by a configured entry or a listed uid whose credentials the code can actually read. Every other unreadable process, including human uids and the owner through the uid listing, still blocks with its PID named. (#3891)
