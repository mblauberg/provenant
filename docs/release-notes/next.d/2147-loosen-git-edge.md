## Behaviour changes

- Repositories with `filter.*` (such as Git LFS), `include.*`, `includeIf.*` or `info/attributes` are no longer refused. Host-side Git reads disable every configured filter driver. An include whose target is in a lane-writable location (a worktree or lane scratch), including an `onbranch:` condition evaluated against the lane branch, is checked per worktree. Its settings are pinned or neutralised, and a setting that cannot be neutralised fails the operation for that worktree with an error. Editing an included file makes the configuration handle stale (#2147).
- Host-side advertisement and fetch (pre-push, git context, worktree base pinning and delivery) refuse a `core.sshCommand`, `credential.helper` or `remote.*.uploadpack`/`receivepack` that runs a program in a lane-writable location. They also refuse configuration read from a file there, or an `include`/`includeIf` that names such a location even before the file exists. Helpers kept elsewhere still work (#2147).
- The pinned Git executable keeps its stable path, such as `/opt/homebrew/bin/git`, so `brew upgrade git` no longer breaks long-lived processes. Its target must be owned by you or root and not group- or world-writable, and no ancestor directory may be world-writable without the sticky bit. Group-writable directories owned by root or you, such as `/usr/local/bin` on Intel Homebrew, are accepted (#2147).
