## Behaviour changes

- Repositories with `filter.*` (such as Git LFS), `include.*`, `includeIf.*` or `info/attributes` are no longer refused. Host-side Git reads disable every configured filter driver. An include whose target lies where lanes can write (a worktree or lane scratch), including an `onbranch:` condition evaluated against the lane branch, is checked for each worktree: its settings are pinned or neutralised, and a setting that cannot be neutralised fails the operation for that worktree with a clear error. The configuration digest covers included files, so editing one makes the handle stale.
- Host advertisement and fetch (pre-push, git context, worktree base pinning and delivery) share one hardened transport, with no hooks or fsmonitor and only the usual protocols. They refuse a `core.sshCommand`, `credential.helper` or `remote.*.uploadpack`/`receivepack` that runs a program inside a lane-writable location, and configuration read from a file there, or an `include`/`includeIf` directive that names a lane-writable location even before that file exists. Helpers you keep elsewhere still work.
- The pinned Git executable keeps its stable path (such as `/opt/homebrew/bin/git`), so a later `brew upgrade git` no longer breaks long-lived processes. Its target must be owned by the current user or root and must not be group- or world-writable, and no ancestor directory may be world-writable without the sticky bit. Group-writable directories owned by root or you, such as Intel Homebrew's `/usr/local/bin`, are accepted.
