## Behaviour changes
### Accounts, quota and routing

- A launch now checks every requested field against the adapter's declared capabilities before it starts. A missing model, effort or image-input capability degrades with a warning that names the declaration: routing prefers a fallback, an exact pin drops the effort control, and image attachments stay readable paths. `policy.LAUNCH_MODEL_UNSUPPORTED`, `policy.LAUNCH_EFFORT_UNSUPPORTED` and `policy.LAUNCH_IMAGE_INPUT_UNSUPPORTED` (warn by default), or an adapter's `on_gap` entry, set that to `off` or `refuse`; the adapter entry wins for that adapter, and each gap names the setting that chose its action, or both settings when it is the default. `run --explain` lists each node's capability gaps on its pinned adapter with those sources, and `[[adapter_capabilities]]` keys appear in the configuration reference. Write, network, resume and skill-location gaps always refuse, naming the adapter, field, reason and source. `policy.LAUNCH_FIELD_UNSUPPORTED`, which no launch read, is removed. (#4035, #4034)
