## Behaviour changes

- `domains.fabric.lanes.max_concurrent_builds` is now a build throttle, not a cap on live writer lanes. Writers are admitted on the new writer caps and the memory and disk floors, so idle writers no longer block each other or other projects, and the `writer build slots full` refusal is gone (#2197).
- A writer lane with `CARGO_TARGET_DIR` set and `~/.cargo/bin/cargo` present gets a `cargo` shim that takes a host-wide build slot around `build`, `check`, `clippy`, `test`, `run`, `bench`, `doc`, `nextest` and the other compiling commands. It is cooperative fair sharing of CPU and memory among lanes, not a hard cap and not a security boundary: direct `~/.cargo/bin/cargo`, rustc and non-cargo builds are not gated. The shim holds the slot for the whole `cargo` command (so `cargo run` and `cargo test` hold it while the program runs), forwards SIGTERM, SIGINT and SIGHUP to cargo, and releases the slot when cargo exits, so a daemon or backgrounded process never keeps one, and the kernel releases it after a crash. Slot files are created by Provenant and lanes can only read and lock them. A build waits with a progress message about every 60 seconds and gives up with an error after `build_wait_minutes`; the same bound applies to waiting for another build's Cargo lock.
- The automatic default for `max_concurrent_builds` is `max(1, min(cores / cargo_build_jobs, GiB of RAM / 6))`, replacing 1 at 16 GiB or less and 2 above. A 10-core 16 GiB host gets 2.
- New keys in `[domains.fabric.lanes]`: `build_wait_minutes` (default 30), `max_writer_lanes` (default 40) and `max_project_writer_lanes` (default 30) replace the fixed host and project lane limits of 64 and 32 for writers. Out-of-range values are rejected when configuration loads, not at lane admission.
