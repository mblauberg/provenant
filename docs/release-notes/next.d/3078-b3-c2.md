## Breaking changes
### Pipelines and graphs

- **`run` takes the template first, and a graph's name is its id.** Write `provenant run TEMPLATE "brief" [--name NAME] [--brief-file PATH]`; `--file` takes a graph document only, `--use`, `--tier`, `--wait` and `--operation-id` are gone from `run`, and `run "brief"` becomes `run task "brief"`. Use `--route` for tiers or a role map, and `provenant wait NAME` to wait. (#3178, #3179, #3180)
- **The same launch twice gives one graph, and a changed launch takes the next name.** Repeating a named run with the same template, brief, `--set` values, route and source commit returns that graph and launches nothing; changed input starts `NAME-2`, and an unnamed run gets `TEMPLATE-K`. (#3178)
- **`--set` is typed by the template's declaration.** A value of the wrong type or an undeclared key is refused with the declaration quoted. (#3178)
- **`implement` runs as junior only for a bounded brief.** A plan-node output or a `batch` slice defaults to junior; other briefs keep the template tier. (#3180)
