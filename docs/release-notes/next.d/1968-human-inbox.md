## Additions

- `ask`, `inbox` and `answer` add human decisions, assumptions and questions that do not depend on the menu bar app. The `fabric_inbox` MCP operations expose the same inbox, and MCP console and chair tools are discoverable. An answer is checked against the revision the human viewed, keeps an immutable history and queues correlated local Fabric mail in one step. Acknowledging an answer requires the originating host, project, session and actor (#1968).
- Inbox reads and answers route to the configured owner host. `inbox` lists, inspects and answers requests on peer hosts, with the answer's origin recorded and replays refused. Closing and acknowledging stay on the owning host (#1968).
- Queued human answers are offered once to the exact Claude session that asked, at Bash tool calls, and again until the session acknowledges them. Answers are delivered in bounded batches, and an answer over the delivery size limit is refused. Fabric mail fallback is published for all five providers; live injection is not available (#1968).
- Inbox requests can link to a run, task, attempt, repository and launch head. Only verified links allow navigation to the work, and a request whose links contradict each other is refused. Requests without links keep their existing format (#1968).
- A request can be replaced after it has been viewed, keeping its saved answers and delivery. A request with a future UTC deadline reads as expired once the deadline passes, with a reason, and rejects late answers. Nothing is approved on a deadline's behalf (#1968).
