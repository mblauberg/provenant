# v1.2.1

This patch release fixes problems found while upgrading hosts to 1.2.0:
- The peer LaunchAgent restarts on the new binary after an upgrade.
- Writer attempts orphaned before a reboot can be settled instead of staying `running`.
- `lanes` shows when the disk guard has paused builds.

## Stability

There is no stability promise. Commands, flags, `--json` output, `config.toml`
keys, the state layout and Fabric MCP tool names and schemas can change in any
release, with no deprecation period or compatibility shims. Each release's notes
list its breaking changes. Upgrade every host together, since peers on different
versions are not supported.

## Fixes

- `cancel` and `reconcile` now settle a writer attempt whose `reservation.json` has gone, provided its custody checkpoint records both guardian and provider identities from an earlier boot, so that a reboot proves the whole process tree ended. The attempt then ends as lost with the cause, instead of staying `running`. An attempt on the current boot, or one without those identities, stays uncertain (#1928).
- `lanes` shows `disk guard paused builds (free X GiB, resumes at Y GiB)` for running lanes while the disk guard holds builds stopped (#1930).
- `provenant install` now restarts the peer LaunchAgent after an upgrade. launchd keeps the code requirement of the binary it first loaded, so after the release binary changed, `kickstart` left the agent unable to spawn (exit 78). When kickstart does not produce a new running process, install now boots the agent out and bootstraps it again (#1926).
