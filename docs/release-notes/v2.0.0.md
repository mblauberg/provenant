# Provenant v2.0.0

Released 15 November 2026.

Provenant 2.0 moves execution to graphs and introduces a new state root. Before upgrading, drain 1.x work and update integrations for the changed command surface.

## Breaking changes

### CLI and install

- **Drain lanes and land or park 1.x work before installing 2.0.** The first default install creates a fresh v2 state root and copies only `config.toml` and `host-id`; 1.x run state and the old install receipt are not migrated. Review the retained v1 root and old client configuration, and remove anything left over when no longer needed. An identified custom 1.x root is refused, including with `--yes`: use the default v2 root or a fresh custom root and configure it manually. Install 2.0 with the bootstrap `./install.sh`. Select your harness again with `--harness` if autodetection is unsuitable. See the [install runbook](../runbooks/install.md#first-20-install-after-1x). (#3078)
- **Update work targets to the graph, node or attempt syntax** `NAME[/NODE[#N]]`; older identifiers and prefixed targets are removed. Use `provenant wait` to wait for work and `retry` to start a fresh attempt, supplying a new brief or extension when needed. (#3078, #3175, #3177, #3179)
- **Update integrations that read internal run files.** Use `provenant status --json`, `provenant output` or `provenant trace`, and check the [consumer contract](../specs/consumer-contract.md) for the stability of commands, output and environment variables. (#3078)
- **Update scripts and integrations for the 2.0 command surface.** Removed commands and options exit 2 with their replacement; there are no aliases. Use the [consumer migration guide](../runbooks/using-provenant-2-from-another-repository.md) for the complete mapping, configuration changes and guidance for consuming repositories. (#3078, #3263)
- **The Fabric MCP server is removed.** `provenant fabric mcp` exits 2; lanes call `provenant fabric` from their shell. Install removes the Fabric MCP registrations it made. (#3078)
- **`wait --json` emits settlement events before its final result.** Read the final JSON record for the command envelope, or consume each event as it arrives. `--any` returns on settlement, including a node finishing within a running graph; a node starting does not end the wait. (#3078)
- **`status --json` reports omitted graphs by state.** Read `omitted` as a map from state to count. Status and wait now share node digests with causes, branches, PR and CI observations, result paths and provider errors; retained external observations are labelled stale and missing observations unknown. (#3181)

### Lanes and settlement

- **Replace the old disk policy keys** `policy.LAUNCH_DISK`, `policy.ADMISSION_DISK` and `policy.BUILD_DISK` with `policy.DISK_FLOOR`. Low disk space warns by default; set it to `refuse` for a hard floor. (#3078)
- **Build wait settings are removed.** Remove the old build and slot wait settings; busy build slots and resource admission warn by default. Launch policy reports its source and override, and strict enforcement is configurable. Writer scope remains writable across the worktree, with out-of-scope paths reported at settlement. (#3078, #3208, #3275)
- **Move repository setup and verification declarations to ports.** Replace `domains.worktrees.setup` and project setup lists with the `post_create` command port, and move `.provenant/verify.json` declarations to `.provenant/ports.json`. The [consumer migration guide](../runbooks/using-provenant-2-from-another-repository.md) explains ports. (#3078)
- **Update consumers of stop causes.** A blocked writer handoff settles with cause `blocked`; a refused launch records its specific cause instead of `preparation_refused`. (#3167)

### Pipelines and graphs

- **The writer launch timeout is replaced by separate launch and writer provisioning allowances.** Set the desired values in Fabric graph configuration; `provenant config schema` describes the settings. (#3078)
- **Replace node-level `brief` with `prompt` in graph definitions.** The old field is refused. (#3078)
- **One policy decides what follows a stopped lane.** Graphs can continue, select another eligible route or return control to the chair according to the [stop table](../specs/run.md#what-follows-a-stop); node policy can override unpinned causes. Standalone runs no longer continue themselves, so replace old continuation settings with graph stop policy. (#3171)
- **Replace `review-shape-f?-v?-s?` composites and `review-topology`** with `review-shape` and the `review-frame`, `review-verify` and `review-synthesis` launch values. Graph nodes can use `when = { name = value }` to skip a node when a condition does not hold. (#3172)
- **`run` takes a template first.** Use `provenant run task "brief"` for a plain lane; see `provenant help run` for graph and route options. Named launches with the same inputs return the existing graph; changed inputs get a new name. Template parameters are typed: supply declared values of the required type with `--set`. (#3178, #3179, #3180)

### Fabric

- **Upgrade peer hosts together.** Peer replies must declare their protocol, and a missing or invalid reply reports uncertainty without retrying a mutation. (#3078)

## Behaviour changes

- A state root may contain lane checkouts and provider homes. A state root placed inside a credential store, Git metadata or another declared state root is refused; ordinary checkout locations warn. (#3078)
- Lanes have the same tool, shell and network access as native subagents. Sandboxing is off by default and sandbox admission warns by default when a child lowers its parent's sandbox; set `lanes.sandbox_floor` to `strict` to retain the parent sandbox or `off` to disable that advisory. Explicit path or network restrictions select an enforcing sandbox, with a warning if its backend is unavailable. Credential protections remain in place. (#3078, #3244)
- `wait` shares native filesystem notifications across local graph targets on macOS and Linux. Peer and relay sources without an event subscription use the configured `domains.wait.local_interval_ms` fallback, which remains visible after settlement. (#3078)
- PR and CI observation use conditional requests and configurable fast/slow intervals; recent check-run durations determine when observation accelerates. Conditional PR wait rows report unknown review decisions; one-shot `pr status` retains its detailed review observation. (#3078)
- Lanes share the host Cargo home, registry and Git downloads, and can reuse matching warm build targets, including in nested workspaces. With sandboxing off, lanes can write host `~/.cargo/config`; an enforcing sandbox grants read-only access to that configuration. Cargo credentials remain protected and build output stays private. Set `domains.fabric.lanes.cargo_source_writes = false` for read-only source caches and offline Cargo. (#3078, #3207, #3274)
- Lane preambles and status report enforced limits with their configuration sources. (#3169)
- Writer token targets can trigger a wrap-up continuation; clean, pushed work and natural completion retain their own outcomes. Token policy can warn or stop, and status identifies the source of overrides. (#3257)
- Landing honours the effective landing port before publication. Repository forge and build admission adapters can be replaced or disabled independently through the sourced port table. (#3078)
- Every listed pool member remains capability-eligible; capability preferences, reset-adjusted account load and attributed outcome priors adjust ranking, with 10 per cent exploration by default. Route explanations show each member's prior and evidence count; pacing reserves and uncertain headroom warn and lower ranking. (#3207, #3271)
- `run implement` plans an unbounded brief before its junior writer starts. Use `--set bounded=true` for a brief already sized as one slice; plan outputs and `batch` slices keep a direct junior writer. `--explain` shows the plan and writer. (#3180)
- Graph node questions appear as requests in the inbox. Answering a request resumes the node, and repeated checkpoint saves do not duplicate the request. (#3170)

## Additions

- `config ports` shows effective backends and their sources; `verify [TIER]` uses the effective verification port. Repository ports override host ports and can provide setup, admission, CI observation, tracker and release checks. (#3078)
- `domains.run.resource_sample_interval_ms` controls guardian CPU and process-tree sampling, defaults to five seconds and reports its source. Process-tree freshness follows the selected interval. (#3078)

## Fixes

### CLI and install

- Commands read their declared configuration domains, so unrelated invalid settings warn without blocking the command; help lists those domains and preserves flag requirements and child commands. (#3078)
- `provenant upgrade` removes duplicate and stale menu-bar launch arguments. (#3078)

### Lanes and settlement

- Finished writer imports no longer leave a false worktree fence after an interrupted cleanup. An unresolved import names its fence, lane and exact reconciliation commands; restarting by work key uses the same custody evidence and preserves retained work. (#3078, #3273, #3174)
- Lanes admit verified linked worktrees wherever they live, including Claude Code's `.claude/worktrees`. Credential protection follows declared store paths, while project-local agent configuration warns. `run --explain` uses launch preparation's source admission decision. (#3279)

### Git and safety

- Lanes with GitHub credential delivery disabled no longer inherit host token environment variables. (#3078)
- `provenant gc` releases settled lane scratch and private Cargo output independently of worktree retention. GC measures nested allocated bytes consistently in preview and apply, reports failed cache operations with their paths, and skips busy observation gates immediately. `gc.free_floor` warns; `gc.critical_free` sets the critical threshold that `policy.DISK_FLOOR` decides (warn by default). (#3078)
- Cleanup covers managed and foreign worktrees using separate subsumed and landed evidence. The first foreign pass previews changes, idle clean worktrees retain their branches, and explicit discard archives the tip and working data before removal. Repository settings control exclusions and remote pruning. (#3078)
- Worktree retirement preserves unique detached commits before removing their checkout. Reusing a removed path starts fresh custody, and interrupted cleanup resumes reference removal before marking the lane pruned. (#3078)

### Accounts, quota and routing

- `agy` accounts no longer report an unavailable keychain after a normal keychain save. (#3078)
- `claude` accounts stay routable while an access token refreshes. Login-expiry warnings use the sign-in end date and default to ten days' notice. (#3078)
- Cursor registration and quota probes share one typed identity reader and no longer require the external SQLite command. Unavailable identity data remains an explicit failure. (#3078)
- Protected file references retain confidentiality classification through sentence punctuation, Markdown wrappers and normalised path separators. (#3078)
- Repositories can declare confidential inputs in `.provenant/config.toml` under `[launch_policy]`, using `confidential = true` or `protected_paths = ["private"]`. Launch records show the classification source, confidential work excludes training-enabled and unknown-treatment models, and recovery retains the accepted policy. (#3244)
- OpenCode drops valid but unsupported effort controls before admission. The applied route, launch record and route explanation retain a warning; invalid controls still report an error. (#3245)
- OpenCode account selection follows the registered Go or Zen plan, independent of its key. Quota lists each registered identity once; Go credentials no longer create a synthetic Zen account. Missing or unknown plans retain unknown quota evidence; free-model pacing remains separate. (#3256)

### Pipelines and graphs

- Occupied graph concurrency caps warn and let eligible work run unless an explicit policy refuses it; depleted work takes the next eligible route without waiting for a quota reset. (#3078)
- `stop` records cancellation while a graph launch holds its journal lock, reports the request while acknowledgement is pending, and prevents further launches within the cancelled scope once acknowledged. Recovery retains route and account pins and closes linked asks on cancellation. (#3078, #3254)
- `steer` can address an accepted live attempt before its graph checkpoint records the attempt reference, using verified local or authenticated peer ownership. Unsupported controls refuse with the `retry` alternative. (#3078, #3261)

### Telemetry and providers

- Lane and chair quota totals use verified account identity together; unknown usage stays unattributed. (#3078)
- The answer hook abstains with a diagnostic when its input is malformed, belongs to another harness or times out, so Cursor lanes can run shell commands. (#3078)
