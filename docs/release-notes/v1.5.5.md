# Provenant v1.5.5

Released 4 November 2026.

This patch release lets writers start in worktrees whose only uncommitted files are ignored by Git, such as `node_modules` or `target/`, which 1.5.4 refused as dirty. Review graphs now pass findings to the evaluator when a lens is missing and receive the real change range and spec, and `status --wait` waits on lanes, graphs and pull requests together.

## Behaviour changes

- The repository loads global agent rules once, while releases retain their existing instruction paths. Routing, tracker, research and branch protection guidance matches the current defaults (#2722).
- Lanes discover host user skills read-only for Claude, Codex, agy, OpenCode
  and Cursor, including installed skills linked into release directories. Set
  `domains.lanes.user_skills = "off"` to opt out, or override it per project ID
  and route model policy. Attempt output records exposure, paths and source
  (#2773).
- Writer, repairer, refactor and review roles default to running only targeted local checks, leaving full suites to CI on the pull request and combined checks to the batch head. Projects can override the policy in `.provenant/roles.toml` or via the `local_check_policy` preset parameter (#2758).

## Additions

- `status --wait` waits on lanes, graphs and PRs together, returning on the first observed transition. Use `--until all` to wait for every target or `--follow --json` to stream changes; timeout and source intervals are configurable under `[domains.wait]` (#2721).
- Configure `writer_writes` per project under `[domains.run.projects.<project ID>]` to replace the host-wide writer roots; an empty list grants none (#2795).
- Attempt route records retain selection provenance, and `telemetry stats --by route` groups resolved models and efforts (#2719).

## Fixes

### CLI and install

- The brief read-root scan skips `/`, `~` and ancestors of effective read roots, and `[domains.run] brief_read_root_warnings = false` turns the warning off (#2737).
- Brief read-root warnings no longer flag paths on lines that prohibit access (#2796).

### Lanes and settlement

- A lane that ends without a final handoff now settles as `review_required` instead of `succeeded`, and `provenant output` says why: "no handoff: the lane ended without reporting results" (#2707).
- A graph repair node is skipped, not launched, when the CI check it recovers from reported no failing checks (#2707).
- Every terminal attempt record, refusals before launch included, carries a `settlement_reason` (`completed`, `handoff_missing`, `declared_stop`, `provider_stop`, `uncommitted_work`, `pre_launch_refusal`, `cancelled`, `lost`, `unsettled`, `failed`) that waiters can match on (#2464).
- `provenant dispatch` exits non-zero and names the reason when every lane is refused because its route is held back, such as by the pacing reserve (#2464).
- `provenant run` accepts a worktree whose only uncommitted files are ignored by Git (such as `target/` or `.provenant/scratch/graphs/`). A worktree with uncommitted tracked or untracked changes still refuses, and the refusal names up to 12 dirty paths (#2735).
- Writer settlement completes when its branch has advanced beyond the lane head. Reconcile reports publication errors and offers `--abandon RUN/ATTEMPT --reason TEXT` to release an unsettleable fence while keeping its evidence (#2782).

### Git and safety

- `land` uses paced REST polling and retries GitHub rate limits within the wait budget. REST merge commits use the GitHub account's commit email rather than the local Git author email (#2757).

### Pipelines and graphs

- A preset node whose route names a configured pool, such as `verifier`, keeps that pool instead of being substituted with `senior` as if the route were undefined (#2697).
- `fabric graph cancel --reason` records why a graph was cancelled, and cancelled graphs no longer show settled members as pending or running (#2736).
- Cancelling a graph member on a remote host, and `lanes --wait`, now follow a policy retry chain to its live tail, so a successor queued during the lookup is no longer missed (#2736).
- Planned graphs retain expanded composite membership and completion edges across checkpoint reloads, allowing settled members to advance or report their typed failure. Existing pattern and fallback checkpoints recover the missing topology from the submitted specification. Invalid checkpoints name the node and the violated invariant (#2774).
- Review syntheses and evaluators can settle dispositions using only an upstream finding id, disposition and reason. Composite findings have member-qualified ids, and invalid findings errors identify the failing entry and field (#2779).
- Generator-evaluator reviews receive the changes from the configured base to the implement commit instead of an empty host diff. Sourced review nodes with no configured base still launch in repositories without `origin/HEAD`, and any review whose range is empty warns; set the preset's `base` to compare changes (#2783).
- Review stages pass FAIL findings and available lens results to the evaluator when one lens is unavailable. The minimum lens quorum is configurable, and graph status names blocking upstream nodes (#2784).
- Review nodes receive file acceptance criteria with their resolved path and digest. Planned big-batch reviews share one bounded excerpt from the batch worktree or project roots; lane-only or missing specs warn at explain and launch with guidance to use an issue number (#2785).

### Chair, inbox and console

- The console Inbox list has a draggable divider again and remembers its width between launches (#2732).
- The menu bar menu keeps its width when providers refuse models: an account row shows one short refusal summary, the submenu lists each refusal, and long text truncates at an overridable maximum width (#2761).

### Telemetry and providers

- OpenCode launches on macOS no longer fail confinement when `~/.config/opencode` exists: an exact read grant may name a directory, which the profile lists without reading its children. The macOS CI job now runs the provider tests. (#2793)
