# Provenant v1.3.0

Released 30 October 2026.

This release hardens lanes and landing: writer lanes run with a private Git directory and receive the GitHub credential only when `lanes.publish=true`, and a graph land merges only on independent review of the head it lands. It adds the `deliver` preset, which carries a writer's pull request through CI repair and review to a merge using each lane's `handoff` block, together with per-task network settings, private port blocks for writer lanes, a specific `error.code` for each run refusal, and scheduled routing policy with `route override`. Several changes need action on upgrade; see Breaking changes.

Provenant makes no stability promise; see [stability](README.md#stability).

## Breaking changes

- **`provenant check harness` is removed.** Run `scripts/check-harness` instead, which needs Python with PyYAML.
- **Run refusals carry their own `error.code` instead of `REFUSED` or `IO`.** Scripts that matched `REFUSED` or `IO` should match the new codes, such as `WRITER_SCOPE`, `CONFINEMENT`, `DISK_FLOOR`, `MEMORY_PRESSURE`, `LANE_CAP`, `BUILD_SETTINGS`, `GUARDIAN_IDENTITY`, `HOST_CLOCK`, `WRITER_REF_LOCKED` and `OBJECT_IMPORT_LIMIT`; `status` and exit codes are unchanged. `help --all --json` lists every run code with its meaning under `error_codes`, and the [CLI reference](../reference/cli.md#error-codes) renders it (#2273).
- **The `[disk_guard]` table and `provenant disk-guard` are removed.** Delete `[disk_guard]` from your configuration, and upgrade while no lane shows `disk guard paused builds`, because `install` retires the old disk-guard agent without resuming builds it paused. Lanes now pause their own builds below `gc.free_floor` and resume at the same floor, and housekeeping runs when a lane settles (#1941, #1952, #1965, #2169).
- **Drain writer lanes before upgrading.** Writer lanes now have a private Git directory with read-only shared refs, and the host verifies lane objects before they reach the shared repository, so lanes started by an earlier release keep grants that no longer match. An interrupted older attempt can resume only if it has private objects; otherwise start a fresh run (#2130, #2131, #2138, #2139, #2158).
- **`land N` replaces `pr land`.** Use `provenant land N` to check CI at the pull request head, merge and clean up; `--head SHA` is still accepted, and `pr land` now points to `land` (#1947).
- **The Claude Bash hook now refuses only irreversible actions.** It blocks a force push to the default branch and recursive `rm` of your home directory, the repository root or the Provenant state directory, and everything else, including `git reset --hard` and `--no-verify`, now runs. The `[domains.guard] deny` rule ids are now `force-push`, `rm-root` and `rm-state`, so update any `deny` list that uses the old ones (#1949).
- **Graphs in flight when you upgrade do not resume.** Let them finish before upgrading, or restart them afterwards; a peer on an earlier release cannot read the new checkpoints either (#2004, #2234).
- **Fabric moves to schema 9 and the run store (`run.sqlite3`) to schema 6 on upgrade, and older binaries refuse the upgraded stores.** Upgrade every host together. To go back to Fabric's previous schema, stop everything that holds the stores, archive `fabric.sqlite3*` and `host.sqlite3*` together, and restore a backup taken before the upgrade (#1968, #2029, #2125).
- **The upgrade drops records from the removed legacy import, including legacy tasks and messages.** Archive imported history with the previous release before upgrading if you still need it (#2144).

## Behaviour changes

### CLI and install

- The CLI is now organised around `run`, `status`, `land`, `quota` and `install`. `help --all` and `help COMMAND` show the advanced commands (#1947).
- `run` now waits up to 240 seconds for its result and prints a short tail. On timeout it prints the exact wait command, and `--wait` accepts durations such as `30m` (#1947).
- `status` is now the overview of active and recent lanes, with `--all` and `--json` for full records (#1947).
- `run`, `dispatch`, `cancel` and `resume` print a generated operation ID when none is given, so pass one explicitly for planned retries. Run and attempt targets accept a unique hex prefix of eight or more characters (#1947).
- Human command output defaults to a compact summary: counts by state, rows that need action first, and one `next:` command. `status`, `lanes`, `route list`, `quota show`, `pr status`, `accounts list` and `fabric graph status` summarise, and other commands say how much they omitted. Use the new global `--full` for complete detail or `--json` for the machine envelope (#2199).
- `output` shows the whole final result up to 12 KiB, with a settlement line and changed-file evidence, locally, with `--host` and with `--json`. A larger result keeps its head and tail and names the omitted bytes and `--full` (#2180).
- `output --tail N` reads peer artifacts as well as local ones, keeping at most 500 lines within `--max-bytes` (#2180).
- User configuration warns about unknown keys and invalid optional values instead of refusing the file, keeps the valid settings, and `provenant config check` lists every warning with its file and key. Syntax, size, schema version, credentials, Git-boundary, authority and confinement checks stay strict, and an invalid value that could widen a restriction, such as `lanes.publish`, enforced model policy, Fabric caps, graph limits, budgets or quota ceilings, still refuses the file (#2268).
- Model policy recovers per field, so valid siblings of an invalid value stay in force, but a malformed selector or schedule drops its whole rule or pacing override. Agent JSON requests ignore unknown fields with a warning naming the source (#2268).

### Lanes and settlement

- `install` and GC now print aggregate counts and exceptions by default, with `--json` for detail. Disk-floor refusals name the available space, the floor and `provenant gc --apply` (#1952).
- On macOS, lanes now run at lower priority by default (nice 10 for writers, 5 for read-only lanes and 15 for build-heavy lanes). Set the values in configuration, pass `--build-heavy` for build-intensive work, and read the applied value from `lanes --json` (#2018).
- Lane admission defers at critical macOS memory pressure by default, and `lanes` reports the refusal; `domains.fabric.lanes.memory_pressure_threshold` takes `critical`, `warning` or `never`, and the memory and disk floors still apply (#2093, #2268).
- Writers are admitted on new caps in `[domains.fabric.lanes]`, `max_writer_lanes` (default 40) and `max_project_writer_lanes` (default 30), which replace the host and project lane limits of 64 and 32 for writers. Out-of-range values are rejected when configuration loads (#2093, #2197).
- `max_concurrent_builds` throttles builds across the host rather than capping live writers, so idle writers no longer block each other or other projects. It defaults to `max(1, min(cores / cargo_build_jobs, GiB of RAM / 6))`, so a 10-core 16 GiB host gets 2, and `cargo_build_jobs` sets the default Cargo jobs; `-1` or omission selects the automatic value for either (#2093, #2197).
- A writer lane with `CARGO_TARGET_DIR` set gets a `cargo` shim that holds a host build slot for the whole of each compiling command (`build`, `check`, `clippy`, `test`, `run` and the like) and releases it when cargo exits or crashes. It shares CPU and memory fairly among lanes but is not a hard cap or a security boundary, and a build that waits longer than `build_wait_minutes` (default 30) for a slot or another build's Cargo lock gives up with an error (#2197).
- Each adapter now declares its launch capabilities (effort, resume, steering, network modes, image input, write mode). Dispatch, `run`, resume and graph validation refuse an unsupported request with the adapter and field named, before any worktree, reservation or receipt exists. Cursor takes no effort control, so `--effort` on a Cursor model is refused (#2126).
- Settlement resumes after a crash, `cancel` and `reconcile` stay responsive while Git runs, and a terminal result no longer needs a second `reconcile` (#2141, #2151, #2154, #2157).
- Lanes build with `CARGO_INCREMENTAL=0` and `CARGO_PROFILE_DEV_DEBUG=line-tables-only`, so a lane's target no longer accumulates incremental sessions; set `cargo_incremental` and `cargo_debug` in `[domains.fabric.lanes]` to restore either (#2159).
- Idle Cargo profile directories in lane caches are collected, least recently used first, until they fit within `domains.fabric.lanes.build_dir_max_bytes` (default 20 GiB) and free space is at least `gc.free_floor`. Collection runs when a lane settles, when admission finds space below the floor and in `provenant gc`, which reports what it removed; a directory with a Cargo lock held or written within `build_dir_grace_seconds` (default 15 minutes) is kept (#2159).
- Writers no longer stop at `review_required` or `uncommitted` over paths every implementation changes. The new `[domains.run] review_exempt` list defaults to release-note fragments, `docs/specs/`, `Cargo.lock` and `.tracker-input`, and Git metadata, hooks, provider control roots and CI workflows can never be listed (#2181).

### Git and safety

- Repositories that use `filter.*` (such as Git LFS), `include.*`, `includeIf.*` or `info/attributes` are no longer refused (#2147).
- Host-side fetch and push refuse a `core.sshCommand`, `credential.helper` or `uploadpack`/`receivepack` setting that runs a program from a lane-writable location (#2147).
- The pinned Git executable keeps its stable path, such as `/opt/homebrew/bin/git`, so `brew upgrade git` no longer breaks long-lived processes (#2147).
- Branch names follow Git's ref-format rules (`git check-ref-format --branch`), so names such as `feat/a+b`, `fix#12`, `user@x` and `@` work (#2165).
- Every refusal from the Claude Bash guard and the Git pre-push hook now shows an accepted example in one line, such as `git push origin my-topic` for a default-branch force push. Dynamic command names, `sleep` and `kill` are no longer refused (#2182).
- `land N` checks CI once, and `land N --wait` waits up to one hour (or `--wait=30m`, up to four hours) for the pinned head's required checks, then merges with a matching-head guard. It retries transient `gh` failures, matches required checks on their app, treats a skipped required check as unavailable and, with no required check, waits 60 seconds after the newest check registers (#2184).
- `land` reports typed CI and head-change failures, and reports landed if the pull request merged despite a merge error. A queued or auto-merge result exits 5 as `pending`, a merge whose local cleanup was refused exits successfully with `cleanup_pending: true`, and rerunning it on a merged pull request retries only the cleanup (#2184).
- `pr status` reads each pull request's head and checks in one request and keeps the rows it could read when another pull request is unavailable. An empty check result shows as `checks=unavailable`, never as passing, and `pr status N --wait` waits for the next change (#2075, #2184).

### Accounts, quota and routing

- A successful lane clears its account's quota authentication error, and reopening the menu or waking the host rechecks signed-out accounts (#1969).
- Paced routes reserve account quota for interactive use and weigh every current quota window when choosing a route. The reserve can be set per adapter (#1978).
- OpenCode Go models are now refused when their monthly allowance is unknown or below a configurable floor (default $60; zero disables it). For example, `--model opencode/opencode-go/minimax-m3.1-flash` is refused by default because its allowance is $20 (#1995).
- Provider capacity errors from Codex, Claude, OpenCode and Agy settle as `model_unavailable`, and a spent Claude or Codex account settles as `quota_limited`, instead of as generic failures; `lanes` shows either with the reason. A Claude 429 that names no plan allowance (usage, session or weekly limit) counts as transient capacity, even when it names a reset (#2029).
- A capacity stop resumes the same session after a short, jittered backoff, or redraws the route when there is no session, and read-only graph routes fall back to another model. A quota stop retries the same model at once on another registered, unpinned account that is not spent. `domains.routing.settlement_retries` (default 2, at most 32), `capacity_retry_seconds` (default 30), `capacity_retry_max_seconds` (default 600) and `retry_delay_ceiling_seconds` (default 3600) set the bounds (#2029).
- Account selection skips an account whose latest reading is exhausted, whatever its pacing policy, and falls through to an available account for the same model when admission refuses the first. `route pacing` confirms what it recorded (#2200).
- After a provider capacity error, model selection skips that model for `domains.routing.capacity_cooldown_seconds` (default 600; `0` disables). Explicit models and resumes stay available, and `quota` and `lanes` show live cooldowns (#2050).
- Bundled pools no longer include free routes, and Gemini Flash and OpenCode free routes run only read-only work, with configurable result checks. A failed check falls back once in a host-owned run and keeps the failed attempt, and nested dispatch picks the reliable fallback before launch (#2185).
- `route list --valid` lists the catalogued model and effort pairs that resolution and the configured allowance floor accept, without probing live providers (#2185).
- `install`, upgrades and `accounts register` keep Provenant's hooks, skills, MCP entry and shared Claude settings identical in every registered Claude and Codex account, and `provenant accounts sync [--dry-run]` repairs drift. `check install`, `accounts list` and `hosts doctor` report each account's sync state (#2198).
- `[domains.accounts.shared_settings]` selects which `settings.json` keys are shared. A value edited in one account is kept and reported as `settings_conflict`, and `accounts sync --adopt ACCOUNT` or `--force-settings` resolves it (#2198).
- `uninstall` no longer fails on a configuration defect; it warns and removes the recorded targets (#2198).
- The OpenCode Go catalogue drops Kimi K2.7 Code, MiMo V2.5, Muse Spark 1.2 Contributor and Go-hosted Claude Haiku 5.5, and replaces MiniMax M3 with MiniMax M3.1 Flash and Qwen3.7 Plus with Qwen3.8 Flash, both of which run only when the allowance floor is lowered. The paid Go endpoints of DeepSeek V4.1 Flash and GLM-5.3 Flash are the routed Go models, as provisional fallbacks, and MiMo V2.6 Flash is available by exact selection only (#1989).
- A routing pool member that lists an effort its catalogue model no longer supports no longer invalidates the configuration. The effort is dropped when the pool resolves, a dropped default `effort` falls back to none, and dispatch, `check config` and `hosts doctor` warn with the pool, effort, model and config source without failing. Malformed, duplicate and more than 16 efforts are still refused.

### Chair, inbox and console

- Saving a checkpoint now registers the chair for session discovery and reports a checkpoint left inconsistent by an interrupted save (#1968).
- Each chair now has its own inbox identity, so Claude and Codex chairs on one host no longer share an inbox. To recover an old binding, run `session save --client HARNESS --rebind` (#1968).
- Chair session start and checkpoint saves now warn when free space is low and give the commands to inspect disk use and run GC (#2023).
- The quota menu leads with local requests that need attention and task summaries, folds spent accounts and reports overview refresh failures (#2060).
- Session hooks now summarise settled lanes and closed pull requests, and session saves advise when a checkpoint needs trimming or holds stale references (#2100).

### Fabric and MCP

- Fabric run listings now return compact attempt summaries, newest first. Use `next_after` to page back and `op: status` for the full record (#1937).
- Fabric MCP now exposes a compact core catalogue, with graph, lease, task and event schemas available through discovery. Calls can submit and wait in one bounded call, and errors include recovery guidance (#1948).

## Additions

### CLI and install

- `install.sh` installs checksum-verified macOS arm64 release packages, or builds from source with `--from-source`. A first interactive install guides provider, hook and Claude account setup (#1945).
- `provenant upgrade` upgrades this host and its registered Fabric peers together, and reports any host that fails (#1945).
- Tagged releases publish packages and checksums with the release notes (#1945).
- `run` takes an optional task title, which `lanes` shows (#1968).
- `provenant run` accepts effort and network controls and shows the applied settings in its receipt (#2115).

### Lanes and settlement

- With `lanes.publish=true`, networked writer lanes can push branches and open pull requests with the host's `gh` login, and you merge with `provenant land N`. The setting defaults to `false` because it gives lanes the GitHub credential; host-side delivery (`delivery = "pr"`) needs no setting (#1938).
- A review lane takes `--head` with a full commit SHA and, optionally, `--base` with another, defaulting to the merge base with `origin/HEAD`. The range goes into the brief and is exported as `PROVENANT_LANE_HEAD` and `PROVENANT_LANE_BASE` (#2015).
- `provenant output --part receipt` prints the provenance of a settled reviewer or writer: the applied route, where its resolution came from and the reviewer attribution. Fields with no recorded evidence print `unknown` (#2022).
- Hosts can opt writer lanes into private APFS clones of the host Cargo registry and Git store, and build target seed generations from `origin/main` for writer targets (#2031).
- `provenant lane deliver --accept-review ATTEMPT` accepts and delivers a reviewed `review_required` writer, and the delivery receipt records the acceptance (#2039).
- Graph tasks can run named commands from `[domains.fabric.commands]` through the model-less `command` adapter, with read-only confinement, deadlines, descendant cleanup and a bounded output tail ending in `VERDICT: PASS|FAIL`. Command lanes have network on by default like other lanes, and `--network off` or `"network":"off"` restricts them to provider-only reach (#2119, #2276).
- A settled lane posts a terse notice (at most 300 bytes: attempt, outcome, `(partial)`, model, staged recovery, head and pull request) to the dispatching chair's inbox and appends a `lane_settled` entry to that chair's session log, once per attempt. Lanes dispatched by other lanes stay quiet, and `[lanes.settlement]` switches `notice`, `notice_read_only` and `chair_log` (#2125, #2217).
- Settlement notices and log entries survive a crash: recovery delivers any that were pending, a failed one is retried, and finished records are pruned under `[retention] logs_days` (#2125).
- A lane that finishes only part of its brief is flagged instead of reading as complete. An attempt carries `partial_signals` when its final answer ends with a `stopped_early` handoff, the provider reports a stop other than a finished turn, or a writer left uncommitted edits; `lanes` shows `(partial)` with a resume hint, and `telemetry stats` counts partial signals for every grouping (#2178).
- A `--base` review gets a `git-diff.stat` summary and one patch slice per changed file under `git-diff-slices/`, with an `index.txt`, beside the whole `git-diff.patch`. The review prompt points at the stat and slices first, and `git-context.json` reports whether the slice set is complete and which files it omits (#2179).
- Lanes end with one `handoff` JSON block for completion, partial finishes and continuation, giving `status` (`done`, `stopped_early` or `blocked`), `note`, `remaining`, `decisions` and `verify`. Lanes also keep bounded `handoff.json` progress outside the worktree, so when a provider stops without a final answer the next attempt, including a fresh account continuation, carries that progress on (#2188).
- `lanes` and `status` show a running lane whose build waits for a host build slot, or for another build's Cargo lock, as `build slot: ...` in `waiting_for`, the way they show admission waits (#2220).
- Each writer lane holds a private block of ports, given as `PROVENANT_LANE_PORT_BASE` and `PROVENANT_LANE_PORT_COUNT`, so parallel lanes running dev servers or tests do not collide. `lane_port_base` (default 30000), `lane_port_block` (default 16) and `lane_port_blocks` (default 64; 0 turns blocks off) in `[domains.fabric.lanes]` set the host-wide range, and a block is released when the lane's whole process tree has exited. A writer that finds every block held does not start and reports `no free lane port block` (#2245).
- A manifest task takes a `network` field (`on` or `off`) that overrides `--network` for that task, and `--route ADAPTER/NAME` names a model-less command lane without a manifest, for example `--route command/fmt-check --network off` (#2276).

### Git and safety

- `provenant pr contributions N [--json]` lists the attempts that took part in a pull request, with role, model and account. If recording fails, PR creation and landing warn and continue, and `--bind` retries it (#1968).
- Projects can set an advisory deny list of GitHub CLI verbs and labels for writer lanes. The list is empty by default, and GitHub permissions and repository rules remain the enforcement boundary (#2033).

### Accounts, quota and routing

- Pacing policies, window reserves and deadlines can be set per account, including pacing against another account's reset, and they also apply to free models. A monthly `day 31` deadline clamps to shorter months, and `daily` is accepted as a window selector (#1982).
- Pacing profiles, reset references and overrides name accounts by registered label or entry ID, or by `adapter/key` when a key is shared across providers. An unknown, ambiguous or stale reference is a configuration error reported before dispatch (#1992).
- Compaction, cache and lane policy can be layered per adapter, model and account, with schedules and expiring overrides. Claude launches receive the configured compaction window, and read-heavy and review routing can prefer cheap caches, with the reason shown. Policy fallback models and efforts that no longer match the catalogue are warned about and dropped (#2177, #2224; see [model policy](../runbooks/model-policy.md)).
- Quota refreshes keep a history: each account appends a reading to `quota/history/<account_key>.<adapter>.jsonl` when its windows, plan, credit balance or reset credits change, marking `reset` and `plan.change`. The file rotates at `domains.quota.history_max_bytes` (default 4 MiB), and history starts at this release (#2225).
- `provenant quota history [--account] [--since] [--until] [--limit]` lists the readings, and `--json` includes the plan price in force at each one (#2225).
- Accounts take a `plans` table of prices over time (`name`, `price`, `currency` defaulting to USD, `notional_usd` for free plans and `effective_from`), and an optional `directories` list of further config directories for the account (#2225).
- Routing policy rules and pacing overrides take a `schedule` with `starts`, `expires`, optional weekday `windows` and an IANA `tz`. A schedule is checked when configuration loads: an unknown `tz`, `starts` at or after `expires`, equal or out-of-range hours, duplicate or out-of-range weekdays, or more than 16 windows make the record invalid (#2224, #2236).
- `provenant route override set` records a pacing override with `--starts`, `--until`, repeatable `--window [DAYS@]START-END` (such as `mon-fri@23-7`) and `--tz`, and echoes the recorded rule and any rule it replaced; an override needs no expiry. `route override list` shows every pacing override and scheduled policy rule with its active state and time remaining, and `route override clear` removes all overrides or one scope's (#2236).

### Pipelines and graphs

- `provenant review` dispatches and collects named shapes of read-only reviewers, chosen by risk, task kind or changed paths, with an explicit per-review override (#1994).
- Fabric graph plan nodes expand validated, bounded fragments into one final pull request, and a stopped-early handoff creates one continuation per writer within a configurable budget. A plan fragment cannot choose an integration branch: integrate delivery needs a graph `integration_branch`, and always delivers to it (#1996).
- Graph limits and budgets are set on the host under `[domains.fabric.graph.limits]`, and a graph document cannot raise them. The host `expansion_depth` defaults to 64, which covers the bundled `big-batch` chain and composite nesting, and unknown usage is shown and can pause the graph (#2004, #2168).
- Graph nodes can route through a pool by alias and carry readable task titles (#2003).
- Graph nodes can pass selected outputs to later nodes, and `status` shows a short excerpt of each (#2005; see [graphs](../specs/fabric.md#bounded-graphs-and-route-fallback)).
- A `synthesise` node combines selected upstream outputs, and verdict and budget gates route failures to recovery nodes (#2006).
- `loop` nodes repeat a bounded body until their gate passes, and an exhausted loop pauses for stop, extension or acceptance (#2007; see [bounded loops](../specs/fabric.md#bounded-loops)).
- `run --preset` expands layered pipeline presets into Fabric graphs, waits on the whole graph, binds worktrees and read roots and takes concurrency overrides. `--explain` shows the graph, where each part came from, and its roles, limits and work (#2008, #2194).
- A run with no explicit model, route or preset selects a pipeline from bundled rules and optional repository overrides, and underspecified work goes through `scope-then-run`. Graph attempts record the selected preset and why it was chosen (#2009).
- A `decide` node posts a question and options to the inbox, and the chosen option becomes its verdict for a verdict gate to route on. With `timeout_seconds` and a `default`, the default is taken at the deadline; with a graph `decision_session`, a budget or other pause also raises an inbox decision that can resume, cancel or raise budgets. The checkpoint records who answered or that the default was taken, and an answer that names no option is rejected and asked again (#2010; see [node asks and decide nodes](../specs/fabric.md#node-asks-and-decide-nodes)).
- Graph CI-state gates wait for pull request or branch checks and record their evidence, failing closed when checks are unavailable or time out (#2075).
- `provenant tick` advances graphs whose CI or decision wait deadline has passed, and CI polling has configurable backoff with per-node overrides. On macOS, `install` and `upgrade` replace the separate GC LaunchAgent with one `dev.provenant.tick` agent that runs every 60 seconds and collects garbage daily (#2121).
- Preset roles give each stage its own brief, tier, effort, access, writer scope and selected outputs. Roles default to read-only access and resolve tiers through editable routing pools, and the bundled `scout-swarm`, `generator-evaluator`, `review-council` and `big-batch` presets use them (#2191, #2194).
- Presets compose ordered stages, parallel entries of different kinds and nested composite nodes, for example `stages = [{ id = "first", preset = "fan-out" }]`. `single`, `chain`, `fan-out` and `fan-out-synthesise` are bundled stage presets, `--set` addresses a stage directly (`first.route=X`), and a composite stage's children are named like `first--branch-1`. A composite exposes its declared outputs and one grouped status while keeping its children's evidence (#2192, #2215).
- Graph scouts can take extra read roots, and review or writer sources can be pinned to an explicit commit, a dependency's commit or the combined integration head. Source commits survive replay, and a clean writer context advances only by a fast-forward. Graph and preset `read_roots` must lie inside the project unless the host lists them in `[domains.fabric.graph] allowed_read_roots` (#2193, #2206).
- Presets can fan a role out over a list with `for_each` and read `${item.name}`, append a bundled prompt with `prompt_file`, and require a model family distinct from the writer's with `distinct_from = "writer"`. `run --preset` takes `--params-file`, `review-council` takes a `lenses` list and `big-batch` a `lanes` list (#2206).
- A graph that reads the integration branch pins its head, includes it in the graph ID and stops before synthesis if the branch moves. Review lenses default to the standard lens set (#2187) and take their tiers from the routing review shape chosen by risk (#2206).
- Preset stages draw on a role library: a bundled `roles.toml` plus optional user and repository `roles.toml` files, composed with `extends` and shown with their origins by `preset show --roles`. A role carries a short card and `skill:` references, recorded by digest on the node and shown in `run --explain`, and `scout-swarm` adds an external scout that researches outward, with a recorded substitution when no `web` route exists. The `scope` skill ships references for scouts, researcher, architect, acceptance writer and critic (#2208).
- Preset parameters can be typed tables with `type`, `default`, `min`, `max`, `enum` and `doc`, and a refused value names the parameter and the layer it came from. A `[pattern]` table records a preset's level, summary, citations, cost and when to select it; `preset explain NAME` shows both without creating state, and `preset list` shows level, summary and cost. The new `scope-then-run` preset scouts and scopes before implementing (#2209).
- The bundled `deliver` preset takes an approved slice from a writer's pull request to a merge. A CI gate waits on the pushed head with no model running; fresh repair agents fix failing checks on the same branch for up to `max_iterations` rounds, briefed with the check names, log excerpts, the writer's report and the `remaining` items of the previous agent's handoff, but never its transcript. A review council then judges the newest head and a land node merges it under the land tier policy; `land = 0` stops after review, and exhaustion asks the `decision_session` or pauses the graph (#2222, #2279; see [deliver through CI to land](../runbooks/presets.md#deliver-through-ci-to-land)).
- A graph `source` of `{ type = "head", node = "WRITER" }` pins the newest commit delivered by a writer or by the writers that continue it, so a review after any number of repairs judges the head that land merges (#2222; see [sources](../specs/fabric.md#sources-and-read-roots)).
- Presets can set `continues`, `land` nodes and a top-level `decision_session`. A graph input can select `remaining`, the `remaining[]` items of a node's handoff, and a loop body input can name a node outside the body to select it in every round (#2222, #2279).
- A CI gate can target an upstream writer's delivered branch, pin its head SHA and discard stale checks when a newer push arrives. Bounded failed-check evidence becomes findings for the repair node, and graph status shows the waiting check names, head and elapsed time (#2232).
- A graph writer can set `continues` to repair an earlier writer: it reuses that worktree and branch, and the host pushes its commits to the same pull request without force, so a moved branch is refused (#2233; see [writer continuation](../specs/fabric.md#writer-continuation)).
- A graph `land` node merges a writer's pull request through `provenant land` once its review and CI gates pass. By default routine and substantial tiers land automatically and crucial asks first; set `graph.land`, per project if needed, to change this, and the checkpoint records the policy, its source and who authorised the merge (#2234; see [land nodes](../specs/fabric.md#land-nodes)).
- An inbox answer never approves a land. A tier that asks posts a request naming `provenant land N --head SHA` and succeeds once the pull request is merged at the reviewed head; `hold` or any other answer fails the node (#2234).
- A land node accepts review evidence only from an agent attempt outside the writer's chain and bound to the head it merges, never from a CI, gate, loop or decision output. It finds its pull request by head branch in the same repository, and a repository preset layer or `roles.toml` cannot lower `land_tier` or turn on `land` beyond user configuration (#2222, #2234).
- A pull request delivered by a graph lists every review attempt, from review-council lenses to verification and synthesis, with its role, model family, verdict, route, outcome, pinned head and result command (#2235).
- `review-council` runs a verifier between the lenses and the synthesis, which tries to falsify each finding on the `verifier` route (falling back to `senior`), and the synthesis gives every finding a disposition of accepted, rejected or deferred. `generator-evaluator` has an evaluator stage with the same dispositions, and `verifiers = 0` skips verification (#2238).
- The verifier is routed away from the model families of every lens attempt and records the separation on the node. Where no other family is ready it substitutes with a note, unless the role sets `family = "cross_required"`, and a node that declares `dispositions` fails unless every finding carries an allowed disposition and a reason (#2262).
- Briefs for the bundled scope, slices and implement roles carry an authority envelope: the approved objective, the acceptance criteria, the authority held and an allowance for reversible assumptions. The lane records engineering decisions inside the envelope under DECISIONS instead of stopping, and keeps NEEDS-USER for owner decisions and for expanding authority (#2270).
- `pr wait`, `land` and the graph CI gate report `Conflict` when the pull request conflicts with its base, so CI never starts, and `NotScheduled` when the wait ended with no check registered for the head. Each gives a `next:` line, and required checks on the exact head stay mandatory (#2270).

### Chair, inbox and console

- Chair sessions keep a log of retry-safe updates and corrections, read in pages with a per-session retention setting that GC prunes. Successful lands and release-note cuts add milestones to it when a session is known (#1968, #2217).
- Direct dispatches are bound to an explicit chair identity, which nested launches and continuations inherit (#1968).
- Chair summaries can be read and edited by field and compared across revisions with `summary diff`. `chair summary update` and the MCP `summary_update` operation take an operation ID, so a retry returns the original result, even after a crash, and the same ID with a different request is refused (#1968, #2149).
- `console projects|sessions|overview|board|tree` show local projects, chair sessions, pending requests and runs (#1968).
- `console board` and `console tree` take `--hosts` to include peers, and name any peer that is unreachable or unsupported (#1968).
- The menu's console overview refreshes when records change and keeps the last good view if a refresh fails (#1968).
- `ask`, `inbox` and `answer` record human decisions and questions without the menu bar app, and the `fabric_inbox` MCP operations expose the same inbox. `inbox` also lists and answers requests on peer hosts (#1968).
- Queued answers reach the Claude session that asked, at its Bash tool calls, until it acknowledges them. Other providers receive them through Fabric mail (#1968).
- A request can link to a run, task or attempt and can carry a UTC deadline, after which it reads as expired and rejects late answers (#1968).

### Fabric and MCP

- Fabric MCP refusals for an unknown argument or action now name the one valid name it most likely meant when the match is close and unambiguous, such as `sessionId` for `session`. The call is still refused and nothing is corrected automatically (#2124).

### Telemetry and providers

- Idle provider CLIs update automatically, never while their lanes run. Updates can be turned off per provider, the interval (default 24 hours) and timeout are configurable, and a failed update keeps its cause in `provider-updates/worker.json` under the state root (#1977, #2175).
- Runs and attempts carry a bounded work `context`, and a run submitted with a field outside its nine fixed fields is refused (#2231). `telemetry stats --by pr|issue|graph|node|pattern|preset|role` groups attempt usage and API-equivalent cost by that context; graph groups add the latest checkpoint's verdicts, findings and repair rounds, and `--by pr` covers merged pull requests through their contribution links (#2011, #2189).
- `telemetry stats` shows configured monthly plan prices beside API-equivalent usage when quota history has a matching reading (#2189).
- `quota usage` and `telemetry stats` show chair session tokens, cache economics and API-equivalent cost beside lane spend, read from each session's transcript and its sub-agents'. The SessionStart hook records the serving account, or `unattributed` for a config directory that is not a registered account, and a session whose transcript cannot be read counts as unread, not as zero (#2173).
- Codex and Cursor attempts record cache reads and writes, and Claude's one-hour part of cache writes is kept as `cache_write_1h` (#2174).
- `telemetry stats` reports the cache-read share per model, account, provider and source (lane or chair), in text and under `cache` in JSON, with chair sessions in a `chair` section. It compares the share with the model policy's advisory targets under `cache_read_share` (#2174, #2177).

## Fixes

### CLI and install

- `status [ID]` accepts run, qualified task and attempt IDs, and `lanes --all --id ID` is accepted (#1971).
- `run` announces every repository preset file it uses, including inheritance-only and overridden layers (#2109).
- A misspelt command or flag suggests the nearest valid form, and usage errors for route resolution, peer output and account selection include a working example (#2183).

### Lanes and settlement

- Settling an attempt now removes its temporary build output, except when the attempt is lost without exit evidence (#1934).
- Writers orphaned by a reboot are settled when their reservation is stale or their worktree has been removed (#1939).
- Writer lanes can read briefs and graph documents from the primary checkout's scratch directory, `.provenant/scratch/` or `.agent-run/` (#1942).
- Shell lanes can run the system `python3` (#1950).
- `cancel` now recognises a writer that settled and released its reservation during recovery (#1970).
- `lanes --wait` returns at once when every named lane has already settled, and `lanes --wait` and `--watch` retry through transient run-store contention (#1983, #2013).
- `land` run from a clean merged worktree now removes that worktree and its branch. It also clears abandoned writer reservations, and refuses with a retry message when it cannot finish its live-worker check (#2014).
- Lanes run the installed `pnpm`, leave the pnpm store and `PNPM_HOME` unset and skip pnpm's pre-run dependency check, so `pnpm run <script>` uses a worktree the chair installed natively instead of failing with `ENOEXEC` or reinstalling into a store the lane cannot write. Corepack ignores the `packageManager` field and refuses downloads, so a pinned pnpm cannot arrive as a non-executable placeholder (#1944, #2040).
- A lane can no longer choose child or continuation run IDs that affect a sibling or bind it to a host chair; only a host-derived or host-sealed run ID inherits a chair, and `resume` and other host continuations keep theirs (#2054, #2088, #2099).
- `lanes --wait` no longer fails with a run-store path error when a running lane replaces its process checkpoint, and remaining run-store path errors name the path and the failed check (#2057, #2106).
- Writer custody from an earlier boot is recovered when filesystem device numbers change. If the evidence is insufficient, the reservation is kept (#2094).
- A child lane now inherits its parent's network restriction instead of being refused (#2097).
- Worktree registrations are refreshed after filesystem device renumbering when the recorded and Git identities still match. A stale registration shows the adoption step (#2112).
- Lane launches no longer refuse over hard-linked build or dependency files (`target/debug/incremental`, `node_modules/.pnpm`), a compiled profile above 64 KiB, or a path anchor for a file whose directory does not exist yet. Lanes still cannot create links, profiles may reach 512 KiB, and a failure names the size or the path and check (#1951, #2164).
- Attempt runtime deadlines now hold on the wall clock, so a laptop asleep through a deadline no longer keeps its provider, worktree, lock and quota for hours. The attempt settles as `timed_out` with the reason `runtime deadline exceeded`, `lanes` shows each running lane's `runtime_deadline`, and `providers.<id>.runtime_deadline_seconds` caps the deadline per provider (#2176).
- Excerpts of lane notes and OpenCode server errors in run reasons and diagnostics are now redacted for credentials, like fetch errors already were, and a cut excerpt ends in a single `…`.
- OpenCode writer lanes get the Rust and Node toolchain, with `~/.cargo/bin` on `PATH` and caches in the lane cache. On every adapter, Rust toolchain grants fall back to system tools when the Cargo or rustup directories are missing, so Codex and Agy writer lanes start on such hosts (#2253, #2255).
- `provenant run --worktree-branch` validates the prompt, title, route, fallback, knobs, delivery and access before it creates or claims the worktree, and admits against the base pinned at creation, including expressions such as `HEAD^`. A failed preflight leaves no stray worktree or branch (#2267).
- Pruning a merged, clean worktree is no longer blocked by an unreadable process of another user when that process provably cannot write the tree. Cleanup still needs proven ownership, no live writer, a clean tree and the merged head (#2267).
- A long step between store writes no longer makes the writes after it time out (#2267).
- A review verdict is captured when the lane's closing handoff block follows it, and only a line that starts with `VERDICT:` counts, not the word in prose or quotes.

### Git and safety

- Writer lanes commit with the host's configured Git name and email, while global Git configuration stays isolated (#1959).
- Read-only lanes can run Git commands that need temporary objects, which go to private scratch while the shared object store stays read-only (#2016).
- Settlement now refreshes the `origin` tracking ref for each writer branch, so a successful push shows in the shared repository (#2017).
- `land` recognises a primary checkout that uses a separate Git directory, and reports the problem when Git's worktree list is unusable (#2042).
- A worktree whose registration no longer matches is no longer refused as an unknown writer, and the refusal names the reason and the repair (#2067).
- `provenant worktree adopt PATH --owner NAME` replaces a stale registration when the writer lock is free, and a refusal because a writer is live names the process (#2067).
- `provenant worktree list` now prints plain paths, quoted only when needed, and `--json` keeps the structured path object (#2068).
- Delivery diagnostics redact credentials in malformed remote URLs, and host preparation fetches are limited to remote-tracking refs (#2113).
- New worktree branches are refused when the name differs from an existing branch only by case, Unicode normalisation or a path prefix, and origin refresh warns about branches that collide by case (#2132).
- A remote worktree base the remote did not advertise, such as `Origin/main` on a case-insensitive filesystem, now fails instead of using the local commit (#2132).
- Registered detached worktrees can now be removed with the usual safety checks. Unmerged detached commits need `--discard`, and refusals name the reason and a recovery command (#2133).
- `worktree adopt` now accepts a fresh linked worktree when the host cannot tell whether a writer is running, while observed live writers still refuse adoption (#2137).
- `provenant land` no longer refuses to fast-forward the base checkout over untracked files, such as Provenant's own scratch, and no longer keeps a finished worktree because an unrelated process works in a deleted directory.

### Accounts, quota and routing

- Resuming a named route keeps the earlier attempt's provider, model and account instead of drawing from the pool again (#1960).
- Transient Claude credential or identity read failures are now retried with a growing delay instead of reported as authentication failures. A manual quota check can retry an account in backoff (#1966).
- OpenCode Console free models now count against a separate `zen` account in lanes, telemetry, quota and pacing, so Go pacing no longer applies to them (#1988).
- Unregistered local OpenCode logins now identify paid lanes as `go` and Console lanes as `zen`, so continuing an older `local` run needs a new run (#1988).
- Quota reports and routing diagnostics label OpenCode Go usage as a partial lower bound and name a missing or stale calibration window (#1989).
- Expiring per-account dashboard floors now apply to quota and pacing (#1989).
- Route previews and effort errors list the supported efforts, and an unrecorded exact model gets suggestions of nearby catalogue IDs (#2021).
- Agy Claude models are no longer paced, reserved or refused because the Gemini pool is spent, and the reverse. A catalogue model can name a `quota_pool`, `route resolve` shows the pool it used, and the compact `provenant quota` summary shows each pool's state, for example `gemini exhausted, claude 40%` (#2227, #2242).

### Pipelines and graphs

- A graph whose worst-case checkpoint could exceed 16 MiB is now refused at submission with the size it could reach, and a planner admission or loop extension that would cross the limit pauses instead. Stored outputs, reasons and usage lists have fixed caps, so an accepted graph can always save and reload its checkpoint (#2044; see [checkpoint envelope](../specs/fabric.md#checkpoint-envelope)).
- A completed graph is reported as completed after a crash, not paused (#2047).

### Chair, inbox and console

- Session saves now require a Git checkout or `--project`, refuse conflicting project selections, and name the selected project in the output (#2127).

### Fabric and MCP

- Newer stored records, graph documents and database schemas now report `upgrade_required` with the reader and writer release, and stored and peer records accept additional fields (#2144).

### Telemetry and providers

- `telemetry stats` now prices recorded models against the bundled price table, including dated snapshots, and counts subscription entries. The Claude Code sub-agent report groups native usage by model and skips incomplete transcript records, and native JSON costs name the reviewed price table (#1943).
- OpenCode lanes now succeed where they failed with "provider identity was not observed": the answering model is read from the current session record, answers without `step_finish` count, and an exact model needs no catalogue entry. An unavailable OpenCode model reports `model_unavailable` (#1936, #1972, #1974, #1975).
- `telemetry stats` reports cost as unknown when no cost data exists, and notes partial coverage (#1984).
- Claude lanes with open network now enable WebFetch and WebSearch, and read-only Claude lanes get the same toolchain setup as Codex lanes (#2000).
- OpenCode lanes no longer fail with `UnexpectedStatus: 500` before a session starts. A failed attempt reports the server's own bounded cause for an HTTP 5xx instead of a bare status, and keeps the server log in `stderr.log` (#2160).
- `telemetry stats` and graph node usage no longer treat every attempt as partially priced because providers report no separate `reasoning` count. Only a missing price or a missing priced count leaves a cost a lower bound, and an empty report names the project it read (#2174).
