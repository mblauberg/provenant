# Provenant v2.3.0

Released 19 November 2026.

## Breaking changes

- Removed spellings now fail with the generic unknown-command or unknown-flag error. (#3284)
- `provenant pr watch` is removed; use `provenant wait --pr N`. There is no
  alias and no compatibility row: `provenant pr watch` now fails with clap's
  generic unknown-subcommand error (exit 2). (#3528)
- Replace `domains.fabric.lanes.max_concurrent_builds` with `[admission.build].slots` in host or project configuration; the retired key is ignored with the normal unknown-key warning. (#3252)
- Replace `gc.lane_cargo_cache_max` and `domains.fabric.lanes.build_dir_max_bytes` with `"lanes.cargo_cache_max"` in the host configuration `[knobs]` table. The budget defaults to 10% of the cache volume, accepts byte or percentage overrides and covers private and shared Cargo targets, reclaiming idle targets by last use while protecting live attempts and held Cargo locks. (#3515, #3521)

## Behaviour changes

- `wait --pr` absorbs the useful parts of the retired command. At a timeout it
  now prints the last known readable check summary (head, check counts, failing
  names, merge and review) and, when no check was ever reported, the cause and
  next step: check the workflow triggers or push an empty commit to start CI.
  Its budget is `--timeout` or `domains.wait.timeout_seconds`, clamped to
  `domains.wait.max_timeout_seconds`, with the source shown; the fixed 24-hour
  `pr watch` budget is deliberately dropped rather than copied into another
  hard-coded path. (#3528)
- `gc` reclaims settled attempt scratch and stale shared Cargo incremental sessions after `gc.idle`, and reports busy items in its preview. Discard archives exclude build caches and expire after `gc.discard_archive_retention`, which defaults to 14 days; lanes share the project Cargo target and warn when their Cargo target is in attempt scratch. See the [GC guide](../runbooks/gc.md). (#3541)
- The hard boundaries are now three outcomes, defined once in
  [ADR 0035](../adr/0035-three-hard-boundaries-and-flexible-everything-else.md):
  credentials and secrets reach only what was granted them, no lane changes
  another lane's work, and user gates, merge, release and ruleset changes need
  authority. Everything else warns and proceeds with its source shown. Default
  review panels now include the flexibility lens, and the security lens runs
  only for credential, secret or publication paths or on request. (#3448)
- Bundled route-pool weights are neutral: every member carries the catalogue's
  default weight and ranking is tiered by capability preference alone, so no
  account, plan or provider is favoured by the shipped defaults. Account- and
  plan-specific weights belong in local configuration. `route list` now reports
  the layer that set each weight (bundled, host config or project config), not
  just the pool member's own source. (#3438)
- Codex writers can select clean configuration with `providers.codex.clean_config`;
  read-only launches retain their configuration boundary. Provider capability
  failures can use eligible fallback routes, while local diagnostics and task
  briefs preserve their text. Advisory GitHub deny-list matches warn and proceed.
  (#3422)

## Additions

- In compact mode, read commands print tailored summaries instead of raw JSON dumps: `templates` shows layer, name, and one-line purpose per template; `templates show` reports name, layer, nodes with their roles, and parameters with defaults; `status` tallies counts by state, shows every failed, attention, or blocked row in full, and live rows up to the cap; and `result` reports outcome, cause, verdict when present, and result path. (#3493)
- `result NAME` now reports a review lane's verdict and structured findings in both human and `--json` output, with severity counts in the compact form and one verdict per lens for panels, reusing the projection `status` and `wait` already read. (#3499)
- `provenant run smoke` runs the bundled lane smoke graph; `provenant upgrade --verify` runs it after upgrading. (#3502)
- Port layers now deep-merge object fields, so a project or host layer that
  sets only `verify.base` keeps the lower layer's other verify fields, and
  `schema_version` is optional in an overlay. `config show` lists the effective
  `verify.base` and `verify.remote` with their layer. An unset `verify.base` is
  inferred from `refs/remotes/<remote>/HEAD`; if nothing resolves, the refusal
  names the key and the files to set with an example. Builtin verify tiers now
  use neutral cargo commands, while this repository keeps its own
  `scripts/verify-nextest` tiers in `config/ports.json`. Malformed port layers
  name their file and key instead of surfacing as a Git configuration error;
  an invalid project layer warns and is skipped so commands that do not need
  verify still run. (#3534)
- `wait --pr N --until complete` waits for all observed checks and head-filtered Actions workflow runs to finish (falling back with a warning when runs are unavailable) and reports every failed or cancelled check with its available link. The default still returns on the first failure. (#3548)
- Heavy commands coordinate through named admission classes (`[admission.<class>]`)
  configured across host and project scopes, replacing single-purpose build slots.
  Shipped `build` class preserves existing build slot concurrency derived from host
  cores and memory. (#3252)
- Lanes run `cargo`, `cargo-nextest`, and `nextest` through the `build` admission
  class by default across both compilation and test execution phases, preventing host
  stampedes during concurrent test runs. Nested invocations detect re-entrancy and
  pass through without deadlocking. (#3252)
- Hooks and scripts acquire slots via `provenant admit <CLASS> -- <COMMAND> [ARGS...]`,
  releasing leases on process exit or termination. `provenant status` reports waiters,
  holders, wait durations, and admission classes. Saturated classes warn and proceed
  after a configurable bounded wait. (#3252)
- `pr sync` merges a pull request's base into its branch and records a carry receipt. Landing can reuse independent approval across a clean base merge or a formatter-only change when the configured formatter reproduces both trees. Conflict resolutions that alter the merge tree still require fresh approval. (#3495, #3501)
- `scripts/prepare-release vX.Y.Z` bumps every workspace member's package version, refreshes the lock and the bug-template placeholder, collates the notes and warns about merged changes without a next.d fragment. `provenant check release` now names the missing tracked path in its evidence error. (#3527)
- Enhanced the bundled `batch` template to support structured items, ordering,
  and concurrency caps:
  - `items` accepts structured tables `{id, brief | brief_file, route | model, write_scope, after}`
    alongside bare strings. Mutual exclusion between brief/brief_file and route/model is enforced.
  - Slices can specify `after` dependencies; cycles and unknown IDs are rejected at compile time.
  - `max_parallel` caps concurrent slice execution, defaulting to `domains.fabric.batch.max_parallel`
    (with source shown in `--explain`) and overridable per run via `--set max_parallel=N`.
    Queued slices show as waiting in `status` with reason `cap` or `after`.
  - Slice settlement integrates into `integration_branch` incrementally; a merge conflict pauses
    only that slice, reporting conflicting files, while other slices continue running. (#3532)

## Fixes

### CLI and install

- `wait --pr N --head SHA` pins the wait to one head: until GitHub reports that
  exact SHA the reading stays pending, so a failed check on the previous head
  can no longer produce a verdict seconds after a push. The wait always names
  the head being watched. Without `--head`, when the PR's branch is known
  locally and its tip differs from GitHub's head, it warns and waits for the
  local tip instead. (#3373)
- `wait` ends with one line that states each target's settle state — settled ok,
  failed, needs input or still running at timeout — and the next command: resume
  the still-running targets, or re-read status once every target has settled.
  The observation-method note moves out of default human output into `--full`
  and the JSON envelope, so a chair can tell settled from timed out at a glance.
  (#3437)
- `wait --pr` reads a pull request's mergeability before diagnosing missing
  checks. A conflicting head now reports cause `merge_conflict` with a next step
  to merge the base into the branch (`git merge origin/BASE` then push) rather
  than blaming workflow triggers and suggesting an empty commit; a mergeable
  head keeps that trigger diagnosis. UNKNOWN mergeability is reread a bounded
  number of times before choosing. (#3492)
- Advice now names live commands. A graph whose worktree is missing tells the
  operator to run `provenant stop NAME` instead of the removed `cancel`, and an
  invariant test checks the commands named in user-facing Rust strings against
  the live command tree. (#3529)

### Lanes and settlement

- `provenant gc` collects eligible output from Provenant-created and primary worktrees when foreign cleanup is disabled, and collects managed worktrees of verified bound bare repositories. Live writers still protect their output. (#3295, #3351)
- Preflight a writer worktree before any plan node runs: a dirty tree is refused immediately with its paths and the `lanes.writer_dirty` setting, whose overridable choices are refuse (default), wip-commit (recorded in graph events) and continue-in-place. Manual retry re-pins to the worktree head when it descends from the pinned commit, warns with both ids, and refuses a non-descendant with both ids; a pin mismatch now has its own honest cause text. (#3338)
- A writer that exits without a handoff keeps its uncommitted paths and pinned head in the terminal reason and sealed writer terminal. An empty final message is recorded as the `empty_result` cause appended to that reason, never substituted for the path list, leaving the graph continuable for the chair. (#3341)
- Refuse lane identity checks when the host port table is unreadable instead of dropping its configured worktree roots. (#3362)
- Provider JSONL is retained losslessly, preserving complete handoffs; unparseable frames report an evidence defect naming their line rather than settling as generic task failures. (#3395)
- `provenant steer` now states, in one line, the configured
  `domains.fabric.steer.fallback` and the layer that set it before it interrupts
  the live attempt, so the restart is announced before it happens. (#3436)
- Steered lanes that settle together no longer race the launch lock: restarts
  claim slots from a shared gate spaced by the new, overridable
  `domains.fabric.steer.restart_spacing_ms` (default 2000 ms; 0 disables), and an
  applied wait names its configuration source. (#3436)
- `provenant steer --help` now names which providers keep the session across the
  restart (claude, codex, cursor, agy, opencode) and which start fresh (command,
  host-native routes). (#3436)
- Reusing a graph name with changed input now leads the launch output with `started NAME-2 (NAME exists with a different input)` and reports the prior handle as `named.superseded` in `--json`. `wait NAME` and `status NAME` warn that the graph was superseded and print the newer handle as the next step without redirecting the read. Name-grammar refusals suggest the normalised name, so `--name Foo-` suggests `foo`. (#3496)
- Keep run refusal causes distinct at the CLI and Fabric facade: the formerly collapsed secret, refusal, unsupported, writer-scope, confinement, disk, memory, lane-cap, build-setting and guardian-identity kinds now carry their own codes and next steps, and a held writer lease is a typed `writer_lease_held` with local holder facts. `--branch B --base REF` binds its managed worktree from the primary checkout or a linked worktree with the cause preserved when it cannot. (#3513)
- Released read-only scratch expires after `gc.idle` while results, handoffs and logs remain durable. GC uses an overridable sweep budget, resumes interrupted work and warns about stale sweep holders and unrelated EPERM processes. (#3518)
- `provenant wait --pr` tolerates malformed optional journal display fields and no longer writes null for empty failing checks. (#3520)
- A graph whose nodes have all settled and whose worktree is gone with no live
  presence or lease settles itself on the next tick: succeeded when its outcome
  succeeded, otherwise stopped with the reason "worktree removed after
  settlement". (#3530)
- `gc` warns about paused or pending graphs older than `gc.stale_graph_age`
  (default `1d`, source shown) whose branch has merged or whose PR is closed;
  `gc --apply` stops them. (#3530)
- `provenant status` lists live lanes first and counts settled-but-open graphs
  in one summary line; `--full` lists them. (#3530)
- Writer binding refusals name the holding attempt, branch, worktree, reservation age and liveness. `reconcile` reports the stale writer custody it releases, and stored-record errors identify the file and record type. Reconciliation warns about uncertain custody and unreadable reservations while continuing with other attempts. Process exits written by Provenant 2.0.0 remain readable. (#3533)
- Settlement reuses held writer custody during cleanup, caps failures before
  object import, and honours the durable retry deadline before recovery passes.
  Exhausted recovery stops with its cause visible as blocked in status; retries
  overdue by three minutes are flagged as stalled, including failures before a
  settlement driver starts. (#3537)
- `gc --dry-run` reports Cargo targets with held or unprobeable build locks as busy, excluding their bytes from reclaimable output. (#3539)
- `gc` recognises an exited sweep owner on macOS and resumes abandoned collection without waiting for its budget to expire. (#3539)
- Refused lane launches record a typed terminal cause plus the fixing command on the attempt and in `terminal-pending.json`, eliminating opaque refusals in `result` and `wait`. Unlaunched attempt settlement and queued proposal refusals settle with their typed cause instead of missing terminal causes. (#3544)
- Lane Git object import runs with `advice.graftFileDeprecated=false`, and git advice lines are filtered from stderr so advice messages are never surfaced as Provenant warnings. (#3544)
- A guardian retaining custody of a detached service no longer burns most of a
  CPU core. It waits on process, cancellation and signal events, repeats its
  bounded stop every 30 s instead of every 20 ms, and reads lane graph
  checkpoints only when it has a process to signal. (#3560)

### Git and safety

- Exclude declared credentials and links to them from staged skills, including credentials for unselected accounts. (#3416)
- Keep nested credential declarations protected beneath selected runtime and
  authentication grants. Admission and sandbox rendering now share one resolved
  policy, and unavailable enforcement cannot silently widen a selected sandbox
  route. Ordinary hard links remain available outside protected roots. (#3422)
- Git-driven tests in lanes can import into their own fixture repositories without the lane's private Git binding redirecting the operation. The lane Git wrapper also scrubs host global configuration for commands that act outside the lane checkout, so a host identity or credential helper never reaches another repository. (#3550)

### Accounts, quota and routing

- Route resolution now uses eligible outcomes from recent settled attempts, including pool draws without a matching graph tier. (#3282)
- Retry unclassified provider errors once on the same route before trying one eligible fallback route. (#3342)
- A route-level refusal is no longer hidden by an account reading of "probed, no figures"; the route reads unavailable. (#3364)
- A fresh usage reading below the headroom threshold clears recorded refusals,
  including model-scoped refusals without a pool; a successful run on a route
  clears that model's refusal. Each clearing records its source. `provenant
  quota clear ACCOUNT [MODEL]` removes recorded refusals and reports exactly
  what it removed. (#3450)
- `provenant` skips login-required accounts and continues to the next route after
  a local launch preparation failure. Unknown identity follows policy and warns
  by default. Unpinned fallback routes can use each candidate's account. (#3461)
- Login failures found during preparation are recorded for the whole account and
  remain unavailable until a newer successful login check or sign-in, or until
  expiry for adapters without a login check. Mixed candidate exclusions retain route fallback eligibility. Graph fallback briefly
  rechecks missing custody evidence across live settlement and resume before
  refusing. (#3461)
- Exact-model launch and `route list` resolve models through one effective-catalogue
  lookup, so a model reported as `source=discovered` no longer warns that it is
  absent from the catalogue at launch. A truly unknown model still warns and is
  passed to the provider for checking. (#3531)

### Pipelines and graphs

- Refused launches, retries and graph edits preserve the checkpoint and requester PATH. Graph admission checks the full prospective loop expansion before saving. Policy refusals retain safe schema positions through the lane relay without echoing caller keys or extension values. (#3391)
- Resuming graphs preserves cancellation and checkpoint corruption diagnostics, retries continuation pauses after budget increases, and retains valid extension lists within the checkpoint envelope. Malformed planner fragments keep their non-structural refusal cause. (#3391)
- Cloud placement refusals retain the cloud launch remedy. Secret-shaped retry, patch, launch, template and child inputs warn and proceed by default; warnings name schema fields and never values. Shape-only matches never refuse, even under a strict policy. Operator retry briefs matching an exact declared credential refuse atomically with a typed cause; launch, edit and child inputs are accepted. Local inputs and captured output retain their bytes; disclosure projections mask or withhold sensitive content. (#3391)
- Oversized held credentials withdraw publication instead of leaking raw values. Only retry admission skips over-bound ambient credentials, with one warning per process containing no names or values. (#3391)
- Graphs with large briefs save checkpoints faster. (#3549)

### Chair, inbox and console

- `chair log append` accepts markdown text directly on standard input or `--file`, and `chair log list` defaults `--session` to the active host chair session when known. Config refusals on keys with dedicated commands name their replacement command. Unknown CLI subcommands and flags receive suggestions, and `ci failures pr N M ...` accepts multiple pull requests with a single batched forge read. (#3497, #3504)

### Fabric

- Stored records deserialise on the default debug thread stack: nested `#[serde(flatten)]` chains in `records` and `fabric-runtime` are replaced with single-pass readers that keep unknown fields for round trips. Stored JSON is unchanged. The `RUST_MIN_STACK` override and the 8 MiB `check_providers --live` worker stacks stay for now: debug-build graph launches still need more than 2 MiB (#3542). (#3292)
- Cross-host projection preserves protocol fields and identifiers, limits prose credential masking to the assigned value, and keeps paged output readable when a page splits a mask or word. Peer refusal messages mask declared credentials before leaving the host. (#3422)

### Telemetry and providers

- On macOS, a timed-out provider updater no longer fails its check with a spurious EPERM while cleaning up its private process group. The ownership census now counts a member that is exiting or was reaped mid-kill as unsignalable, so only a live member keeps the EPERM an error. (#3380)
- The provider node-prefix tests derive expected paths from the canonicalised temporary directory, so they pass on macOS where `/var` resolves to `/private/var`. (#3380)
