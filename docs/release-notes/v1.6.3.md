# Provenant v1.6.3

Released 5 November 2026.

This release restores `review-council` and other multi-route dispatch on real hosts, and corrects 1.6.2, whose notes said its path-denial fix restored `review-council`: that fix was necessary but not enough, and councils kept failing on 1.6.2 for the reasons fixed here. Graph landing, review substitution and pending recovery also improve.

## Behaviour changes

- Graph landing resolves pull requests through REST, so GraphQL rate limits do not block that lookup (#2777).

## Additions

- Landing reports observed head moves as shadow review evidence without changing the exact-head gates (#2839).

## Fixes

- `land` handles stacked pull requests bottom first and checks each retargeted head before merging (#2849).
- Batch landing recovery excludes members whose requests were never sent and warns when an outcome remains unknown beyond the configured limit (#2872).
- A route whose availability is unknown or stale, or that cannot run here for another local reason, no longer blocks the routes after it. Lanes and graph nodes now move on to the next route, so one account with stale evidence cannot lock a host out of its other providers.
- Review lenses and verifiers can retry a settled task failure on their next route within a configurable limit, with the substitution recorded in graph status (#2837).
- A graph or lane with a remote-tracking base such as `origin/main` no longer fails after the remote moves past the last fetch. Provenant fetches that branch once, and a graph refused for a base it still cannot resolve now names the base instead of reporting `invalid input`.
- A `review-council` synthesis may now name a verified finding by the lens finding it carries, or by its qualified form. It used to fail with `disposition_count` (#2915).
- A Codex or OpenCode lane whose final message holds only its handoff or verdict no longer settles `review_required` when prose came before it. Each message now starts on its own line, so new `review-council` subjects no longer fail this way. Earlier runs keep their recorded result.
