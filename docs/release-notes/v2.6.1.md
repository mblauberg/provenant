# Provenant v2.6.1

Released 21 November 2026.


## Fixes

- `provenant worktree seed-build` now shows the bounded output of a failed `build.prepare` command as an indented cause in human output and in `error.cause` under `--json`; the output tail no longer has to be reproduced by hand to learn why the command failed. The cause follows the message and precedes `next:`. Under `redaction=full` the stream is masked at capture, before the tail window bounds it, so a secret straddling the cut cannot leak into the stored seed result, the refresh record or any display; the stored and printed text is the masked text. Long human causes keep the end (where the failure is) and mark the omitted bytes, while compact output stays one row (#3730)
- Refusals now render the diagnostic detail as an indented human cause (and as `error.cause` in JSON), between the message and `next:`; previously the detail reached only structured fields (#3730)
- Cross-host launches now fetch the pinned base from the peer clone's origin
  before resolving it, so a stale peer clone no longer refuses a launch whose
  base commit exists upstream. If the commit is still missing after the fetch,
  the refusal names the clone and the fetch outcome and is reported as a
  host-state failure rather than invalid input. If the launch is cancelled
  during the fetch, the cancellation is preserved instead of being reported as
  a failed fetch. (#3742)
- Cross-host launches again accept the peer's graph document: the submission carries a peer-bound attempt projection that withholds sender-local filesystem paths, brief inputs and extension state while retaining the sealed classification, the peer-bound document withholds the sender's submission snapshot (the other carrier of file-backed brief paths, with the brief travelling as prompt text), and a peer-side decode or admission refusal names the inner field or reason instead of a bare `document`. (#3744)
