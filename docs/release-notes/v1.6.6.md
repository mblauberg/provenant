# Provenant v1.6.6

Released 6 November 2026.

Writer start-up no longer stalls on Cargo seeding: with eight concurrent writers, the first started 17 seconds after launch instead of about 10 minutes, and supervisors use less CPU while their lanes wait. This release also removes legacy flags, renames the `review-council` preset to `review` and uppercases six error codes, so read Breaking changes and drain in-flight graphs before upgrading.

## Breaking changes

- The `--deliver-remote`, `--deliver-branch` and `--open-pr` flags are removed. Use `--deliver push`, `--deliver integrate:<branch>` or `--deliver pr` for host delivery.
- Error codes `launch_unknown`, `owner_local_only`, `unsupported_owner`, `console_app_unavailable`, `reconcile_incomplete` and `cli_failed` now use their uppercase spellings; update consumers that match these codes.
- Lane build seeding requires `tools/front-door/rust-toolchain.toml`; move any fixed release pin from `rust-toolchain` into its `[toolchain]` table.
- **Drain in-flight graphs before upgrading.** Graph launch retry checkpoints now retain the policy bound to each attempt (#2822, #2823).
- **The `review-council` preset is now `review`.** Finish graphs with an unresolved deferred review before upgrading, then use `review` for new runs (#2870).
- Review verdicts must use the final-line wire grammar; first-line legacy verdicts followed by prose are no longer accepted (#2870).
- `provenant review --json` now reports `graph`, `graph_id`, `status_command`, `document` and `continue`. It also reports `reviewers` from the graph checkpoint, including pending lenses with no run ID yet. The former top-level `verdicts`, `shape`, `selection_source`, `lens_reasons`, `size`, `kind`, `risk`, `risk_tags` and `target` fields are replaced by graph and provenance data. Exit status follows the final panel verdict. Explain uses the preset graph envelope, and lowering errors use preset diagnostics.

## Behaviour changes

### Pipelines and graphs

- Graph launch failure advice now names the `--fresh` preset rerun option (#2699).
- Reviews with equal base and head settle as inconclusive and report both commits; an unresolved base is reported separately (#2739).
- Graph outputs retain whether findings are complete, including partial composite coverage, so replay can report unavailable evidence (#2822).
- Graph nodes retain their own review-base commit before launching, so replay does not follow a moved reference (#2822).
- Read-only graph launches inspect an isolated view of their pinned source commit even if its checkout advances; status hides host checkout paths (#2822).
- Schema 2 graphs can require selected commit, verdict and findings outputs from direct sources, or complete composite findings. The consumer stops before launch when the value is unavailable; unsupported selections are refused at admission (#2822).
- A failed custody withdrawal blocks the launch with its cause and keeps its reservation for recovery (#2823).
- Graph status shows the same recorded wait and retry facts in human, JSON and MCP views without advancing the graph (#2823).
- Graph land records the PR number before requesting a merge and uses that identity when recovering an uncertain result (#2823).
- Graph launch retries use configurable limits and backoff, and report an exhausted retry budget (#2823).
- Review path floors raise review depth and add required lenses for protected and unknown paths, including protected Markdown paths. Projects can override the bundled `review.floors` policy; explain output reports applied or pending floors. When changed paths cannot be read, reviews apply the highest configured floor and report why (#2838).
- Review findings with malformed fields retain their usable evidence and report warnings to downstream consumers; unreadable severity is treated as blocking (#2840).
- Composites can reduce review verdicts by their worst outcome; landing checks every counted reviewer against the head (#2870).
- Presets declare which request values and parent parameters they accept. Unbound `--risk-tier` and `--task-kind` values warn when dropped (#2878).

## Additions

- **Projects can set writer capabilities.** Project defaults and graph node settings can grant PostgreSQL IPC, with invocation overrides (#2764).
- **Writer lanes share configured host paths.** Projects can grant writable shared paths and lanes receive the primary checkout and worktree Git directory locations (#2829).
- `provenant run --placement cloud:NAME` sends verification work to a configured Claude or Codex cloud environment and observes advisory results in status and lanes across chair restarts (#2889).
- A lane's supervisor no longer re-parses the whole configuration ten times a second while no child lane is queued, which cost each running lane about a fifth of a core.
- Read-only lanes can name a checkout with `--mode read-only --worktree PATH` without taking its writer lease.
- Add a GitHub event intake worker with signed webhook hints and periodic reconciliation (#2846).
- Pull request review and landing integrations can persist per-head work, leases and publication recovery records across restarts (#2847).
- `scripts/cloud-environment` prints a starting checklist for preparing a repository's cloud environment (#2889).
- `scripts/cloud-verify` writes a job-bound result with a verification command's commit, outcome and tracked-file changes (#2889).

## Fixes

### Lanes and settlement

- PR delivery checks for an existing pull request before creating one and stops when the lookup is uncertain (#2823).
- Retry transient writer lock contention and unknown custody during admission, while keeping live writer refusals distinct (#2823).
- Writer cache preparation no longer holds up Git setup for other lanes in the same repository. A refused peer branch collision reports that the existing branch was kept. `provenant run --wait` returns while a launch is still preparing: the lane reports `waiting` with its phase, and preparation carries on. Local preparation has at least five seconds and a larger window for multi-task submissions (#2934).
- A short `provenant run --wait` no longer refuses a writer with `WRITER_LOCK_BUSY` while another worktree is being created. It now shortens the admission window to no less than 60 seconds. `--admission-timeout` still sets any shorter limit.
- Writer lanes seed their private Cargo cache with one directory clone instead of a clone per file. Several lanes starting together on a large registry no longer spend minutes in launch preparation.

### Git and safety

- `gc` previews explain idle output reclamation in worktrees created by other tools. (#2834)
- Landing reports eligible small head moves as shadow class B evidence while retaining exact-head review gates (#2839).

### Pipelines and graphs

- Refuse a writer continuation when its predecessor left uncommitted edits, and report the affected paths without discarding them (#2822).
- Graph inputs distinguish missing or invalid findings from a direct attempt from a valid empty findings block (#2822).
- Preset review bases resolve in the bound worktree and stay pinned if the named ref moves (#2822).
- Graph PR delivery keeps its checkpoint unsettled when the PR identity is missing or cannot be recorded intact (#2823).
- Reviews prefer different model families within a reviewer group and report when a separate family is unavailable (#2870).
- Refuse secret-bearing preset prompts and parameters before retaining a graph, protect tracker advice, and allow ordinary bound paths (#2874).
