# Provenant v2.5.0

Released 20 November 2026.

Provenant 2.5.0 brings shared worktree leases, a configurable Cargo target seed budget, and status, install and identity fixes that keep lane work visible and preserved. Drain writer lanes on the previous version before upgrading: attempt evidence written before shared worktree leases is not upgraded in place.

## Breaking changes

- Drain writers before upgrading: finish or stop every writer lane on the previous version first. Attempt evidence written before shared worktree leases (guardian lock record, object binding schema, import pins) is not upgraded in place. `provenant reconcile` reports each such attempt as a reservation issue and fences it until it is reconciled; leftover `refs/provenant/import/<commit>` pins are removed when the matching attempt is cleaned up. (#3451)

## Behaviour changes

- `install` and `upgrade` now warn on stderr and name the live attempts when a release changes the live-attempt record format and attempts are still live. The advisory covers every live attempt under the installed state root, in any project and whatever the current directory; if those attempts cannot be inspected, it warns that it could not inspect them instead of staying silent. The warning also appears as `live_record_warning` in `--json` output. Install never refuses on it; drain the named attempts first or expect them to settle under the new release. See the [install runbook](../runbooks/install.md#upgrade). (#3361)
- Unscoped budget settlement preserves work whenever another writer shared the worktree during the attempt, including writers that settled before the budget stop. New sibling admissions pause during the commit decision (#3451).
- `provenant gc` now reports each Cargo target's reclaimable bytes as APFS private bytes -- the blocks no other clone shares -- where the filesystem can report them. Seeded worktree targets are clones that share blocks with their seed, so their allocated figure overstated what removal would free. The private figure is measured inside the existing target census walk, so it stays within `gc.sweep_budget`, resumes with the census cursor and adds no separate full-tree pass. It feeds both the reported reclaimable totals and the budget arithmetic, while eviction remains least-recently-used. The budget compares the summed private figure with the configured byte cap, so it can understate volume occupancy where clones share blocks. (#3595)
- Where private bytes are unavailable, GC says so, reports allocated bytes instead and never reports zero. The human and JSON summaries name which figure they carry. (#3595)
- Authorised lanes can share worktree files while keeping their staging, commits and credentials in separate attempt-private Git views. Host publication verifies objects and uses compare-and-swap; divergent sibling work is retained for recovery. Overlapping path claims warn the owning lane. See [lane lifecycle](../runbooks/lane-lifecycle.md). (#3451)
- Git output forwarding no longer hangs when `tail` reads a FIFO on Ubuntu 26.04, including commands that produce no output. (#3451)
- Lanes see the host Git configuration in full. Sandboxed lanes include and receive a read grant on the same host global Git configuration files as unsandboxed lanes, instead of filtering entries through an allowlist. Lanes no longer force `GIT_CONFIG_NOSYSTEM` or drop command-scope Git configuration (`GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_*`, `GIT_CONFIG_VALUE_*`, `GIT_CONFIG_PARAMETERS`); the lane's own token helper entries are appended on top of the host configuration so pushing keeps working. The `domains.lanes.git_config_allow` knob and the launch receipt's `git_config` field are removed.

## Additions

- `provenant gc` now collects a private Cargo target nothing has used for `gc.cargo_target_idle` (default `30d`), whatever `lanes.cargo_cache_max` allows. This covers targets of worktrees the chair or a person made, which were never collected before. A target whose worktree is gone, or was replaced by another directory at the same path, goes once the build-directory grace has passed. A lane cache whose worktree exists outside the project is kept only until `gc.cargo_target_idle`. A target held by a Cargo lock, a live lane or unobserved custody is always kept. (#3580)
- A target's last use is now the newer of its `.provenant-last-used` stamp and its newest file time. Launches and `provenant worktree seed-target` write the stamp, so a freshly seeded target no longer looks idle because of the file times its clone carried. (#3580)
- The preview names each target with its worktree, its reason (`worktree gone`, `worktree replaced`, `idle`, `over budget` or `tombstone`) and which evidence dated its last use. It reports allocated bytes and shows the budget and idle settings with their sources. (#3580)
- Lane caches and seed generation targets now carry Cargo's `CACHEDIR.TAG`, so backup and indexing tools skip them. (#3580)
- Retiring the old shared Cargo targets now honours `gc.sweep_budget` and the sweep lease. Each directory is renamed to a tombstone before it is deleted. Tombstones are deleted without being measured, and a stopped measurement resumes on the next pass, so a directory larger than one pass still goes. The preview probes and measures each directory as apply would. Every kept directory is reported with its cause: a held lock, a recent write or a failed lock probe. (#3576)
- `lanes.cargo_seed_budget` bounds each step of a private Cargo target seed (default 5m, ceiling 1h); its value and source appear in seed results. (#3620)

## Fixes

### CLI and install

`provenant land N` now binds only pull request N. It no longer reads the end
state of other pull requests on the branch or emits "stale binding sweep
failed" contribution-binding warnings naming them. Stale bindings remain
reconciled by `pr open` and `pr contributions --bind`. (#3494)
- `provenant gc` no longer floods its output with one EPERM census warning per unreadable process. A census now emits a single aggregated warning with a count and what it means: custody is unknown for those processes, so they are not treated as free. Repeated censuses on the same host do not repeat the warning, and `provenant gc --full` still lists each affected PID. (#3592)
- `provenant wait --pr --until complete` now defaults to a 60-minute budget from `domains.wait.pr_complete_timeout_seconds` (3600 seconds), covering a normal CI run without repeated re-arming. An explicit `--timeout` still wins, other waits keep `domains.wait.timeout_seconds`, and every budget still clamps to `domains.wait.max_timeout_seconds`. The help text and `config/harness-knobs.json` name the new setting. On timeout a complete wait now names the checks still pending in its last-known summary. (#3603)

### Lanes and settlement

- The worktrees test harness now routes the lane cargo shim's `admit build`
  invocation to the real admission command instead of treating it as a libtest
  argument. The shim re-enters the harness through `current_exe`, so an
  unrecognised `admit` fell through to the test suite and printed "worktree
  integration: invalid input parameter", leaving the native writer-capability
  probe quarantined. With `admit` dispatched like the other internal commands,
  the probe verifies that a lane's cargo and nextest shims reach
  `provenant admit build`, so `lane_prepare_isolates_nested_writer_state`
  leaves quarantine. (#3299)
- The writer preparation scratch test no longer runs a single oversized fixture that timed out on macOS. Each GitHub credential layout (missing token, linked config, linked XDG config) now has its own test, and the continuation phase records an effective sandbox so it actually exercises copying retained session state into the resumed attempt's private provider state. The test leaves quarantine and its per-test timeout override is gone. (#3300)
- A lane's HOME and XDG state directories are now rebound into the attempt scratch whenever they resolve inside the worktree the lane writes, with a warning naming the variable and both paths. Previously a tool could write state such as `.local/state/gh/device-id` under a HOME inside its worktree and have it committed with the lane's work. Values outside the worktree are unchanged. (#3457)
- Settlement now warns when a writer's commits add or modify tool state at the repository root. Paths whose first segment is `.local`, `.config` or `.cache` are named in the warning, so a lane that accidentally commits a tool's device identity under `.local/state/` no longer goes unnoticed. Ordinary dot paths such as `.github/x` and `src/.config` are unaffected. This is a warning: the lane still settles. An operator who wants a hard stop can set `policy.LANE_TOOL_STATE_COMMITTED` to `refuse`; an unreadable diff also warns and never blocks settlement. (#3457)
- A writer whose observed provider identity contradicts the requested route now settles `review_required` with its committed head and a warning naming both the requested and observed identities; the work is no longer failed or discarded when publication is unavailable. The head pinned by first settlement is used for this decision, so a writer that already committed under the mismatched identity keeps its work. A writer with no verified new head, and read-only lanes, keep the fatal `identity_mismatch` decision. (#3557)
- `status NAME --full` now reports an unsettled lane's last observed event time (naming whether it came from `output`, `started` or `queued`), host-local attempt directory, masked current admission-gated child command and known wait reason; a dead or unobservable writer gets a line too, a settled one does not. `child_command` is the admission-gated command, set only when the child went through the admission shim. Admission shims record a redacted, bounded argv when a lane waits for or holds a heavy-job slot, so the chair can tell a lane blocked in a repository lock from a hung writer. (#3559)
Settlement cleanup no longer refuses to end a lane's own processes because an
unrelated graph child is still running. A live graph child is a separate
attempt: it is never a recorded descendant of the lane's provider and never
carries the lane's sandbox mark, so it was never among the processes the lane
could signal. The old all-or-nothing gate held background loops and services
past settlement and kept the guardian in retained custody until that child
finished. Now a graph child spares only its own tree, which its own guardian
ends; the lane's recorded descendants and sandbox-marked escapees receive TERM
and then KILL after the descendant grace as usual, so cleanup resolves and the
writer fence is released on time. (#3568)
Settlement now waits a bounded time for a writer worktree's lock and wakes when
it is released. Lock contention no longer counts as a recovery failure, so a
busy holder can no longer block settlement and leave a steered writer's node
running with no successor. Status names the holder: `waiting for writer lock
<path>, held by attempt <id> (guardian live, reserved 4s ago)`. A steered
writer's continuation waits for custody release instead of being dropped, and
`provenant stop` on such a node resolves its queued steering at once, cause
shown. Commands that settle a lane's cleanup no longer wait on another holder's
lock; they leave it to the settlement worker. A lock held for three minutes
with no live guardian and no live settlement owner is reported as blocked and
names the recovery commands; an unidentified holder keeps the wait visible.
Reconcile now shows a recorded settlement failure as past evidence with its age
and recording process (`recorded 45s ago by process <pid>: ...`), never as a
current failure. `provenant reconcile --abandon` now releases a node whose
guardian died with its cleanup unresolved once a fresh census proves every
recorded process gone and no process carries the lane's sandbox mark;
otherwise it refuses and names the live PID or the omitted descendants. A lane
without a sandbox mark whose guardian never completed a census of its processes
is refused too, because a daemon that detached itself cannot be ruled out.
Deferred Git cleanup is now retried for launched writers too; a refused import
keeps its Git evidence instead.

Nodes blocked by lock contention before this release keep their blocked state.
Run `provenant reconcile <lane>`, or a bare `provenant reconcile` to sweep
every blocked node; an explicit reconcile resets the failure count and
settlement resumes. An import that settlement already sealed as refused
(status: `settlement exhausted three attempts; private Git retained for host
recovery`) is final and reconcile will not retry it. Release that node with
`provenant reconcile --abandon <lane> --reason <text>`: abandonment keeps the
private Git evidence but stops automatic import, so recover that work by hand.
- Codex writer token budgets now name their unit in `status` and `result`: `fresh_tokens` (uncached input, cache writes and output/reasoning, with cache reads excluded), the limit's value and the layer that set it, the fresh tokens counted for the attempt and the provider's cumulative input for comparison. The provider's cumulative figure is marked as session-wide when Codex has not attributed it to the attempt, and the adapter's turn-boundary caveat travels with it. (#3573)
- Codex config-deprecation notices from an inherited config (for example `[features].multi_agent`) are now warnings shown once per attempt beside the applied route, naming `config.toml` and pointing at `providers.codex.clean_config`. They no longer fail the lane or headline its result as provider errors. (#3573)
- `provenant gc --dry-run --full` no longer reports `0 Cargo target(s)` with an empty budget setting and source on a host with large caches. A 4096-entry cap on each cache measurement ended the sweep at the first large lane cache, so the target seed and Cargo target classes never ran and printed empty reports as measured zeros. Measurement now stops only at the sweep deadline. A class that a pass does not reach reports `not run in this pass`. (#3580)
- GC no longer keeps a Cargo target for ever because one of its top-level directories holds more than 1000 entries. The Cargo lock probe gave up at that count and reported a failed probe on every pass. It is now bounded only by its depth and the sweep deadline. (#3580)
- GC no longer deletes a lane cache or Cargo target that a launch or seed started using while the sweep measured it. Every removal of a lane cache or a Cargo target now rechecks the last-use stamps and the cache activity marker with the Cargo locks held, immediately before it detaches anything. (#3580)
- `provenant gc --apply` no longer fails with `lock acquisition timed out for .../gc-sweep.lock` on a busy host. The sweep's own fence watcher took the lease's metadata lock every 25 ms to read the lease, so a slow read could block the sweep's checkpoint past its wait. The watcher now reads the lease without the lock. (#3580)
- A lane guardian no longer loses a SIGTERM, cancellation or process event that arrives while it is cleaning up or retaining custody, so a signalled guardian ends within a bound and releases the lane's writer lock. Before, a guardian could ignore SIGTERM and hold the lock for hours. Retained custody is now bounded by `domains.run.retained_custody_seconds` (default 3600). Past the limit the guardian records the unresolved processes and what blocked them on the exit, then exits with status `timeout` (exit 124), leaving the fence for `provenant reconcile`. A signalled guardian also stops retrying an undurable reservation or exit publication after 5 s. `provenant status` names the holding guardian's PID and age while it is alive, and says when it is gone. (#3585)
- Retry an interrupted scheduled collection within minutes instead of waiting a day, and seed each project on its own. The daily collection deadline used to advance when the worker was launched, so a worker that was killed or failed cost a full day, and every tick then reported the stale failure as new. The deadline now advances only when a collection completes; a failed or interrupted one retries after 15 minutes, then 1 hour, 4 hours and 16 hours, capped at the daily cadence, a sweep that only stopped at its budget counts as progress rather than a failure, and tick reports the old failure as `gc=retry_pending` with its age and next retry. Seeding no longer stops at the first project whose verify base cannot be resolved: that project is recorded as skipped with a typed reason and a repair step, every other project is seeded, and tick reports counts such as `seed=ok:1 skipped:1`. (#3591)
- `provenant gc` no longer skips a whole project when its run store is unreadable. The import-pin backstop now warns on stderr and keeps the pins it cannot prove settled, so settled-lane collection and the path-based sweep still run. The counting test for batched `update-ref` no longer assumes the subcommand is the first Git argument. (#3605)
- Import pins under `refs/provenant/import-extra/<attempt>/` no longer outlive their attempt. Settlement now removes them on every terminal outcome (success, failure, cancellation and declared stop), and `provenant gc` removes the pins of settled or missing attempts, so ref listings and `packed-refs` stay small. Thousands of pins are deleted in one batched `update-ref --stdin` transaction rather than one Git process per pin. When cleanup withholds an import pin as recovery evidence (no writer slot or a writer fence with issues), it now keeps the import-extra pins too. `provenant gc --dry-run` reports how many import pins it would remove; only an applied pass deletes them. (#3605)
- Writer lanes are now told their working copy in every adapter's prompt: the absolute bound worktree path, branch and base, and that the primary checkout is not theirs. opencode lanes (Hy 4) read the primary checkout as the workspace root of a linked worktree and edited, branched and committed there while the bound worktree stayed at base. (#3611)
- Settlement now notices work made outside the bound worktree. When the primary checkout sits on a branch that did not exist at launch, or holds commits that no launch ref, fetched remote-tracking ref or other worktree reaches, the attempt settles `review_required` with the new `stray_work` reason, naming the branch or commits, instead of `succeeded`. A pull or fetch in the primary checkout is not stray work. (#3611)
- Writer lanes no longer start with a cold Cargo target when the host is busy. A seed generation records the size of its built target, so a clone need not walk a multi-gigabyte seed first, and stage cleanup, generation selection, the clone and dep-info aging each get their own budget rather than sharing one two-second deadline. A clone's reservation follows the cache census's byte unit -- near-zero private bytes when the census reports private sizes, the seed's recorded allocated size when it falls back to allocated bytes -- so it cannot evict an unrelated under-budget target under a private-byte census, while under the fallback it charges the incoming target's full size and evicts a target near the limit to make room. A budget fallback names the step that ran out and reports the effective value and its source in `cargo-target-setup.json` and the warning. A seed without a recorded size is accepted quietly (`size_recorded: false`), and an unreadable host config warns with its path and uses the compiled default. (#3620)
- Unsandboxed lanes now find the host's gh login whatever the adapter does to
  `XDG_CONFIG_HOME`. OpenCode points that variable at private state, so gh read
  an empty configuration and reported no authenticated hosts. The lane
  environment and the lane's `gh` shim now pin `GH_CONFIG_DIR` to the host's
  directory (the host's `GH_CONFIG_DIR`, else its `XDG_CONFIG_HOME/gh`, else
  `~/.config/gh`), and the launch receipt's `github_credential.detail` names
  it and its source. The lane preamble and runbooks now say a lane opens its
  pull request with `gh pr create --body-file`; `provenant pr open` is for a
  settled attempt. (#3641)

### Git and safety

- Shared-worktree lanes keep separate indexes and refs, so plain commits cannot include a sibling's staging and a new launch cannot reset it. Budget commits report the OID created by their own operation. Staged snapshots and stopped merges stay private while native convergence carries committed trees forward. Divergent host publication retains private work for recovery. (#3451)
- Worktree removal retains unresolved writer reservations and inspects every recorded private index, including unfinished Git operations. Clean-index retirement is durable before scratch cleanup, so interrupted cleanup can resume without losing staged work. (#3451)
- Worktree creation checks its destination and branch under exclusive custody; ambiguous partial additions are retained for inspection instead of risking deletion of another creator's checkout. See [worktrees](../worktrees.md). (#3451)
- Output redaction recognises GitLab, npm, Slack, Hugging Face, Google API and Stripe live token shapes. (#3584)
- Worktree creation, writer launches and landing evidence no longer refuse every request with "worktree Git output is malformed or incomplete" when the repository holds a remote ref without a `remote/branch` shape, such as `refs/remotes/pr123` from `git fetch origin pull/123/head:refs/remotes/pr123`. Every ref Git lists under `refs/remotes/` is now read as a remote ref. A Git read that fails or returns output Provenant cannot parse now names its subcommand, its exit status and Git's first stderr line, or the ref it could not read.

### Accounts, quota and routing

- Family aliases such as `claude/sonnet` now resolve through the effective model catalogue to their latest matching exact model, so graph launch no longer warns that the alias is not in the catalogue. Launch uses that exact model and records it in the launch receipt, while the requested route keeps the alias, so a provider that reports the exact model is no longer judged an identity mismatch. Unknown or ambiguous aliases still warn. (#3557)

### Pipelines and graphs

- Graph execution uses smaller stack frames in a debug build. The scheduling pass, gate evaluation, attempt admission and observation recording, the host launch preparation and the submit path are split into separate functions, and large values on the submit path are boxed. Threads that run graph execution now take one named size, `GRAPH_STACK_BYTES`, in place of the scattered `RUST_MIN_STACK` and 8 MiB worker overrides. (#3542)
- `provenant status` no longer hides a settled graph whose lanes are still running. The global listing now leads with the live-lane count from the same attempt presence digests as per-name status, and `--json` exposes it as `live_lanes`. (#3556)
- A graph resumed after a supervisor restart against lowered host structural limits no longer leaves a succeeded writer's node in `running`: the terminal attempt is still observed under the saved pause, so its node settles and `head` reports the writer's final commit from the bound branch instead of the base. The pause still admits no new launch: attempts the host never accepted are not started. It stays while any node is live and the graph is over the lowered limit, and clears when the graph fully settles or the limit is raised. (#3558)
- A graph checkpoint whose digest does not verify is no longer retried on every tick. The first host tick read reports it once with its typed reason (`bad_digest`, `decode`, and so on), records the failing bytes in a quarantine marker, and later ticks over the same bytes skip it instead of rebuilding the same warning on every pass. A checkpoint whose bytes change is reported again, restoring valid bytes clears the quarantine, and `provenant stop -- NAME` retires the record. Status and strict reads still show the corrupt graph with its ID, and other graphs keep indexing. (#3592)
- `WallTime::MAX` now names the greatest instant the wire accepts (253_402_207_200_000_000 microseconds, `9999-12-30T22:00:00.000000Z`), replacing a documented value that jiff rejects. The graph checkpoint envelope derives its latest wake time from that constant instead of silently falling back to the Unix epoch. (#3596)

### Fabric

`provenant run implement` no longer emits the `unbounded_brief_junior_writer` advisory for a junior writer without a plan input, write scope or explicit `plan` parameter, and the `domains.fabric.implement.warn_unbounded_junior` knob is removed. Implement starts a junior writer directly by default, so the warning contradicted the documented default and fired on every unplanned brief. No compatibility alias is kept: a host config that still names `warn_unbounded_junior` now receives the config loader's ordinary unknown-field warning, so remove that key. (#3494)

### Telemetry and providers

- An unclassified provider error now settles as `Unclassified` even after assistant text and exit 0; only a clean stream with no error settles as `Succeeded`. (#3342)
