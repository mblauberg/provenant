# Provenant v2.11.0

Released 27 November 2026.

Provenant 2.11.0 settles every lane through one classifier that reads a sealed evidence record, pins each graph's subject at admission so a later push cannot change what a lane reads or reviews, and checks each launch against the adapter's declared capabilities. The lane verb `provenant handoff` is now `provenant declare`, settlement and read-source names in JSON, config and smoke parameters change without aliases, and stored run records, graph checkpoints and the fabric store move to schemas 2.10.0 cannot read, so drain live lanes and upgrade every host together.

## Breaking changes

- JSON output renames, applied to stored run records by the run store migration (schema 15) and to graph checkpoints by the checkpoint migration (schema 3): `terminal_cause` is now `cause` (and `terminal_cause_code` is `cause_code`), `partial_signals` is `signals`, `terminal_evidence` is `terminal_basis`, `settlement_reason` is `settlement_class`, and graph `advance_error_code` and `advance_error` are `advance_code` and `advance_note`. The cause value `handoff_refused` is now `launch_handoff_refused`, and the advance code `writer_declared_stop` is `declared_stop`. Scripts that read the old keys must switch to the new ones. (#4020)
- The document explain `settlement` block has a new shape: `precedence` lists the layers, `knobs` is one entry per `lanes.settlement.*` key with its `key`, effective `value`, `layer`, `origin` and `allowed` values, and `warnings` holds the resolution warnings. Nothing reads the earlier shape, so scripts that parsed it must switch. (#4020)
- The lane verb `provenant handoff` is now `provenant declare`, with the same `--file` and `--stdin` flags; there is no alias. Its settings are `domains.run.declaration_journal_bytes`, `declaration_relay_seconds` and `declaration_relay_retries` (and their `projects.<project>` forms), the near-full warning is `DECLARATION_JOURNAL_NEAR_FULL`, a rejected field error is `declaration_invalid`, and lane status reports `declaration_source`. Lane prompts and scripts that call the old verb must switch. (#4020)
- Read-source, wait and smoke names changed with no alias; an old spelling in a script, config file or `--set` is refused as unknown. `lanes.read_source = "checkout"` is now `live`: install's `read-source-live` migration rewrites the host and host-project configs, while a repository's own `.provenant/config.toml` is left alone and warns `READ_SOURCE_VALUE_RENAMED` and resolves as `auto` until you edit it. `run --source` takes the same values as `lanes.read_source` (`auto`, `live`, `default_branch` or a Git ref), so replace `--source local` with `live` and `--source upstream` with `default_branch`. Smoke parameters `smoke-write`, `smoke-retry` and `smoke-steer` are `write`, `retry_probe` and `steer_probe`; smoke nodes `retry-route`, `steer-route` and `review` are `retry-probe`, `steer-probe` and `review-write`, and smoke graphs are named `smoke-*` rather than `smoke-verify-*`. An unverified smoke reports its typed cause's code, such as `SMOKE_PEER_FIXTURE_UNSUPPORTED` for a peer below the smoke protocol. A pull request wait that sees its head move reports `pr_head_moved`. (#4021)

## Behaviour changes

- Settlement is configurable per signal under `lanes.settlement.*` (`declaration_missing`, `declaration_malformed`, `empty_result`, `uncommitted_work`, `stray_work`, `no_work`). Each key layers default, host, project and route (`model_policy.defaults.lanes.settlement.<key>` or a rule's `policy.lanes.settlement.<key>`), and a document explain shows each winning value, its layer and the key's allowed values. A value outside a key's set warns `SETTLEMENT_POLICY_INVALID` and keeps the next layer. (#4020)
- A route whose observed provider identity contradicts the requested route now decides inside the one classifier: a writer's moved head is kept for review, never delivered or released, and every other lane fails with `identity_mismatch`. (#4020)
- A launch now checks every requested field against the adapter's declared capabilities before it starts. A missing model, effort or image-input capability degrades with a warning that names the declaration: routing prefers a fallback, an exact pin drops the effort control, and image attachments stay readable paths. `policy.LAUNCH_MODEL_UNSUPPORTED`, `policy.LAUNCH_EFFORT_UNSUPPORTED` and `policy.LAUNCH_IMAGE_INPUT_UNSUPPORTED` (warn by default), or an adapter's `on_gap` entry, set that to `off` or `refuse`; the adapter entry wins for that adapter, and each gap names the setting that chose its action, or both settings when it is the default. `run --explain` lists each node's capability gaps on its pinned adapter with those sources, and `[[adapter_capabilities]]` keys appear in the configuration reference. Write, network, resume and skill-location gaps always refuse, naming the adapter, field, reason and source. `policy.LAUNCH_FIELD_UNSUPPORTED`, which no launch read, is removed. (#4035, #4034)
- One `PinnedSubject` (repository, base, head, origin, policy and observation time) is resolved at admission and carried on the operation, graph document and checkpoint. A graph document with a subject uses schema v2; peer readers receive the same subject and head. Launch, review, wait and settlement consume those OIDs instead of re-resolving mutable refs, so a push between admission and capture cannot silently change an operation's subject; a moved head is reported as `head_check: moved{pinned, current}` and re-resolved only under an explicit `follow_latest` policy. Status shows the pinned subject beside its origin for every operation, and graphs admitted before this change load without one. A review subject's base is the merge base of the head and the requested base, so a branch behind its base no longer shows newer base commits as reverts; when no merge base can be computed the review keeps the base tip and warns. (#4021)
- An admitted subject's `policy_source` is now a typed provenance source (`{layer, origin}`) instead of a prose string. It names the layer that chose the pin and the exact file, key or command-line flag that supplied it; the wait reports the compiled profile, host config file or host-project config file with `FILE#KEY` as its origin, and a `--head`/`--pr-head-policy` pin names the launch flag. Diagnostics print it as `LAYER (ORIGIN)`. (#4021)
- A `--branch` writer with no `--base` is created from the `writer_base` commit pinned at admission, not from a ref re-read when the worktree is made, and `lanes.writer_base = "checkout"` pins the caller `HEAD` at admission. A pull request wait honours `domains.wait.pr_head_policy` (`wait --pr-head-policy`) instead of always pinning. (#4021)
- Remote peer readers now read the initiator's pinned `task.head`, the commit the graph's subject pinned at admission, instead of the peer checkout's own `HEAD` as in 2.10.0, and the review range comes from the pinned subject's base and head. A peer reads the commit the initiator admitted even when its own checkout is stale or has since moved. `lanes.read_source=live` is pinned on a peer and warns `READ_SOURCE_PINNED_FOR_PEER`. (#4043)

## Additions

- `provenant adapter capabilities [--json]` prints each adapter's declared capabilities, with the reason and source of every `no`, its harness version compatibility and measured launch, first-output and settlement times. `--adapter <id>` (repeatable) narrows the list and `--no-probe` skips the version read. `[[adapter_capabilities]]` entries in host or project config narrow an adapter's facts with `disable = [...]` and a `reason`; the matrix and `check` name the layer that narrowed them. The `domains.adapter.capabilities.measurements`, `measurement_samples` and `measurement_records` settings bound the measurements. (#4039, #4034)
- Harness versions are assessed against `[[harness_compatibility]]` ranges (`provenant_range`, `recommended_range`), bundled empty and overlaid by host and project config. `policy.HARNESS_VERSION_UNSUPPORTED` and `policy.HARNESS_VERSION_BROKEN` warn by default at launch and in `check providers`. `providers.<id>.version_probe` turns the bounded `--version` read off, and `providers.<id>.version_probe_timeout_seconds` (default 4, 1-60) bounds it. (#4036, #4034)

## Fixes

### CLI and install

- Every typed warning now carries a structured source, and observational policy warnings name the layer and knob that set the rule. A person sees each warning once per state change on stderr; a `--json` envelope keeps every warning, including repeats, so two launches in one state root both list `WRITER_CENSUS`. Orphan process warnings name their detected source and attempt. (#3778)
- Settled attempt scratch whose run record is unreadable or cannot prove custody is reclaimed after the configurable `gc.scratch_grace` (default `1d`, source shown by `provenant gc`) instead of being kept forever. The grace is measured from the scratch tree's newest write, and fresh publication, writer-lock and continuation checks still gate removal. Settlement applies the same release path. (#4092)
- Read-only GC previews observe `gc.preview_budget` (default `1s`) instead of a hidden hard-coded second. When a preview or an applied sweep stops at its bound, exit 3 now names which budget stopped the pass and how to raise it. (#4092)
- Attempt scratch collection ranks candidates largest first within each resume page and reports reclaimed bytes per retention class. (#4092)
- `check` warns (`ATTEMPT_SCRATCH_HIGH`) when attempt scratch exceeds `gc.scratch_warning_share` (default `0.25`) of measured free space; zero disables the warning and small positive shares retain their precision. (#4092)
- A failed `provenant upgrade --verify` now names the smoke graph id, the node that actually failed, that node's advance code and message, and a `provenant status GRAPH` next command. The summary is read from the graph checkpoint instead of the dependant's innermost `upstream_blocked` envelope, which only named its blocker. (#4102)
- Warnings for ignored `[[adapter_capabilities]]` rows, unreadable adapter configuration and skipped capability-matrix entries now carry a structured `detected` source naming their warning code, as required by `docs/specs/cli.md#warnings-are-typed-values`. (#4106)

### Lanes and settlement

- `run smoke` and `upgrade --verify` now run one hermetic lifecycle. A deterministic nonce fixture repository is built under `domains.smoke.fixture_root` (default `.local/state/provenant-smoke`, home-relative) in the home of every target host, locally and on peers through the `SmokeFixture` peer protocol (protocol 16). The graph's `review-write` node reviews the writer's own commit against `diff_base`, which defaults to the fixture head and must resolve inside the fixture. `review-fixture` reviews the fixture's own commit when `--set write=false` skips the writer, and `fixture_base` names the fixture commit the write node starts from. The `smoke-write` and `smoke-review` node names and the staged fixture are gone, and the verdict counts only when the nonce appears in both the read and the review result. A peer reader reads its own copy of that fixture rather than its checkout `HEAD`, so a stale peer clone still reads a valid tree, and no caller path or staged bytes cross the wire. `--set diff_base=BASE` still overrides the review base and its source is shown. (#4016, #4015)
- A lane that committed and pushed before declaring a stop no longer settles as `stopped_no_work`. Terminal settlement reads one sealed evidence record and decides once from the launch-pinned input head and the writer's verified head; a remote-tracking ref, a later prose line or a restart cannot reclassify the attempt. The typed cause now agrees across `status`, graph state and telemetry. (#4020)
- Graph admission reserves the worst-case configured `on_stop` defaults in the checkpoint envelope, so a graph with full host/project defaults cannot be refused by a bound that undercounts them. (#4020)
- Host and project `on_stop` defaults are typed graph settings, `[domains.fabric.graph.on_stop]` and `[domains.fabric.graph.projects.<project>.on_stop]`; an unknown cause or step is refused with its file and line. (#4020)
- A registered project whose checkout has vanished no longer fails settlement and `forge_events` on every tick. When the verified primary checkout is gone — even though its separate Git common directory survives — both tasks report it once with `PROJECT_ROOT_VANISHED` and the `provenant gc --apply` unregister command, then skip it; other projects keep their `ok` task state. `provenant gc --apply` now retires such a binding once its record has been idle for `gc.idle`, matching the advertised remedy. (#4107)

### Git and safety

- A repository whose Git remote is not `origin` and whose default branch is not `main` or `master` now follows its declared names through handoff push and branch recreation, cloud fetch and `ls-remote`, GC upstream probing, PR base resolution and delivery. The last compiled-in fallback in PR base resolution now uses the one resolved forge remote; a branch with its own tracking configuration keeps that remote. With no remote HEAD, a declared `git.protected` set (and a declared default branch) controls which branches delivery protects. `provenant config ports` prints the effective remote, default branch and protected set with the layer and key that supplied each, so a non-conventional name can be confirmed before a workflow runs. Conventional literals may still appear as shown defaults; they no longer decide behaviour. (#3288)

### Accounts, quota and routing

- `model_unavailable` keeps its typed identity through settlement and is treated as a route-level depletion: the run falls back to the next eligible candidate in the same tier, with the hand-off's rung, target and tier recorded on the restart. It is no longer collapsed into an adapter failure, which stranded a lens pinned to an exact model. (#4109)
- An exact model pin with no pool selection now derives a stand-in tier from its family and the configured `depletion.tiers`, so a capacity stop can hand off instead of going straight to the chair. (#4109)
- A pinned route with no fallback now names cause-neutral options: another eligible entry in `node.routes`, an applicable depletion ladder, or removing the route's account/model pin. (#4109)

### Pipelines and graphs

- Blocking findings now name the invariant they break in their top-level `class`. A finding without one is warned first at settlement; a blocking finding without one is refused. A fix round returns, per invariant, the `sweep` it ran, every `sites` it changed and the `pin` test, and round two reviews only that delta against the named invariants instead of re-running a full panel. Two distinct findings with the same invariant route to principal design, and a split verdict on one head goes to one adjudication node rather than starting another round. The `code-review` and `deliver` skills state this contract and cite the spec that declares it. (#4017)
- Each split panel gets a routed read-only adjudicator pinned to its reviewed head when recorded; its gate uses that adjudicator’s verdict after exactly one adjudication run, including splits in nested lens groups and in later repair rounds. A failed or missing adjudication result cannot be bypassed by the original panel verdict. An upheld blocking finding returns `VERDICT: FAIL` and routes to repair. (#4017)
- Different member verdicts, including PASS and INCONCLUSIVE, now trigger adjudication instead of silently reducing to one verdict. (#4017)
- Graph tasks now carry their admitted `PinnedSubject` on the graph document, checkpoint and coordination task, so a dispatched attempt uses the base, head, origin and policy that admission pinned. A peer placement records that subject as its own graph's subject; the run request carries only `head`, the one commit a lane reads. Status and later peer head checks read the persisted subject instead of re-resolving a mutable ref. (#4021)
- Lane-side graph calls no longer report `relay_peer_refused` when a macOS process census is unavailable or inconclusive. The relay proves ancestry from the kernel-reported parent chain with exact live identities and stable parent links, without relying on process start timestamp ordering. (#4070)
- Isolated macOS lanes can verify their host guardian using public kernel process metadata when the sandbox denies libproc access, while retaining the ancestry check. (#4070)
- `provenant wait GRAPH` now re-drives the journal-locked graph advance when a successful remote reading reports a terminal attempt against an unsettled checkpoint. A graph whose peer attempt has finished settles within the wait's normal reread cadence instead of timing out until a manual `provenant tick`. (#4104)
- A tick runs graph advancement as its own pass before forge polling, so slow forge pages cannot place graph settlement behind a long poll. (#4104)
- A structural or stop pause now yields any active expansion pause, and a settled planner fallback refreshes the pause it consumed, so a checkpoint cannot be saved with an active expansion pause that does not own the graph pause. (#4106)
- A stored checkpoint whose active expansion pause disagrees with the graph pause is quarantined after one tick report with a `provenant stop -- NAME` retire step, instead of repeating the same validation error on every tick. (#4106)

### Chair, inbox and console

- An untouched `# Console checkpoint` template no longer becomes a chair's derived summary line; the summary is unavailable until the checkpoint has real content (#3788).
- Installing with `PROVENANT_APPS_DIR` set away from `~/Applications` warns when an older bundle remains at the default path, instead of leaving a stale app silent (#3788).

### Fabric

- `provenant upgrade --verify --host PEER` now builds its smoke fixture in an owner-only scratch project under the home-relative `domains.smoke.fixture_root` instead of the system temporary directory. A peer can only name a project whose canonical common directory is relative to its home, so the old `$TMPDIR` fixture could never be projected and a remote smoke refused at `task--read` with `peer_project_unprojectable`. The `--dry-run` preview uses the same root. (#4101)
- `run --explain` no longer admits a peer-placed writer against the caller checkout. The writer is reported as proposed on the peer, naming the peer and the worktree it will provision from its branch; the explanation is no longer refused for the caller's state root. (#4103)
- `upgrade --verify --dry-run` now builds its `run smoke --explain` preview with the same writer branch and base as the real verify. The preview no longer reports a missing base or an admission refusal the launch would not produce. (#4103)
