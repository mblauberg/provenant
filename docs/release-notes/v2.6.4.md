# Provenant v2.6.4

Released 21 November 2026.


## Behaviour changes

- Oversized `console`, `disk report` and other command results no longer fail with `RESULT_TOO_LARGE`: they warn with the cap's source and the omitted byte count, then show a bounded view or page the result to an artefact (#3551)
- `provenant wait` inside a lane no longer refuses when no targets are named; it warns and waits on the lane's own children and relay-discovered targets, honouring `--all`, `--any`, `--fail-fast` and `--follow` for those children (#3551)
- Unreadable or malformed wait configuration now warns with the configuration source and uses the compiled defaults instead of aborting the wait (#3551)
- A disabled verify port warns with the port's source and returns a clear skipped result instead of an `unavailable` refusal, and an unreadable tracker port warns and falls back to compiled defaults (#3551)
- The Claude `WorktreeCreate` and `WorktreeRemove` hooks now adopt a clean, idle worktree a person created with a warning naming the difference, instead of refusing it for an off-path location or a missing hook ownership record (#3551)
- A dirty worktree, a tree with a live writer, and the primary checkout are still refused by the hooks and by the owner's non-forcing removal path (#3551)
- Recorded refusals are advisory. A model that is not in the catalogue was already attempted with a warning; now the provider's own refusal for a nonexistent model is classified like any other model-unavailable outcome, without an extra "nearest catalogued IDs" note (#3551)
- An explicit model pin whose recorded quota, pacing or provider refusal says exhausted is now attempted with a warning naming the record's source and expiry, because recorded refusals go stale. The carve-out covers only the exact pinned candidate: an automatic fallback keeps its recorded readiness, and a model-only pin still redraws to another account of that model when the chosen account is spent or refused, attempting the pin when no other account can serve it (#3551)
- `providers.<adapter>.out_of_scope_pin = refuse` no longer stops a launch. An out-of-scope explicit pin warns with its setting source and is attempted (#3551)
- `graph --pr N` against a template that does not accept a review range no longer fails with "--pr requires a review template". It warns with that source and proceeds with the host's default review shape (#3551)

## Fixes

- Settlement's Git configuration reads now name the operation, file and key or include that failed with a bounded underlying diagnostic, naming static key classes instead of keys or values so a credential in a config file cannot leak through a refusal; a transient Git config-lock collision from a sibling writer is waited out within one deadline shared by all of the operation's attempts, with the same bounded retry as Git mutations and the hardened environment and post-read checks still applied to the retried output, so concurrent settlement no longer fails with an opaque "repository Git configuration could not be read"
