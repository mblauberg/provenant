# Provenant v2.0.2

Provenant 2.0.2 improves provider routing and lane handoff across Cursor, Agy
and named command workflows. It includes the unpublished 2.0.1 fixes.

## Behaviour changes

- Cursor's shipped automatic pools include Composer and Grok at weight 1 to
  preserve monthly allowance. They exclude Auto because Cursor does not report
  its chosen model; owners may still pin Auto or add it to a configured pool.
  Supported effort levels reach Cursor while route and continuation identity
  keep the canonical model. (#3316)
- Compiled provider scopes limit shipped automatic pools; owner-configured pools
  and routes may select other catalogued models. An explicit
  `providers.<adapter>.models` setting restricts all automatic choices,
  including owner pools, routes, fallbacks and depletion hand-offs. Explicit
  pins follow the configured warn, refuse or allow policy. (#3316)
- Agy's HOME login stays explicitly selectable beside isolated registered
  accounts without becoming a registered credential root. Automatic routing
  continues to prefer registered identities. (#3316)

## Fixes

- Account registration rejects HOME and overlapping registered directories,
  and config checks report existing conflicts. (#3310)
- Cursor result capture keeps the final answer once. (#3311)
- One filtered requester PATH now drives model and account discovery, named
  command lookup, provider launch environments, and delivery tool lookup.
  Node and graph retries save that PATH with the retry checkpoint before the
  next tick can use stale tools. (#3315)
- Installed binaries no longer warn when their state root contains their own
  release assets; a state root inside an advisory location still warns. (#3308)
- Release checks accept relative symlinks to tracked files inside the same
  tree. Unsafe, untracked and chained targets remain findings. (#3320)
- Updated junior and orchestration examples to include the required `implement`
  template in `run` commands.
