# Provenant v2.0.2

Provenant 2.0.2 improves shared caches, provider routing and lane handoff across
repositories. It includes the unpublished 2.0.1 fixes.

## Behaviour changes

- Cursor's shipped automatic pools include Composer and Grok at weight 1 to
  preserve monthly allowance. They exclude Auto because Cursor does not report
  its chosen model; owners may still pin Auto or add it to a configured pool.
  Supported effort levels reach Cursor while route and continuation identity
  keep the canonical model. (#3316)
- Compiled provider scopes limit shipped automatic pools; owner-configured pools
  and routes may select other catalogued models. An explicit
  `providers.<adapter>.models` setting restricts all automatic choices,
  including owner pools, routes, fallbacks and depletion hand-offs. Explicit
  primary model pins follow the configured warn, refuse or allow policy;
  fallback models follow automatic scope rules. (#3316)
- Agy's HOME login stays explicitly selectable beside isolated registered
  accounts without becoming a registered credential root. Automatic routing
  continues to prefer registered identities. Continuations retain the applied
  provider and exact account key together, avoiding cross-provider key and
  label collisions. (#3316)

## Fixes

- Account registration rejects HOME and overlapping registered directories,
  and config checks report existing conflicts. (#3310)
- Cursor result capture keeps the final answer once. (#3311)
- A filtered requester `PATH` now reaches provider identity and version probes,
  bare command lookup and native and sandboxed launch environments. Automatic
  lookup excludes the canonical primary project and selected linked worktree,
  including when a requester starts in a subdirectory. Sandbox launches retain
  requester precedence behind private wrappers and ahead of fixed tool
  fallbacks. Graph retry capture failures preserve the last valid `PATH`;
  deliberate empty `PATH` values remain distinct. (#3315)
- Installed binaries no longer warn when their state root contains their own
  release assets; a state root inside an advisory location still warns. (#3308)
- Release checks accept relative symlinks to tracked files inside the same
  tree. Unsafe, untracked and chained targets remain findings. (#3320)
- Shared Cargo target seeds track each repository's verify base independently,
  prefer a matching project generation in writer lanes, and retain up to the
  configured generation count per project. The configured byte cap remains
  host-wide and may evict a project's only generation under pressure; failed
  refreshes retry at the next scheduled collection, and busy projects retry on
  the next tick. Full refreshes supersede busy retries, and interrupted workers
  retain their request scope for recovery. Seed builds and writer lanes now
  share the effective Cargo profile; reuse and currentness check that profile
  alongside the compiler and host platform, so copied seeds can provide reusable
  dependency artifacts. (#3326)
- Native package-cache binding keeps npm, pnpm and Corepack caches shared when an
  adapter redirects HOME or XDG state. Account homes and provider state stay
  isolated; explicit settings take precedence. npm follows the selected Node
  installation, including NVM, instead of a later Homebrew installation.
  Unsupported configuration warns without overriding it. (#3326)
- Writers launched from linked worktrees or subdirectories use the verified
  primary checkout for managed paths and project configuration. Separate Git
  directories retain that verified checkout hint, so registered projects
  protect configured writer roots before a worktree exists. Bare-backed writers
  use the common directory for managed allocation and host configuration.
  Worktree inventory reports the verified primary checkout even when Git lists
  its external metadata directory. GC refusals distinguish bare repositories
  from unresolved layouts. (#3317, #3326)
- Updated junior and orchestration examples to include the required `implement`
  template in `run` commands.
- Full documentation checks now announce their Cargo build and show the
  options for checking without a build.
- Installation guidance distinguishes active processes from stale workflow
  labels and limits client quiescence to configuration files in the write plan.
- `run --explain` identifies unsafe project binding directory ownership or
  permissions and gives a local repair command. (#3317)
- Configured account-directory diagnostics name the setting and a repair step,
  rather than suggesting sign-in at an unrelated default location. (#3326)
- Fabric, provider preparation and cloud collection retain the project-binding
  state path and repair command when ownership or permissions block access. (#3326)
- Stale OpenCode sign-out evidence remains advisory and labels executable-only
  launch readiness as unverified. (#3326)
- Typed peer output preserves field ownership through read/write round trips,
  avoiding duplicate JSON members without weakening frame validation. (#3326)
- Native pnpm cache binding follows the selected installation or Corepack
  project pin, using its supported selector family. npm cache paths support
  standard host path variables without forwarding unrelated environment values.
  Unresolved tool/config cases warn and preserve explicit settings. (#3326)
- Local binding-state refusals retain their repair guidance, while peer status
  and compact summaries keep private paths out of exported reasons. (#3326)
