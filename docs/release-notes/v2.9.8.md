# Provenant v2.9.8

Released 26 November 2026.

Provenant 2.9.8 is a reliability release. `upgrade --verify --host <peer>` exercises the remote write node again, so verify passes on hosts where 2.9.7 reported red. `run implement --branch` launches from an existing branch that is behind its base, lanes that rebase their own branch settle with a warning, and a writer no longer settles `review_required` because something else moved the primary checkout. `reconcile` ends a dead lane's recorded processes, terminal read-only reviews no longer keep custody uncertain, and an exhausted GitHub REST quota is reported as `FORGE_QUOTA` instead of an input error.

## Fixes

- `provenant upgrade --verify --host <peer>` now exercises the remote write node even when the launch supplies no `--branch`: the bundled smoke graph provisions a scratch branch from a sourced default (overridable with `--branch B --base REF` or `--set write_attempt`), and the peer creates the worktree in its own clone. A bundled smoke launch with no `diff_base` uses the checkout's first parent as its review base, or skips review with a reason if the parent is unavailable. The read lane sees the staged fixture at the path its brief names. (#4004)
- `provenant run implement --branch <existing> --base REF` now launches from the branch tip when the branch is behind `REF`. `--base` is the merge target, not an ancestry requirement or a reset: the lane records the given base and warns `BRANCH_BEHIND_BASE` with the number of commits behind, while a branch that already contains its base launches without that warning. This also applies when a clean checkout is reused at an occupied worktree path, the usual fix-up on an open PR. A base with no merge base with the branch still refuses with `WRITER_SCOPE`, naming `--worktree` and the merge or rebase remedy; a shallow clone whose missing history cannot prove unrelatedness warns and proceeds. (#3644)
- A terminal read-only review whose guardian left a reservation no longer keeps custody uncertain. `provenant reconcile` and `provenant stop` settle it with a typed warning naming the retained slot instead of re-recording the same fence on every pass, after the custody lock is confirmed free. A live lock, writer reservation or retained import still fences. (#3844)
- Released terminal read-only reservations no longer prevent cache cleanup or retention, and lane scratch now lives alongside temporary files outside attempt records. (#3844)
- A lane that rebases its branch can settle with a rewritten-history warning when the host branch still equals its pinned launch tip, including after a private force-push leaves the host tracking ref stale. The displaced tip is retained at `refs/provenant/recovery/<oid>`. A host tip advanced during the lane is merged or refused, even when a remote-tracking ref matches the lane head. `lanes.history.rebase = "refuse"` retains rewritten or diverged history instead. (#3890)
- A writer that committed on its bound branch no longer settles `review_required` because another process moved the primary checkout during its attempt. The host still observes the unaccounted move, now warns naming the new primary HEAD, and leaves it intact; the lane settles `succeeded` and the status text no longer claims the bound branch gained no commits. A lane whose bound branch stayed at base is still held as `stray_work` for review. Review lanes already read a pinned, read-only detached view of the PR head instead of checking it out in the primary checkout. (#3943)
- A lane killed before its guardian could publish an exit can leave processes holding the repository's heavy lock. `provenant reconcile <lane>` now ends the provider and descendants the attempt recorded, revalidating each identity before TERM and KILL under writer exclusion; a live guardian or a surviving process still fences settlement, and no exit is invented. When a guardian publishes its cleanup observation, status names observed PIDs and the custody writer-lock path; an open descriptor alone does not prove ownership. Unrecorded detached processes and arbitrary repository locks may remain unreported, including when the guardian dies before publishing an exit. (#3992)
- Concurrent project binding creation and checkout-hint updates now share one publication lock, and GC uses the same contention-safe read as other binding readers. (#3992)
- `provenant run review --pr N` no longer reports an exhausted GitHub REST core quota as `INVALID_INPUT` naming an input field the caller never supplied. When the batched GraphQL read has valid base and head subject fields plus a usable PR URL, it serves the review even if the check rollup is truncated; an incomplete cached row is refreshed first. Otherwise the refusal is typed `FORGE_QUOTA`, carries the reset and says `retry after <reset>`. A peer that refuses this way is retried rather than settled as a permanent verdict. (#3986)
