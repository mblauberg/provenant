# Provenant v1.8.0

Released 11 November 2026.

This release moves lane usage into a ledger that outlives the run store, makes the Fabric MCP server opt-in, and has `provenant land` decide the approval a pull request needs by tier. After upgrading, run `provenant telemetry backfill` once on each host and read Breaking changes, because later releases remove run history.

## Breaking changes

- Delivery receipts move to schema version 2. A pull request subject now records `base`, the head's merge base with the branch the pull request merges into (for a stack member, the head of the branch below), and its repository; `workflow receipt save` reads both from the forge and ignores any the request carries. Changed paths are read from that base. A receipt saved before this release is reported as `receipt shape retired: save it again`; saving the delivery at its revision replaces it, with the decision reset to pending. (#3132)
- The Fabric MCP server is now opt-in. A default install writes no `fabric` MCP entry, an upgrade removes the unchanged entry an earlier release wrote (edited and foreign entries stay), and lanes launch without it. Clients without a shell turn it on with `provenant config set fabric.mcp_server true` and reinstall; the `provenant fabric` and top-level commands cover every tool. (#3078)
- **Lane usage now lives in a usage ledger that outlives the run store.** After installing 1.8.0, run `provenant telemetry backfill` once on each host, before any later release removes run history; running it again adds nothing. Settlements record their usage in the ledger from now on. (#3138)
- `telemetry stats --claude-subagents`, the token-per-PR study module and its document, and the `tier` field of quota history records are removed; stored history lines that carry `tier` are still read and the field is ignored. Default `telemetry stats` output no longer lists native sub-agent attempts one per row; use `--detail` or `--json` for them. (#3139)
- **Cost and plan value now come from the usage ledger, in two commands.** `provenant telemetry cost [TARGET] [--by route|account|model|graph|node]` reports API-equivalent cost, and `provenant telemetry value` compares each account's usage with its plan price and quota readings. Both state unpriced and unattributed attempts instead of counting them as zero. `telemetry stats` no longer reports cost (including route outcome cost per success, the chair session cost and cost per accepted outcome) or `plan_value`; `telemetry value` reports cost per accepted outcome for the project. `telemetry stats --outcomes --suggest` ranks pipeline arms by confirmed findings per graph node, not per dollar. `telemetry mileage` no longer reports `effective` rates, and `quota usage` reports no cost; use the new commands. (#3165)

## Behaviour changes

- `provenant land` takes `land.approval = "receipt"` to let an accepted delivery receipt stand as a pull request's approval. A merge-in from the target or a rebase with an unchanged delta keeps the review; any other change, including a stacked pull request retargeted past the branch below it, needs a new receipt. The graph land node accepts the same carried-over heads. (#3132)
- `pr status`, `pr watch`, `land` waiting, the landing gate and post-merge checks read CI through one observer per repository. Concurrent waiters on a head share one GitHub read per poll, an unchanged answer is revalidated with a conditional request, and a rate limit is reported once with its reset time while every waiter backs off until then. `pr watch` now polls the pinned head itself instead of running `gh pr checks --watch`. (#3137)
- `pr watch` now fails on stale and startup-failure checks, like `pr status`, where `gh pr checks` treated them as pending. (#3137)
- `provenant run` prints the full `GRAPH/NODE/ATTEMPT` lane ID of each node it launched, one `lane:` line each, and `--json` carries them as `lane_ids` (#3186).
- The default `status` listing shows every active and needs-attention lane however many there are, and states how many settled lanes it left out (#3186).
- A launch or `retry` refused before admission prints the recorded route and reason instead of the fixed sentence (#3186).
- `provenant land` sets the approval a pull request needs by tier: `land.approval_tier` is `none` (CI only), `carry`, `delta` (every change after a review needs a review of that delta) or `auto`, the default, which is `none` for a pull request touching only tests, docs or review-exempt paths and `carry` otherwise. With `land.approval = "receipt"`, a change after a review that touches only tests, docs or review-exempt paths keeps the approval and the landing receipt lists the paths; any other change needs a review of only that delta (`workflow receipt save` takes `delta_from`, the reviewed head, in a `pr` subject). `land --accept-delta REASON` lands a delta no review covers, warns, and records the reason and your forge login in the receipt. (#3196)
- `provenant land N` now decides approval the way `land A B` does; it used to land without checking. A pull request with no approval that its tier needs is refused, so set `land.approval_tier = "none"` to land on CI alone. (#3196)
- Settlement now makes one detached attempt to collect a settled lane's worktree. If that attempt misses, nothing is queued: the next applied daily or pressure `provenant gc` sweep runs the same owner-bound collection for it, including a lane landed by fast-forward, and records its receipt as `pruned`. The host tick no longer reports a `completion_cleanup` task, and the completion request, claim and exhaustion files under `<state>/gc/completions`, `gc/completion-locks` and `gc/completion-exhausted` are no longer read. Those directories are inert after upgrade; you can delete them. (#3136)
- A review panel that cannot meet its provider-family minimum now runs with one warning per short family in the panel record and each lens's advice, including panels re-planned during repair. Set `review.diversity = "strict"` to refuse it as before (#3135).
- `max_repair_cycles` keeps its default of three and no longer has an upper limit. A raised budget runs every round before the principal's design judgement; the default budget still asks for it at the third review (#3135).
- `scripts/check-skill-negatives` reports short near-miss coverage and exits 0; it still fails when it cannot read a fixture (#3135).

## Fixes

- `status GRAPH/NODE/ATTEMPT` with a node or attempt that does not belong to the graph now fails at once with a `not_found` error naming the part that did not match. `status` and other lane listings no longer flush every settled writer's delivery receipt to disk, which made them take minutes while another lane was building. (#3144)

- `status`, `output` and `steer` now resolve a full `GRAPH/NODE/ATTEMPT` lane ID through the graph's checkpoint and show or act on only that lane, instead of rejecting it or listing every lane. `steer` also accepts `GRAPH/NODE`. (#3144)
- OpenCode lanes on free (Zen) models no longer fail `identity_unobserved` after the model answers. The answering provider and model are now read from either of OpenCode's session tables, and a lane is still refused if the session names a different provider than the one requested, so Go lanes stay strict. (#3152)
- A worktree-write lane whose settlement cannot publish its commits no longer leaves the bound worktree with the lane's files but the old HEAD and index. Settlement moves the lane's own files back, leaves any other edit untouched, and names the commit and branch holding the work in the settlement reason. (#3153)
- Route pacing now treats an account recorded `exhausted` as standby (score 0) even when the requested model's windows have not been probed, so a spent account no longer outranks ready ones. When launch preparation refuses the picked account because its allowance is spent, the launch moves to the next eligible account for the same model, at most once per account, and settles `usage_limited` naming each refused account only when none remain. A pinned account is never swapped. (#3155)
- A launch naming a model the selected account does not offer is refused before the provider starts, and the refusal lists the models the account offers. Agy accounts report their models through the usage probe (#3143).
- A failed lane's provider error shows the provider's whole error message from its structured result (bounded), not only the last stderr line (#3143).
