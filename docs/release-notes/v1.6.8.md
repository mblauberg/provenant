# Provenant v1.6.8

Released 6 November 2026.

This release removes the setup waits that held writers back, lets aliases move past exhausted accounts, and makes lanes behave more like agents launched directly, including `gh` and here-documents. See Breaking changes if you run an older OpenCode.

## Breaking changes

- Provenant no longer reads OpenCode's older `message` table, so OpenCode versions whose database lacks `session_message` lose model identity on lane records. Upgrade OpenCode; 2.2.5 is unaffected.

## Behaviour changes

- Writer settlement no longer quarantines instruction changes or requires protected-path review. The Bash guard no longer blocks removal of the repository root, and lane profiles no longer deny SysV creation system calls (#2964).
- Exact model IDs missing from the catalogue now warn and launch, including OpenCode models; the provider decides whether it can serve them (#2964).
- Writer setup now holds the repository lock only for upstream configuration writes and releases it before provider launch. Overlapping origin refresh requests share one fetch. The arrival-order queue and `domains.fabric.lanes.setup_lock_wait_seconds` setting have been removed. Host configuration that still sets `setup_lock_wait_seconds` fails to load until that line is removed (#2964).
- Lanes start without default spacing; configure `[domains.fabric.lanes] start_spacing_ms` to space both classes. Starting lanes report launch preparation when no limit holds them, and reached lane caps show their counts (#2991).

## Additions

- **The unconfigured memory floor is advisory.** A lane reports `MEMORY_FLOOR` with the observed capacity and a next action instead of being refused solely by the shipped memory floor; the configured pressure threshold still applies.
- **Total lane caps identify their settings.** `max_lanes` and `max_project_lanes` retain the existing host and project defaults, can be lowered in host configuration, and appear with their source when admission reaches a cap.
- Supervisors of waiting lanes now scan processes on real events and at a 5 s backstop instead of ten times a second.

## Fixes

### CLI and install

- **Refusals keep source text out of diagnostic details.** Writer and I/O diagnostics retain a safe cause and next action without copying process evidence or database error text (#2820).
- **Shared settings refusals have a stable code.** Identity and credential keys that cannot be synced report `SHARED_SETTINGS_NEVER_SYNCED` with the existing explanation.

### Lanes and settlement

- Agy lanes use their private scratch directory when separate provider state is unavailable.
- The argv prompt threshold can be adjusted with `domains.run.argv_prompt_limit_bytes`.
- A build-slot shim that cannot be configured now warns and lets the lane start without the shim.
- Claude lanes use their private scratch directory when separate provider state is unavailable.
- Dependency preparation refusals identify the setting and profile controlling automatic installation.
- Writer dispatch warns and continues when host disk space cannot be observed.
- Writer disk checks use compiled GC defaults when their configuration cannot be read.
- Read-only provider preparation warns when its Git launcher cannot be included in the search path, while writer Git bindings remain required.
- Grant-count and profile-size refusals identify their effective limits, settings and origins.
- Invalid optional discovery paths now warn and are omitted before sandbox grants are prepared.
- Invalid provider network endpoints now warn and are omitted while valid network access remains available.
- Lanes with a missing search path warn and use system defaults with the private Git wrapper.
- Writers report the port-pool setting origin on exhaustion and warn when an I/O error leaves them without an allocated block.
- Invalid native control labels now warn and are omitted rather than preventing a lane from launching.
- Provider lanes preserve native Cargo search paths and warn when a path separator makes the optional entry unusable.
- OpenCode writer lanes preserve non-UTF-8 paths in their tool search path.
- OpenCode lanes use their private scratch directory when separate provider state is unavailable.
- Read-only lanes in the primary checkout no longer receive a worktree Git directory identity.
- Lanes use the compiled priority and warn if their configured priority cannot be read.
- Authentication and native-control profile limits can be raised through the lane grant limit.
- Lanes warn and use compiled profile limits when their resource settings cannot be read.
- Read-only lanes warn and omit their Git launcher from the search path when its directory contains a path separator.
- Provider executables in shared system prefixes are prepared with a narrow grant and a warning when their package directory cannot be granted.
- Claude lane shell setup preserves non-UTF-8 Cargo setting values instead of refusing preparation.
- Optional grants with paths the sandbox cannot represent are omitted with a warning, and affected library closures report as incomplete.
- The encoded write-grant limit can be raised with `domains.run.write_grant_limit_bytes`, and receipts identify its value and origin.
- **Disk refusals identify the floor's source.** Diagnostics say whether `gc.free_floor` came from host configuration or the shipped default, alongside the limiting space and remedy.
- **Invalid input names its field and limit.** Oversized bounded fields carry a safe field path, byte limit and next action in typed graph and MCP diagnostics.
- **Graph status explains fallback refusals.** A denied route fallback now reports the lane outcome and available typed readiness cause alongside the custody reason, host delivery output limits retain their command and byte limit, and resource refusals identify their limits and corrective actions.
- **Input refusals explain the safe cause.** Typed input refusals identify oversized or unreadable input and a next action without copying source error text into diagnostic details.
- **Lane-cap refusals identify the limiting policy.** Diagnostics distinguish configured writer limits from fixed total-lane ceilings and name the source of a writer limit.
- Lane rows keep the Provenant-written facts that a refusal or retry needs. An unresolvable configured command, an unconfigured host-native route and an unobserved provider identity carry the typed `terminal_cause` values `command_unavailable`, `host_native_unconfigured` and `identity_unobserved`. The command refusal names the configured executable, and a policy retry names its attempt, for example "retrying this session (attempt 2 of 2)". Neither copies provider output or an operating-system error (#2820).
- **Memory-pressure refusals identify their policy source.** The observed pressure, configured threshold and whether it came from host configuration or the shipped default are available in diagnostics.
- **Process-limit refusals explain host capacity.** Diagnostics identify the operating-system process limit, reserved headroom and corrective action across run and graph surfaces.
- **Provider refusals explain the next action safely.** Quota, rate-limit, capacity, login, identity and skipped-route reasons no longer copy provider messages or account paths into lane status.
- **Access-denial diagnostics keep captured text private.** Lane status suggests checking access grants and filesystem permissions without copying a path or provider output into the reason.
- Lane rows identify unsupported platforms, unknown pacing accounts, unregistered selected accounts and credential-helper preparation refusals with a typed `terminal_cause` and a safe reason. Resume refusals retain the specific preparation reason.
- **Graph decisions use recorded causes.** Text in a result can no longer impersonate a composite truncation notice or become a planner refusal reason, and loop pauses retain their actual cause across graph advances. Finish paused or truncated graphs before upgrading.
- A bystander in a worktree produces a warning during lane admission, while available writer custody and safe Git state allow the claim (#2877).
- Worktree admission now reports incomplete census evidence when reusing a lane after its previous attempt has finished (#2877).
- Creating a lane worktree and cleaning up a failed creation now preserve competing owner claims (#2877).
- Worktree admission, listing and cleanup share scoped occupancy evidence; retained import fences report uncertainty rather than a live writer (#2877).
- Peer worktree adoption now refuses a held writer lease and reports its recorded holder, while advisory process observations travel with the receipt (#2877).
- Retrying the same worktree reservation no longer fails solely because another process is present or the census is incomplete (#2877).
- A finished lane can release its worktree for a new writer even when a shell remains in that worktree (#2877).
- Claude and Codex lanes can find `provenant` on their `PATH` to submit read-only children and read their output, retaining the correct host configuration and private child run store (#2962).
- Claude writer lanes stop on their fresh-token budget (default 500000); cached reads do not count. After the provider stops, the host attempts to commit uncommitted work for continuation. In-progress merges are preserved, and commit errors remain visible alongside the budget timeout. Codex reports usage only after the turn, so its budget is not enforced. Current lane providers cannot receive the 90% steer warning; the receipt records that limitation. Build-slot waits stay off the wall deadline for at most `lanes.slot_wait_seconds` in total (#2962).
- Route aliases skip members with fresh exhaustion evidence; stale evidence ranks members last without refusing them. Aliases retry another member after a quota limit that produced no work. When every member has fresh exhaustion evidence, the refusal names the members and earliest known reset; exact `--model` launches stay on that model (#2988).
- Read-only lanes can use host GitHub authentication without saving tokens in run files. Command denials name the operation, and the captured output holds the path (#2989).
- Claude lanes retain the requested permission mode when launched from a Claude parent, and malformed results report the provider’s error (#2990).
- `/bin/bash` here-documents work in lanes on macOS (#2989).

### Git and safety

- GC previews reuse the worktree inventory for each repository, reducing repeated Git queries (#2877).
- Repository fact reads, including pull-request base, landing, worktree inventory and target-seed reads, now report when Git output exceeds the configured capture limit (#2877).
- Peer worktrees and session handoff use bounded repository facts and check the pinned base commit against remote-tracking refs (#2877).
- Session handoff warns about bystanders and refuses WIP Git changes while a writer lease is held or writer custody cannot be determined (#2877).
- Landing and worktree GC recognise trusted included Git configuration when identifying a bare repository, while protecting worktree inventory from lane-controlled overrides (#2877).
- `worktree create` now reports success when Git is configured to use relative worktree paths.

### Accounts, quota and routing

- **Account and pacing refusals have distinct codes.** An unknown account and duplicate pacing profiles now identify their causes in the CLI error code, and unverified or stale readiness names a refresh action (#2820).

### Pipelines and graphs

- Review preset explanations match changed paths faster on large branches (#2988).

### Chair, inbox and console

- Tracker filing guidance helps prevent duplicate issues after a create error (#2977).

- Git launchers preserve native executable paths containing non-UTF-8 or shell-special characters.
- Lanes warn and continue when a Fabric MCP configuration path cannot be represented, while keeping isolated Claude settings.
- **MCP argument errors protect caller data.** Unknown object keys are omitted from reported paths while suggestions continue to name known schema fields.
- **MCP input refusals retain their cause.** Typed validation now reports the safe field and reason without echoing the submitted value.
- **Stale account readiness triggers one fresh check.** The launch reports a warning and retries the selected account's availability observation before deciding whether it can proceed.
- Preset worktree discovery recognises linked checkout paths containing quotes and newlines (#2877).
