# Provenant v2.10.0

Released 27 November 2026.

Provenant 2.10.0 adds a durable delivery queue that carries tracker items through CI, review and repair on each `tick`, and makes long-running lanes easier to watch and steer: a provider that goes quiet is reported as `stalled`, and `provenant steer` queues its text for the next turn unless you pass `--now`. Chair hooks now keep to one configurable time budget and a project-scoped digest, and the one breaking change renames the project `capabilities` key to `grants`, which `provenant install` migrates.

## Breaking changes

- `domains.lanes.projects.<project_id>.capabilities` is renamed `domains.lanes.projects.<project_id>.grants`. `provenant install` rewrites `<state>/config.toml` once; there is no alias, so update any other tooling that writes the key. (#4093)

## Behaviour changes

- `provenant install` warns, listing the live attempts that may need draining, when it replaces the shared binary across a live-record format change. This release changes that format, so settle or drain live lanes before installing it. (#3895)
- Writer preambles now give the project's valid `verify.lane` declarations (tier, argv, scope and source) as the verification guidance, and the launch receipt records them; a declared no-build `verify.static_checks` tier is recorded the same way, with the layer, file and key behind each check. Invalid entries warn instead of blocking the launch, and without a usable declaration the resolved formatter and declared pre-commit hooks still apply. A failing static check is reported in the handoff without refusing the push, and `build.prepare` runs once per declaration digest, warning and staying retryable when a lane preparation fails. (#3652, #4069)
- The lane Git wrapper unsets `LEFTHOOK` and warns, then refuses, `--no-verify` and `core.hooksPath` overrides, so a lane's commits and pushes always run the repository's hooks. A Git command whose only remaining option takes a value, such as a bare `-c`, now reaches Git unchanged instead of aborting the wrapper. (#4069)
- The session-start digest names only custody this chair holds in the hook's project. Adoptable items and other projects' rows collapse to one `Unattended: N (M this project)` line pointing at `provenant status --adoptable`; `session.digest.scope = project|all` (default `project`) restores the cross-project view, and the line shows the effective scope and its layer. (#4026)
- Chair hooks keep to one budget derived from `domains.hooks.timeout_secs` (default 10), which replaces the fixed 5, 5 and 10-second timeouts for chair-start, chair-stop and chair-prompt. A hook that reaches 60 per cent of the timeout returns before the host kills it, warns `HOOK_BUDGET_OVERRUN` with the setting source and records the overrun in the state root's `hooks/diagnostics/failures.jsonl`; usage ingest moves off the chair path to a detached incremental worker. `provenant doctor` and `provenant hosts doctor` report the timeout, its source and the overruns of the last 24 hours. (#4028)
- The global rules keep standing rules out of private memory: memory holds one current entry per topic, superseded in place, and a rule the user restates moves into the rules or a skill. They add two review checks (a repair that deletes a stated rule is a contract change; a test pinning a restriction makes the restriction the suspect), scratch-directory hygiene and generic naming of private projects in public trackers. The `deliver` skill names the GraphQL fallback when the GitHub REST quota is exhausted.
- `provenant steer` queues its text for the lane's next turn and leaves a running lane alone by default. `--now` stops the lane and resumes the same provider session with the text, and is refused as `steer_session_unavailable`, leaving the attempt running, when the lane has no retained session. `domains.fabric.steer.delivery = "queued" | "now"` sets the host default (`queued`), and `provenant steer --explain` shows the effective mode and the layer that set it. (#4043)

## Additions

- `gc.attempt_scratch_max` (default `2G`, `0` disables) caps each attempt's scratch tree: `provenant gc` collects an over-cap tree once its attempt is settled, without waiting out `gc.idle`. A tree it cannot measure is kept, live or unsettled attempts stay protected, and GC output shows the cap and its source (`attempt_scratch_max_bytes` and `attempt_scratch_max_source` in JSON). (#3950)
- A durable delivery queue drives tracker items through ordinary graphs, advanced by each `tick` without a resident process. Bounded loops carry an item through CI, review and repair; `previous.<node>` binds the preceding round's publication, so conflict and CI gates stay on the latest delivered head, and a moved head invalidates CI and review evidence. `provenant stop` and `provenant retry` apply queue controls (`--queue-control accept|fix|retry|drop` with `--queue-revision` and `--operation-id`); conflict diagnostics tell operators to merge the base into the branch and keep pushed history. See the [delivery queue spec](../specs/delivery-queue.md). (#3972)
- `run --explain` reports a `node_routes` row for every launchable node, with the effective adapter, model and effort and the source of each (`node field`, `policy`, `pool` or `default`); pool candidates list theirs per value. Account and credential choice stay launch-only. (#4066)
- The `session` skill restores after compaction in three bounded steps: read the hook context, run one cursor-bounded state read (`provenant status --session-stream --cursor <cursor>`), then act on its owners. A resumed chair re-orients without re-reading source or polling a wait. (#4032)
- `provenant telemetry value` reports, for each account with quota readings and a configured plan, the API-equivalent cost per full window and its trend (the change in microdollars), the value multiple against a USD plan price or USD notional, the share left unused at reset and priced coverage; credit accounts add a draw-down rate and days to exhaustion. A figure the readings cannot support, such as an unpriced bucket, an attribution gap, a foreign-currency price without USD notional or a window without usable bounds, is named unavailable with its reason instead of shown as zero. `--since` limits the summary, and `price_source` and `window_source` show where the defaults came from. (#2225)

## Fixes

### CLI and install

- Upgrading past a retired hook action hands its ownership only to that action's declared replacement, so a managed hook you deleted by hand is no longer re-added. Installing without `--hooks on` still registers the `PostToolUse` replacement for Claude's retired `PreToolUse` answer-delivery hook. (#3824)
- `provenant status NAME` finds a graph in another registered project instead of returning `NOT_FOUND`. One match is read through its project with a `CROSS_PROJECT_TARGET_FOUND` note, several matches refuse with `AMBIGUOUS_TARGET` listing them, and reads inside a lane keep their existing scope. (#4073)

### Lanes and settlement

- A graph wait no longer fails on the first error when a remote lane finishes while its home endpoint is unreachable. It treats the unavailable reading as pending, rereads within its budget and settles on the next good reading; a wait that ends pending names its last failed reading, and `status` shows the settled state once an advance succeeds. (#3600)
- A dead attempt whose stored record no longer decodes no longer fences its branch forever. Once writer exclusion and exit evidence prove the owner gone, `reconcile` and `release attempt:ID` keep the raw record under the attempt's `quarantine/`, release the writer lease on the same boot and warn `UNREADABLE_RECORD_RELEASED` with the record path, schema version and error. A live or unobservable holder, or an exit still settling, keeps the fence, and neither command deletes or rewrites the record. (#3829)
- A review placed on a peer no longer shows `unknown` on the launching host while its writer is live: the peer relays its own observed presence with the status result. A peer-owned lane's reclaim hint names the peer's graph target and the host where `reconcile` resolves it, and target refusals no longer print `NOT_FOUND: NOT_FOUND:`. (#3842)
- A provider that stops producing output no longer reads as `running` forever. After `providers.<id>.stall_after_seconds` without output (default 1800, `0` disables; queued time excluded) the lane warns `PROVIDER_STALLED`, `status --json` carries `stalled: true` with the last-event time and `wait` ends with outcome `stalled` (exit code 6) without claiming settlement; `run --explain` shows the threshold and its layer. `providers.<id>.stall_policy` sets what follows: `report` (default) only warns, `steer` queues one steering turn, `retry` stops the provider and moves to the next route within the graph retry budget, and `fail` settles with `provider_stalled`. (#3903)
- A detached, unsandboxed process that outlives its guardian is no longer invisible. `reconcile` names it in `status` as an escaped PID with an `ORPHAN_PROCESS_ATTRIBUTED` warning while the fence holds, and in a settled exit's `unresolved_pids`; such a process is reported and never signalled, while lanes with an OS mark still reap escapees. A launch is rejected if the provider's process identity cannot be recorded first, and hosts without containment warn once per change (`policy.LAUNCH_PROCESS_ATTRIBUTION_NONE`, default `warn`; `off` suppresses). (#4006)
- `provenant upgrade --verify --host <peer>` no longer leaves the smoke read lane on a stale view. A remote reader now reads the peer checkout's own `HEAD` and reviews against its first parent instead of pinning a sender commit the peer never fetched; when Git evidence is unavailable the peer warns and falls back to the sender's pins. The smoke fixture carries a fresh random fact, so a reader cannot pass by reconstructing the answer from the checkout. (#4015, #4043)
- `run smoke` no longer reviews the caller checkout's last commit. Its review node runs after the writer and reads the writer's smoke change against the commit the writer branched from, so a reused branch's history stays out of review; a launch with no writer skips review with a stated reason, and `--set diff_base=BASE` still overrides the base. (#4016)
- A warm slot's Cargo target is no longer shared blindly across toolchains and worktrees, so a pinned build cannot pick up stale workspace-member artifacts. The new `build.target` setting (default `toolchain,worktree`) keys the target by the compiler Cargo selects, `+toolchain` included, and gives each checkout its own workspace members while dependencies stay shared; `shared` keeps one target. `check config` and `config show` report the layer, and `check config` warns when a warm slot's recorded toolchain differs from the checkout's `rust-toolchain.toml`. (#4071)
- A lane whose settlement retries have stopped now says why in `status` and names `provenant reconcile <lane>` and `provenant reconcile --abandon <lane> --reason <text>`, instead of looking pending with no way to clear it. (#4072)

### Git and safety

- Delivery accepts remote names such as `team/upstream` consistently, using the forge resolver's grammar, records local integrations as a local destination and refuses an empty remote name. The run-store upgrade migrates older receipts' empty-string destinations and keeps named remotes. (#3895)
- Repository tooling that clears `GIT_*` before calling Git no longer mistakes a lane checkout for an unregistered worktree. The lane Git shim presents the attempt's private repository as a registered linked worktree, so `git rev-parse --git-dir`, `--git-common-dir` and `git worktree list` all resolve, while lane refs, objects and index stay private to the attempt. (#3905)

### Accounts, quota and routing

- `route resolve` no longer reports a `does not offer` exclusion from an expired snapshot, and it keeps the pinned account's own readiness row. Route selection, resolve, preview and launch now judge offers from one recorded model list and report that list's own age. (#3933)

### Pipelines and graphs

- A findings panel over an implement node that reuses a worktree reviews base..pushed head instead of failing every lens on an empty range. Each writer's base comes from the node's `base`, then the branch upstream, then its merge base with the default branch; `run --explain` names each commit and source, and a panel with no resolvable base refuses the graph before launch. (#4064)
- An inline implement writer whose attempt succeeded, with a `done` handoff and its commit pushed, no longer settles `cause=other_failure`: the graph takes the verified pushed head as commit evidence, so the node succeeds and its dependants unblock. A precondition that really fails is named with its settlement reason, and a writer without a findings contract is not failed for reporting none. (#4065)
- `review-repair` resolves an authored `with.writer` id such as `fix` to its expanded node id (`task--fix`), including inside the repair loop. A continuation that still cannot bind names the expected expanded id and the upstream writers that could satisfy it. (#4066)

### Chair, inbox and console

- The session-start hook prints the active-custody list once and streams custody and lane inventories, offering a continuation for unread rows, so a large history reports progress before the deadline. When its output reaches the cap the digest and excerpt shrink first, so `## Intent` (up to 3 KiB) and the new `## Now` section (up to 1 KiB) survive; a fresh checkpoint with nothing to act on drops the freshness boilerplate. (#4027, #4072)
- Compaction summaries no longer relist finished work as next steps or replay saved rulings. The PreCompact instruction marks work done since the last checkpoint, prefers the verbatim tail where they disagree, lists waits in flight, cites rulings from checkpoint Intent, drops items untouched for 24 hours unless they are owner asks, and asks for summaries under 12k characters. (#4030)
- A native subagent no longer receives the chair's checkpoint, standing grants or account-switch handoff on `SessionStart`: a non-empty `agent_id` or agent transcript path makes the chair hooks abstain. `agent_type` alone does not count, because top-level `--agent` sessions carry it too. (#4031)
