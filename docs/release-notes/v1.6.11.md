# Provenant v1.6.11

Released 7 November 2026.

This release moves lane and graph work to a unified run and template interface, and improves recovery, review and status reporting. Before upgrading, finish pending graphs, drain live lanes and review the breaking changes below.

## Breaking changes

### CLI and install

- Start graph work with `run [BRIEF] --use TEMPLATE` or `run --file DOCUMENT`; inspect layered templates with `templates` and apply live patches with `edit`. The default help shows the ten graph verbs. Removed command routes and `fabric_graph` have no aliases (#2867).
- CLI and MCP share document submission, patch admission, template inspection and grouped attempt statistics. `output --trace` reads the retained graph event timeline (#2867).
- **Removed the unused brief read-root warning setting.** Remove `domains.run.brief_read_root_warnings` and its aliases from host and project configuration.

### Lanes and settlement

- Use `status [ID]` instead of `lanes` or `fabric graph status`, `stop ID` instead of `cancel`, and `retry ID` instead of `resume`. Status rows share one schema for graphs, nodes and attempts, and output and steering accept each ID kind (#2867).
- `stop ID` stops a node and its attached subtree, leaving detached children running. `retry ID --node N [--brief TEXT]` redoes a settled leaf with a fresh attempt identity, retains earlier attempt evidence and budget usage, and journals the brief as a graph patch. `retry` also recovers graphs with `--extend` and continues attempts (#2867).
- **Remove `[domains.guard]` from `config.toml`.** Shell commands no longer pass through a command-rule table. Writer lanes approve provider tools and can execute programs created in their checkout; filesystem confinement, credentials, object verification and host authority gates remain enforced (#2964).

### Pipelines and graphs

- **Finish pending graphs and drain live lanes with the previous release before upgrading.** The new release refuses old pending state even when the upgrade used `--yes`; port user and repository presets to templates by hand. Drain checks refuse new admissions while inspection, cancellation and accepted-receipt recovery remain available.
- **Automatic preset rules and pipeline experiments are removed.** Remove `domains.fabric.pipelines.experiment` from configuration; stale keys produce a warning. Historical child stores remain on disk, but their records drop out of statistics.
- **Graph state and presets change.** Finish or cancel pending graphs and drain live lanes before upgrading every host. Port user presets by hand; retain old child-store directories for telemetry ingestion before garbage collection decides what to remove. See the [upgrade runbook](../runbooks/install.md#bootstrap-and-upgrade). (#2867)

- **Retry a graph node and its dependants.** `provenant retry GRAPH --node NAME` redoes the selected node and downstream work, retaining prior attempts and recording the reset in the graph journal. Writer-child worktrees are reused during crash recovery.
- Use `run`, `status`, `output`, `steer`, `stop`, `retry`, `edit`, `templates`, `land`, `quota` and `trace`; `dispatch`, `review`, `lanes`, `resume`, `cancel`, `preset`, `fabric graph` and `fabric_graph` are removed. Start template work with `run --use` and find advanced commands with `help --all` (#2867).
- **`dispatch`, `review`, `lanes`, `resume`, `cancel` and `preset` are removed.** Use `run`, `run --use review`, `status`, `retry`, `stop` and `templates` respectively. Replace `run --preset NAME --prompt-file FILE` with `run --use NAME --file FILE`; port user presets to templates by hand (#2867).
- **`fabric graph` and MCP `fabric_graph` are removed.** Use `run`, `status`, `output --trace`, `edit`, `retry` and `stop`, or MCP `fabric_run` with a document. `PRESET_INCOMPATIBLE` is removed; use template admission diagnostics and upgrade every host together after draining live work. Unreadable checkpoints are preserved and reported through `retire_unreadable` (#2867).
- **Configuration discovery is compact.** Use `config schema --all` and the generated advanced reference for host policy and tuning outside the documented surface (#2867).
- **Start lanes with `run` and templates.** `dispatch`, MCP `submit` and bundled presets have been removed. Use `run --mode worktree-write --worktree PATH` for an existing writer, or `run --branch NAME --base REF` for a new branch. Retained non-graph lanes remain readable through `status` and `output`; stop and retry require a graph. Drain live lanes and pending graphs before upgrading, and port user presets to templates by hand (#2867).
- **Automatic retries now belong to the graph.** Drain active lanes before upgrading. Runs no longer launch policy successors or use separate child stores; existing child-store directories are ignored. Lane route failover continues through the graph (#2869).

## Behaviour changes

- `run --model ADAPTER/ID` warns and tries an uncatalogued model, letting the provider report whether it is available (#2964).
- `run` accepts lane documents with parameter and `over` overrides, and `edit` can patch a live graph from its lane. `stats` reports attempts after graph checkpoint collection (#2867).
- `run` starts a graph for plain tasks, templates and presets. Inside a lane, `run` and `fabric_run` add children to the parent's graph; `--use` selects a template (#2867).
- Child runs can opt out of parent and graph cancellation with `run --detached`. Lanes can stop their own subtrees. A parent that finishes closes its live attached children; work emitted in its final planner patch remains scheduled.
- Waiting parents release writer admission and graph concurrency so children can drain within the configured limits.
- Integration into a checked-out parent branch now waits for explicit pickup, preserving the parent’s index and edits. Commit the parent’s work and merge the sealed child commit, or switch the parent checkout away from the target branch and retry delivery.
- Review templates now select framing, verification and synthesis from the resolved review shape. A panel of one runs as one review attempt (#2867).

## Additions

- Repair blocking review findings in graph delivery and batch templates, with
  qualified evidence, raising-lens delta review, at most three repair cycles
  and read-only principal scoping for recurring or design defects (#2843).
- Bundle review panels, research and exploration swarms, batch and delivery as
  templates. Batch submissions support a route per named slice and create a
  missing local integration branch automatically (#2867).

## Fixes

### Lanes and settlement

- Graph writer retries retain uncommitted predecessor work and list its paths in the continuation brief (#2786).
- Graph launches honour the caller's wait limit when a provider update is busy (#2395).
- Dirty-writer refusals before launch are retained for status and operation replay, with one path-free notice to the bound chair when enabled (#2823).
- Recovery retains a slot-root custody fence until its carried attempt record is confirmed durable, and reports cutover storage errors while checking other work (#2823).
- In-lane `run` recognises the parent attempt marker even when other lane markers are absent. Repeating the same child brief creates a separate child rather than replaying the first launch.
- Session hooks collect attempt inventory through `status` and preserve cursor ordering when continuing a partial page.
- Retrying a proven pre-launch refusal preserves pending sibling work. Accepted or uncertain launches retain their custody fence.
- Status retains bounded provider errors, result locations and graph advance failures.
- Peer-hosted agents can launch children, edit their graph and yield while waiting. Status exposes the peer subtree, graph output follows its attempts, and stopping the origin node stops its attached descendants.
- Wake graph execution after live child admission, load user and repository
  templates for child requests, and cancel failed parents' attached children.
  Detached children no longer hold up the parent's dependants (#2867).
- Writer children integrate into their parent branch while preserving the parent's staged and unstaged edits. Child waits yield the parent's graph slot and clear it when the wait returns (#2867).
- Waiting supervisors wake less often and spend less work recording process ancestry and CPU usage, while retaining descendant custody and cleanup checks (#2886).
- Writer preparation errors retain the failing Git step and bounded, redacted diagnostics when Git writes excessive error output.

### Git and safety

- `run --branch` now fetches a remote-only branch and starts its writer at the remote tip.
- Publishing writers can use a token without a host `gh` configuration directory. Symlinked host configuration no longer prevents launch.

### Accounts, quota and routing

- Route previews show provider refusals, and override listings hide expired entries unless `--all` is given.
- `stop` reports a settled attempt when settlement finishes during recovery.

### Pipelines and graphs

- Review panels use their resolved lens tiers, and `run --explain` shows those routes (#2700).
- Review templates report malformed findings, invalid verdicts and contradictory PASS replies as contract failures. Verification and synthesis preserve the findings and their evidence even when a brief is overridden (#2700).
- Review panels continue after a quota-limited lens or verifier when another member succeeds. Missing coverage stays partial through synthesis and cannot become a clean PASS. Shapes without synthesis include verifier verdicts (#2700).
- Graph status and output show retained failure causes and their recovery guidance, including uncertain launch handoffs. Launch failures show the owner’s typed code while retaining the graph retry disposition (#2820).
- A refused writer branch names an existing clean linked checkout in a shell-safe `--worktree` remedy (#2820).
- Repairs that expand the changed paths or report increased risk now trigger a fresh review panel before acceptance (#2843).
- Review repairs re-plan the full panel when their diff touches protected risk paths, including paths already reviewed. Findings from a failed replanned panel feed the remaining repair cycles; principal redesign notifies the owner through the host and waits for a decision when scope changes or a one-way door is proposed (#2843).
- Child waits from `run` and `fabric_run` yield the parent graph slot and retain admission receipts when observation times out. Relay children can launch review panels through the host resolver. Cloud nodes submit, recover, observe and cancel their remote jobs through the graph owner (#2867).
- Unreadable graph checkpoints now report their specific cause instead of a generic corrupt-state error (#2867).
- Child runs retain the template compiler’s parameter diagnostic when a setting is invalid.
- Accepted graph attempts remain observable after a host alias is renamed, using the stored host identity.
- Repeating a task brief starts new work. Reviews and delivery runs reuse results only for equal submissions at the same working directory and HEAD; explicit operation IDs replay earlier submissions (#2867).
- Lost child receipts can be recovered after a graph settles. Child receipts explain that attached children are cancelled when their parent exits (#2867).
- Graph traces identify nodes and attempts, timestamp observations and explain slot waits and failures without retaining briefs. Graph status prioritises current failures and the next command; statistics include cache share, queue time and outcomes by node, tier or template (#2867).
- Any agent can return a final graph patch. Planner patches retain the submission's template layers and review resolvers, admit delivery composites, and report actionable template and patch refusals. Task swarms include their named item in each brief (#2867).
- Local graph attempt status retains the result path, transcript location and staleness observation shown by ordinary attempt status. Remote attempt paths remain redacted (#2869).
- New writer branches can request integration or push delivery without being refused because their worktree has not yet been created (#2869).
- Lane edits stay within their own subtree; planners and graph owners can still edit across the graph. Landing requires an approving review gate after a gate replacement.
- Graph calls retain refusal codes and details, and CLI child replies use the same JSON as MCP. Status shows when a parent is waiting to reclaim admission after its children finish.
- Graph `run` retains peer placement with `--host` and attempt settings, plus
  `--model`, `--effort`, `--account` and advanced `--operation-id` controls.
  Set `attempt.build_heavy`, `attempt.confidential` and `attempt.provider_timeout`
  with `--set`; start delivery with `--use deliver`.
- `steer` accepts a graph or `graph/node` selector and refuses ambiguous live attempts. Graph statistics include launch refusals without attempt references.

### Telemetry and providers

- Lane logs now redact recognised credentials following escaped characters in provider output (#3008).
