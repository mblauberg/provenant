# Provenant v1.7.0

Released 10 November 2026.

Writers that stop early now continue or restart from their handoff, review repair judges findings against the code, and `retrospect` compares local histories across experiments. This release removes `provenant fabric task` and `chair viewer` and migrates the Fabric store one way, so read Breaking changes before upgrading.

## Breaking changes

- An in-flight receipt with a downgrade needs a re-save with the new binary to record current factors, chair authority and the PR's actual merge-base-to-head paths, including both names of renames. Remove `risk.changed_paths` from save requests; fetch the PR base and head locally when paths have not yet been recorded. Receipts without a downgrade continue to load and review offline (#3081).
- Review boundary floors follow effective configuration, so owners can lower or remove bundled defaults. Credential delivery and Git custody helpers receive their boundary floors by default; non-PR downgrades are refused because they have no diffable commits, while ordinary tier selection is unchanged (#3081).
- `provenant chair viewer` and its seen, snooze, dismiss and summary-baseline records are removed; nothing read them, and the human inbox and `provenant-console` are unchanged. Opening a Fabric store upgrades it and drops any stored viewer rows, after which older releases refuse the store as newer (#3082).
- `provenant fabric task`, the `fabric_task` MCP tool and the `--task` link on `fabric mail send` are removed. Track work in GitHub issues and graph nodes; mail, events, claims and landing are unchanged. Opening a Fabric store upgrades it and drops the task board, its events and receipts and any message task links, after which older releases refuse the store as newer. Until every peer host is upgraded, an older peer's task requests are refused and its stored task events cannot be read (#3082).
- **Opening a Fabric store with this release applies two one-way migrations, one for viewer state and one for the task board.** After any host opens its store, an older release refuses it as newer and the store cannot be downgraded. Upgrade every host together, and remove scripts that call `fabric task`, the `fabric_task` tool or `chair viewer` (#3082).

## Behaviour changes

- Upgrades only block on running work when a release breaks state readability. Routine releases compare a compiled-in state format version during staged preflight, report in-flight graphs and lanes as warnings and proceed without requiring `--yes` or a blanket host drain (#3091).
- Stopped writers restart from their handoff on the same worktree, keeping commits and uncommitted edits, on another eligible pool route, unless model policy selects session resume. Stops needing an owner decision or missing capability return to the chair without launching more work. A writer's stop is saved together with its restart, so `run --wait` and graph status never report the stopped attempt as final; a restart the host refuses pauses the graph for the chair with the reason. (#3074)
- `provenant land` reports and receipts no longer carry head-move shadow classifications, which nothing enforced; exact-head landing gates are unchanged. (#3082)
- Review repair judges findings against the code and groups confirmed findings by cause before a writer starts. Writers can dispute an item or ask for design judgement; shared flaws and a third review round go to the principal, who can recommend further repair. Typed specification concerns reach the chair. (#3072)
- Reviewers no longer ask for guards against unobserved risks outside the hard boundaries, and give every finding a trigger naming the steps that reach it. A chair running review by hand may overrule a changes verdict after checking the code, posting the reason on the pull request. (#3072)
- Issue specs and the seeded feature form replace `Must not change` with an optional `Boundaries` section, each line citing a recorded hard boundary or giving its reason. Spec rules whose reason cites no event are marked as defaults open to change, and decision records say what would overturn them where a checkable fact exists. (#3073)

## Additions

- `retrospect` can compare local Claude, Codex and lane histories across experiments, release eras, captured instructions and work mix, with blind reasoning labels, usage and attributed outcome comparisons, joint overlap checks and explicit uncertainty. Actionable findings become issues even when no regression can be attributed (#3064).
- `telemetry stats` reports available release and instruction context, reply triggers, CLI ergonomics and accepted-outcome coverage. Missing observations remain unknown; reasoning tokens and output-token proxies are reported separately (#3065).
- `provenant telemetry stats` reports success rate, cost per success and time per success by route, access mode and effort, with sample sizes and a warning for comparisons outside hash-assigned pools. (#3074)

## Fixes

### Lanes and settlement

- Read-only review lenses can publish progress in their candidate's private state: OpenCode permits confined shell updates, and Claude and Agy include that directory in their native workspace permissions (#3068). Lanes with a private-state grant receive the progress-file instruction; updates are best effort when a provider refuses them.
- Status and lane listing check custody and supervisor liveness in each displayed attempt's own worktree slot instead of inventorying every retained worktree reservation once per row (#3079).
- A writer launch refuses a stored worktree path that no longer resolves to itself, such as a checkout moved behind a symlink after submission, so its custody cannot sit where status does not look (#3079).
- Agy lanes that report a refused action with a successful empty result now settle as `permission_denied`, naming the action. Reported denials that may have been recovered are recorded as notes; Claude does not identify whether a denial ended the work. Silent denials, such as an empty glob, cannot be detected (#3079).
- Review results retain findings when the complete result fits in the tail window; review base refs resolve against the subject’s merge base, and empty ranges are refused before lenses start. Status waits retry a busy graph store, and landing exclusions explain the cause and next step (#3079).
- Writers that declare `stopped_early` now continue automatically on the same worktree, including graph nodes. Each continuation starts fresh with the handoff and original brief by default; `lane.resume_continuations` opts a model into retained-session resume. The default allows two continuations per run; model and project policy can override it or disable it with zero (#3086).
- Landing cleanup no longer keeps a merged worktree solely because an unrelated system process cannot be inspected or a transient descriptor observation changes. Live occupants and persistent gaps for possible writers still keep the worktree (#3092).
- Graph attempts refused before provider launch retain their typed preparation cause, and exhausted routes explain the failure. Route fallback still requires local preparation and released custody evidence (#3102).
- Failed Git worktree mutations report the operation and whether Git named a lock failure, without exposing Git output or labelling an operational error as graph input (#3102).
- A lane no longer settles as `provider protocol is malformed` and loses its answer because of content inside a provider frame that the adapter ignores. Provider frames are foreign content and are now decoded with plain JSON rules, bounded only by the 1 MiB line limit, for Claude, Codex, Cursor, Agy and OpenCode. This covers an integer wider than 64 bits (such as a tool schema bound of `18446744073709552000`), a repeated member, and nesting deeper than 64 levels; the final result decides the outcome. A value in a field Provenant reads, such as a usage count, that it cannot hold still fails closed (#3111).
- A lane that ends a turn with a valid handoff and then only replies to a late background notification now settles with that handoff instead of `review_required` with `handoff_missing` (#3115). Claude turns now start on their own line in the result, and settlement reads the handoff that ended a turn: a later turn's own fence replaces it, and later tool work without one leaves no handoff. A fence quoted mid-turn is still never final. Review verdicts keep their final-position rule.

### Git and safety

- A writer launched straight after `git worktree add` is no longer refused when a checkout hook's short-lived process still has its working directory in the new worktree. Launch re-checks within its existing wait budget; a process still present after it refuses and is named as before (#3110).

### Accounts, quota and routing

- A Codex lane that ends on the provider's usage-limit message now settles `quota_limited` instead of a generic partial failure, and its reason names the account and the reset time the provider gave (#3109).
- That usage limit holds every model on the account until the reset (or a fresh reading with headroom), so pools and graph nodes move to an account or member with capacity and `provenant quota` shows the account `exhausted` with the reset (#3109).
- `provenant quota` reports `credit_only` only when credits are spendable; a balance the provider marks `hasCredits: false` now reads `exhausted` (#3109).

### Pipelines and graphs

- Reviews preserve original finding severity, reject contradictory lens PASS verdicts before triage, and retain rejected boundary and data-loss findings for repair and chair judgement unless falsified with evidence (#3072).
