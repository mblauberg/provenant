# v1.2.0

This release makes lanes self-managing (epic #1829):
- A writer dispatch creates, owns and prunes its own worktree.
- `lanes --wait` and landing replace chair polling.
- Garbage collection runs on settlement and landing, with a scheduled backstop.
- Closed runs' event logs expire under `retention.logs_days`.

It also:
- records Claude lane token usage, including cache counts;
- serialises concurrent Claude OAuth refreshes;
- links each attempt to its provider transcript;
- reports quota use by account across projects.

## Stability

There is no stability promise. Commands, flags, `--json` output, `config.toml`
keys, the state layout and Fabric MCP tool names and schemas can change in any
release, with no deprecation period or compatibility shims. Each release's notes
list its breaking changes. Upgrade every host together, since peers on different
versions are not supported.

## Behaviour changes

- Admission now gives each lane a class: `writer` for a `worktree-write` lane,
  `read_only` for every other. Startup spacing is measured per class. Writers
  keep the 20 s gap after the last writer start. Read-only lanes wait 2 s after
  the last read-only start and no longer queue behind writers, so eight
  read-only lanes start in about 14 s instead of 2 min 20 s. The memory (5 %)
  and disk (500 MiB) floors still refuse both classes.
- The per-project active lane cap is 32, up from 16. The host cap stays at 64.
- A batch with no `worktree-write` lane now defaults to 16 lanes at once, from
  the new `lanes.max_concurrency_read_only` knob (1 to 16, default 16; the
  `economy` preset sets 8). Batches with a writer keep the `lanes.max_concurrency`
  default of 8. A `lanes.max_concurrency` you set yourself also caps the
  read-only default unless you set the read-only knob too. An explicit
  `--concurrency` or Fabric `concurrency` still wins, and its upper bound is now
  16. A value above the batch's task count is accepted by the CLI, a local
  Fabric call and a peer alike; before, a peer refused it while the CLI did not.
- `lanes` now shows `lane_class` and `waiting_for` for queued and starting
  lanes, and uses the wait as their reason: launch not yet handed to a
  guardian, run concurrency, the class's remaining startup spacing, or host
  capacity. A peer's lanes, from `lanes --host` or a placed run, show the same
  fields; an older peer shows neither.
- The host admission ledger (`admission.sqlite3`) moves to schema version 2 and
  upgrades in place on first use. Existing leases and tickets with no class
  count as writers, and any old wall-time start, whatever its age, is carried
  across for each class as a start at the upgrade, so the one-time upgrade holds
  each class for one spacing; a ledger that recorded no start holds neither. The wall clock is not read. The upgrade is refused if the host's clock or boot
  identity cannot be read. A binary from before this release refuses the upgraded ledger,
  so upgrade every host together.
- Startup spacing no longer depends on the wall clock. It is measured on the
  host's monotonic clock since boot, which every process on the host shares and
  no clock change can move, and each class's last start is kept with the boot
  it was read in. Within one boot, no two lanes of a class start less than one
  spacing apart, whatever the wall clock does, including a step back then
  forward or a step forward alone. A reboot resets spacing, so the first lane
  of each class after a boot starts at once (the one-time version 1 upgrade
  above holds each class for one spacing instead). If the host's clock or boot
  identity cannot be read, the lane's start is refused with `startup spacing
  cannot be judged: host clock or boot identity unreadable` instead of falling
  back to the wall clock. Spacing is enforced at admission, not at provider
  spawn, so a guardian suspended between the two can spawn alongside a later
  lane.
- Agy read-only lanes can run system commands such as `git log -p` within
  their existing confinement boundary. Provider tool denials name the action
  in the terminal reason; a recovered answer keeps the lane successful.
- Like read-only Codex lanes, read-only Agy lanes can run system programs with
  the lane's existing network access, so read roots must not hold anything the
  lane may not see.
- `provenant install --hooks on` now also registers Claude Code `WorktreeCreate`
  and `WorktreeRemove` hooks. Worktrees Claude creates for native agents are
  made by `provenant worktree create` on the branch `claude/<name>`, so they are
  registered with an owner from the start, and removal goes through
  `provenant worktree remove`. A name outside letters, digits, `.`, `_` and `-`,
  or a worktree the owner refuses to remove (dirty, live writer, primary or not
  listed for the project), fails the hook and leaves the worktree in place;
  the hooks never force. Without `--hooks on` Claude keeps creating its own
  worktrees (#1845).
`output` accepts peer hosts and two-part attempt references, and clamps local
tails to 500 lines. `route resolve` accepts a positional route or model name.
Session checkpoints can now hold up to 256 KiB of UTF-8 Markdown.
`lanes --wait` now counts only lanes that were unsettled when the wait started
or have settled since (or since `--since`), so a settled older attempt no longer
ends a wait on a newer one. An attempt named by its exact ID still counts
whenever it settled, and a wait on runs whose lanes all settled earlier is
refused with the count. `lanes` takes `--session LABEL`, `--host` works with
`--wait`, and `lanes --watch` prints one line per state change for a background
shell or monitor. The wait starts at command entry, so a lane that settles while a
peer is unreachable still counts. One poll shares a single deadline across
all its peer reads, each capped by what the earlier ones left, and none after
the first starts at or after it. A read's SSH termination and reap come out of
the time it has left, so a hung `ssh` is gone by the deadline; only the first
read of `--wait 0` keeps a one-second minimum. A peer wait keeps every running
lane tracked until it settles, even after newer dispatches push it off the
peer's newest 100, and `--since` selects by settlement time rather than queue
order, scanning up to 1000 lanes.

`pr land NUMBER --head SHA` waits for CI, merges at that head through the
existing merge path, then fetches, fast-forwards a clean local base, removes
the merged branch's worktree (after its declared build output) and deletes the
branch, only while it is still at the merged head and not checked out, rebased or
bisected in any worktree. A checkout, rebase or bisect that starts between
that check and the deletion is not caught. Each follow-up step refuses and
reports rather than forcing, and cleanup only touches a local branch whose tip is exactly the head
the pull request merged: a fork's head leaves a same-named local branch alone,
so does a branch recreated or advanced to another tip, and a worktree holding
commits the base lacks is kept along with its branch. Removal refuses if the
worktree's HEAD moves after that check, and the branch deletion keeps a branch
that moves off the merged head after it. `pr open --from-attempt` builds the pull
request body from the attempt's receipts into the repository template, and
`pr status` prints one line per pull request.

Session checkpoints now keep the last 8 saves as numbered revisions, each with
its parent and content hash. `workflow session show --rev N`, `show
--revisions` and `workflow session diff N` read them as plain text.
`[retention] session_revisions` (1 to 64) sets the count, for `workflow session
handoff` saves as well as `session save`. `session diff` now shows a change that
is only a final newline, with a `\ No newline at end of file` note.
GC can reclaim idle Git-ignored declared output from linked worktrees without
ending a lane. Nested repositories protect their containing output directory.
Explicit worktree removal allows that declared output and names
undeclared ignored blockers such as `.env`. Projects may opt into foreign
worktree collection with `gc.projects.<id>.foreign_worktrees = "merged-clean"`.

Writer admission tries a five-second pressure collection before refusing low
disk, then rechecks all output volumes. Pressure sweeps skip network fetches
and worktree deletion, honour `gc.schedule=false` and limit writer-admission
collection to the launching project. Pressure still prunes declared idle output, with a one-day floor below the
free-space floor. Scheduled collection now runs daily.
Manual pressure collection reports why it has nothing to collect, including
when `gc.schedule=false` disables it.

`retention.logs_days` defaults to 30. Large stdout/stderr captures of closed
runs, including child stores, expire with a 64 KiB tail retained. Disk reports
measure captures separately as `attempt_logs`.
Capture rows compact by class so disk reports remain bounded across many runs.

Scheduled GC excludes stale, transient and non-Git project roots.
`gc.data.unobserved_projects` remains an array of paths; `skipped_transient`
reports excluded transient common directories. New transient invocation roots
no longer create persistent project registrations.

Large declared output no longer exhausts the idleness budget for explicit or
foreign removal. Foreign output age uses directory-entry mtimes.

Queued or pending submitted writers retain managed trees under foreign GC.

Foreign removal holds writer exclusion even when no state existed and clears
its temporary state after removal or refusal.
GC refuses bare-backed linked checkouts as primary collection roots.

Stderr output remains readable after retention, with truncation reported.
- Every lane now defaults to open network access across all adapters and modes,
  allowing read-only lanes to run tools such as `gh` or fetch documentation
  without requiring `--network on`. Passing `--network off` still restricts a
  lane to its provider endpoints, or to local network access when the Postgres
  capability is requested.
OpenCode free-tier limit events reporting `retryAfterMs` (available from
OpenCode 2.1.2) now cool the `opencode-free` pool until the stated reset time
instead of falling back to an uncalibrated default period. After the reset
passes, admission restores the free pool across models. Stated retry timings
are clamped to at most 24 hours, and missing, negative, zero or non-numeric
values retain the existing fallback cooldown.
Intermediate event log entries from the run-store database now expire under
`retention.logs_days` (default 30) once all sibling attempts in a run are
terminal. The terminal attempt records, result artifacts, exit evidence,
digests, bounded capture tails and child-store databases survive. Each attempt's
newest event also survives so unacknowledged settlements remain visible to lane
cursors. GC reports the number of expired event rows in previews and applied
sweeps, including child stores, as `provider_state.expired_events` in JSON.

## Additions

Writer lanes using an Opus route now print a one-line advisory suggesting a
cheaper route in the same tier. Dispatch continues normally. Set
`suppress_opus_writer_warning = true` under `[domains.routing]` in `config.toml`
to silence it.
- Each attempt now points at its provider transcript. `provenant lanes --json`
  gains a `transcript` object (`adapter`, `session` and, when the retained
  provider state holds the file, its `path`), and telemetry attempt records
  carry the adapter and session. `provenant output <attempt> --part transcript
  --tail N` reads the redacted, bounded tail in place. Provenant stores a
  pointer, never a copy; retention stays with the provider.
- The Claude Code session hooks now report and keep lane and pull request
  state. A new `hook claude session-start` handler (SessionStart on startup,
  resume and clear), and the existing `compact` handler, print a bounded
  digest of this project's in-flight lanes, the lanes settled since the chair
  last saved the checkpoint, and `pr status` for the pull requests the chair
  named in the checkpoint (`PR #N`). The digest is read-only. A section that
  cannot be read is named as unavailable rather than shown empty (#1843).
- `pre-compact` now saves lane, PR and worktree state to `autosave.md`, a file
  beside the session checkpoint, and a new `hook claude stop` handler refreshes
  it when the state has been quiet for ten minutes. Neither writes the chair's
  `checkpoint.md`, so the chair's text and modification time are untouched.
  When only `autosave.md` exists it is reported as such, so the chair still
  saves notes and authority references. Lane sessions only report (#1844).
- Rerun `provenant install --hooks on` to register the new handlers.
Writer dispatch can create and own its worktree with `--worktree-branch` and
deliver with `--deliver none|push|integrate:BRANCH|pr`. Graph nodes share these
modes and a graph can open one integration PR. `lane deliver` picks up a
settled writer with clean-tree and exact-head checks. Resume starts fresh with
retained context when continuation is unavailable, unless `--no-fallback` is
set. Attempts recorded before #1855 have no launch evidence of running under an
owned tree, so continuation resumes them in place (fail open). Native linked
worktrees can be adopted, and graph scratch is excluded
locally through Git's info/exclude. Owned lane cleanup retains unsafe or
unmerged work and records why.
`provenant quota usage` shows the last seven days of recorded use across
projects, grouped by account. Use `--days` to change the window and `--adapter`
to select a provider. Lane rows show recorded token categories and missing
measurements for registered projects. Transient workspace lane attempts are
excluded. Chair rows show distinct sessions only, since chair token usage
is not recorded. These counts are not provider quota percentages.

Claude chair SessionStart hooks now record the serving registered account,
including when no account-switch handoff is pending. Repeated starts for the
same session count once per account and project in the selected window.
Chair observations use the existing bounded, rotated telemetry log. Historical
chair tokens are not recovered and transcripts are not read.

Chair observations store the serving account key and session ID. Project IDs
are recorded only when `usage.project_attribution` is enabled. Otherwise, or
when an existing project identity is unavailable, the report shows an unknown
project. Attribution never registers projects, and attribution failures do not
prevent consuming an account-switch handoff.
- The `tanstack` library skill now covers Form, Store, Pacer, Hotkeys, Charts,
  Devtools, DB and Router file routes, as well as Query, Router, Table and
  Virtual. It sends agents to version-matched API detail first: read-only
  TanStack Intent `list`/`load` and the pinned TanStack CLI doc commands, run
  with telemetry disabled. It forbids Intent install and hooks and CLI
  scaffolding.

## Fixes

Lane settlement now collects its declared ignored output and Cargo cache even
when delivery pickup retains the worktree. Settlement and landing collection
share GC's existing lock, with the daily sweep as a backstop. Final worktree
removal honours regenerable and keep settings when output is recreated after
collection, so regenerable build files no longer strand merged worktrees.
Claude lane attempts now record input, output, cache read and cache write token
counts from the provider's final result event. Settled Claude attempts with no
provider usage record why usage is absent instead of leaving a bare missing
value.
A dispatch whose confinement plan cannot be built now reports that confinement
error instead of a disclosure denial.
A worktree-write dispatch that passes a `--write-root` equal to, or containing,
its `--worktree` is now refused up front. The error names the flag and says
that worktree-write already grants the worktree.
- Claude Code session hooks now repeat a non-default `--state-dir` in every
  command they print: the `Save:` line, the digest heading, the bounded-output marker, the unread
  `pr status` hint and the `workflow session show` pointer. Following a hint
  saves to, or reads from, the store the hook used and never replaces a
  checkpoint in the default store. A directory that cannot be shown safely
  gives a plain note instead of a command (#1829).
- A damaged or unreadable `autosave.md` no longer hides a readable chair
  checkpoint at session start. The two files are read independently, and the
  hook adds one `Autosave unavailable` diagnostic line instead (#1829).
- Read-only Claude lanes can read every `--read-root`, including roots outside
  their working directory. Each such root is now passed to Claude as an added
  directory, so a review briefed with a diff file outside the worktree no
  longer ends without a verdict after Claude denies the read (#1862).
- Codex resumes copy retained session directories into the new attempt without
  carrying over indexes that point to the previous attempt's rollout. This
  prevents resume from trying to read session files outside its sandbox (#1790).
- Session hooks now recognise pull request references in text containing Unicode.
- Worktree removal hooks now report path resolution errors instead of treating them as already removed.
- A `worktree-write` dispatch is no longer refused with "compiled profile
  exceeds its byte bound" once a worktree's lane build cache passes 100,000
  entries. The cache census now allows 500,000 entries and keeps the
  hard-link check. Entry, depth and grant-count overflows now name their
  family and path instead of reporting the profile byte bound.
- Writer lanes get `PROVENANT_LANE_CARGO_LINT_TARGET`, a `target-lint/`
  directory in their Cargo lane cache. Lint-only runs (`cargo check`,
  `cargo clippy`) can set it as both `CARGO_TARGET_DIR` and
  `CARGO_BUILD_BUILD_DIR`, so they stop waiting on the build-directory lock that
  test and build runs hold. The directory is removed with the lane cache.
  Read-only lanes are unchanged.
- The orchestrate skill's Fabric brief template now tells writer lanes to batch
  targeted tests into one cargo invocation, to lint in the lint target, and to
  keep incremental builds on despite the sandbox's hard-link warning (#1853).
- Resume explicit unowned and adopted worktrees in place, preserving edits.
  Launch-time ownership evidence keeps previously owned lane trees fenced
  after pruning, reassignment or owner removal. Attempts recorded before
  #1855 have no launch evidence of running under an owned tree, so continuation
  resumes them in place (fail open).
- State that prior history is unavailable when resume needs a replacement
  worktree, avoiding unrelated primary-checkout commits in the fallback prompt.
- Refuse protected direct-push targets before admission for concise delivery,
  legacy flags and manifests. PRs may still target protected base branches.
- Recreate deleted graph publication refs on retry when the sealed marker
  matches the same head. Conflicting markers and refs still refuse.
- Preserve accepted dispatch replay when later repository state protects the
  publication branch; new admission and actual delivery still check protection.
OpenCode lanes now launch when the project or an ancestor contains `.agents`,
`.claude` or `.codex` directories. Discovery stays literal and does not grant
reads of configuration contents outside existing read roots. Symlinks and
replaced held parents remain refused. Discovery anchor refusals now name the
path and validation stage.

Provider version-probe refusals now report termination, timeout and stdout
truncation details, or identify empty output, without including captured
contents. The four-second timeout and 128-byte stdout limit are unchanged.
OpenCode runs that emit their final text and exit cleanly now succeed even
when OpenCode omits the closing `step_finish` event. Error events, signals,
non-zero exits and timeouts still prevent success.
OpenCode lanes use the host-selected Git for repository discovery in read-only and writer modes, bypassing Apple's system shim. Read-only lanes permit execution of only OpenCode and the selected Git binary.
Peer dispatch accepts prompts over 64 KiB within the launch and encoded peer
frame limits. Large argv prompts are sealed on the peer, and rerunning with
the same operation ID recovers the lane's outcome. Requests whose encoded
frame exceeds 1 MiB are refused before submission with a size error.
Peer `lanes --wait` and `lanes --watch` now report the last transient host read failure when no later read succeeds before the deadline.
- Quota reports and coverage readings count registered accounts only, omitting
  unregistered cache records and unsupported provider source rows from the
  total. Non-retaining adapters with no registered accounts drop stale records on
  tick, legacy-keyed duplicate agy records are dropped on tick when their
  fingerprint matches a registered account, and empty orphan quota directories
  are removed on drop (#1810).
Writer launch refusals on macOS now name the hard-linked file and explain how
to retry after inspecting and removing disposable build output. The existing
confinement check still applies to ignored files.
Reboot recovery treats unavailable locks and unreadable or mismatched records
as unproven custody, so cancellation reports an unobservable attempt, with the
cause, instead of failing with a recovery error. Attempts that already have a
terminal outcome complete staging cleanup and verified settlement after a reboot
before their reservation is released.
Provider-state garbage collection repairs owned Claude configuration
directories with permissive modes, and continues other cleanup when a
credential path is unsafe.
Read-only Claude lanes now have Bash, so a review lane can run `git log -p`,
`git diff` and `grep`. The shell gets a writer's controls: a scrubbed
environment, isolated git config, no keychain access and only the system
binaries. The read-only profile still denies writes to the worktree and other
project paths.
Read-only lanes with network access can read the GitHub CLI configuration, so
commands such as `gh issue view` work. The configuration stays unwritable.
Writer lanes can use a worktree recreated at a pruned path once the previous
writer's custody has settled. Unsettled reservations stay fenced, a run keeps
the worktree it held, and only the attempt that settled may be readmitted.
Graph nodes can declare `required_verdict`, an exact, case-sensitive result
line (surrounding whitespace is ignored), for example `"VERDICT: PASS"`. A
successful lane without that line fails the node, blocks its dependants and
withholds graph delivery. Nodes without the field keep their behaviour, and
existing graph checkpoints remain compatible.
Provider processes start with umask 077, so state they create under the run
store is private from creation.
Cursor accounts register on CLI-only hosts using the CLI sign-in identity. Live
quota remains unavailable without the desktop app's sign-in database.
