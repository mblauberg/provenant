# v1.2.0

This release makes lanes self-managing (epic #1829). A writer dispatch now creates, owns and prunes its own worktree, `lanes --wait` and landing replace chair polling, and garbage collection runs on settlement and landing.

Provenant makes no stability promise; see [stability](README.md#stability).

## Breaking changes

- **The host admission ledger (`admission.sqlite3`) moves to schema version 2.** It upgrades in place on first use, and the upgrade is refused if the host's clock or boot identity cannot be read. A binary from before this release refuses the upgraded ledger, so upgrade every host together. Existing leases and tickets with no class count as writers, and the upgrade holds each class for one startup spacing once.
- **Rerun `provenant install --hooks on` after upgrading** to register the new Claude Code hook handlers (`hook claude session-start`, `hook claude stop`, `WorktreeCreate` and `WorktreeRemove`).

## Behaviour changes

### Admission and concurrency

- Each lane now has a class: `writer` for a `worktree-write` lane, `read_only` for every other. Startup spacing is measured per class. Writers keep the 20 s gap after the last writer start. Read-only lanes wait 2 s and no longer queue behind writers, so eight read-only lanes start in about 14 s instead of 2 min 20 s. The memory (5 %) and disk (500 MiB) floors still refuse both classes.
- Startup spacing no longer changes when the system clock does. A reboot resets spacing, so the first lane of each class after a boot starts at once. If the host's clock or boot identity cannot be read, the lane's start is refused with `startup spacing cannot be judged: host clock or boot identity unreadable`.
- The per-project active lane cap is 32, up from 16. The host cap stays at 64.
- A batch with no `worktree-write` lane now runs 16 lanes at once by default, set by the new `lanes.max_concurrency_read_only` key (1 to 16; the `economy` preset sets 8). Batches with a writer keep the `lanes.max_concurrency` default of 8. A `lanes.max_concurrency` you set also caps the read-only default unless you set the read-only key too.
- An explicit `--concurrency` or Fabric `concurrency` still wins, and its upper bound is now 16. A value above the batch's task count is now accepted by the CLI, a local Fabric call and a peer alike; a peer used to refuse it.
- `lanes` shows `lane_class` and `waiting_for` for queued and starting lanes, and uses the wait as their reason: launch not yet handed to a guardian, run concurrency, the class's remaining startup spacing, or host capacity. A peer's lanes show the same fields; an older peer shows neither.

### Lane access

- Every lane now defaults to open network access on all adapters and modes, so read-only lanes can run tools such as `gh` or fetch documentation without `--network on`. `--network off` still restricts a lane to its provider endpoints, or to local network access when the Postgres capability is requested.
- Read-only Agy and Codex lanes can run system programs such as `git log -p` with the lane's existing network access. Read roots must not hold anything the lane may not see. Provider tool denials name the action in the terminal reason, and a recovered answer keeps the lane successful.
- Read-only Claude lanes now have Bash, so a review lane can run `git log -p`, `git diff` and `grep`. The shell runs with a scrubbed environment, isolated git config, no keychain access and only the system binaries. The read-only profile still denies writes to the worktree and other project paths.
- Read-only lanes with network access can read the GitHub CLI configuration, so `gh issue view` works. The configuration stays unwritable.
- Provider processes start with umask 077, so state they create under the run store is private from creation.

### Worktrees, hooks and sessions

- `provenant install --hooks on` registers `WorktreeCreate` and `WorktreeRemove` hooks for Claude Code. Worktrees Claude creates for native agents are made by `provenant worktree create` on the branch `claude/<name>` and registered with an owner, and removal goes through `provenant worktree remove`. A name outside letters, digits, `.`, `_` and `-`, or a worktree the owner refuses to remove (dirty, live writer, primary or not listed for the project), fails the hook and leaves the worktree in place; the hooks never force. Without `--hooks on`, Claude keeps creating its own worktrees (#1845).
- Session checkpoints can hold up to 256 KiB of UTF-8 Markdown, and the last 8 saves are kept as numbered revisions. `workflow session show --rev N`, `show --revisions` and `workflow session diff N` read them as plain text. `[retention] session_revisions` (1 to 64) sets the count, for `workflow session handoff` saves as well as `session save`. `session diff` now shows a change that is only a final newline.
- `lanes --wait` counts only lanes that were unsettled when the wait started or have settled since (or since `--since`), so an older settled attempt no longer ends a wait on a newer one. An attempt named by its exact ID still counts, and a wait on runs whose lanes all settled earlier is refused with the count.

### Garbage collection and retention

- Scheduled collection now runs daily. It excludes stale, transient and non-Git project roots, and new transient invocation roots no longer create persistent project registrations. `gc.data.unobserved_projects` stays an array of paths, and `skipped_transient` reports excluded transient common directories.
- Writer admission tries a five-second pressure collection before refusing for low disk, then rechecks all output volumes. Pressure sweeps skip network fetches and worktree deletion, honour `gc.schedule=false`, and limit writer-admission collection to the launching project. Pressure still prunes declared idle output, with a one-day floor below the free-space floor. Manual pressure collection reports why it has nothing to collect, including when `gc.schedule=false` disables it.
- `retention.logs_days` defaults to 30. Large stdout and stderr captures of closed runs, including child stores, expire with a 64 KiB tail kept, and stderr stays readable with truncation reported. Disk reports measure captures separately as `attempt_logs`.
- Intermediate event-log entries in the run-store database expire under `retention.logs_days` once all sibling attempts in a run are terminal. Terminal attempt records, result artefacts, exit evidence, digests, capture tails and child-store databases survive, as does each attempt's newest event, so unacknowledged settlements stay visible to lane cursors. GC reports expired event rows as `provider_state.expired_events` in JSON previews and applied sweeps.
- GC can reclaim idle Git-ignored declared output from linked worktrees without ending a lane. Nested repositories protect their containing output directory. Explicit worktree removal allows declared output and names undeclared ignored blockers such as `.env`. Projects can opt into foreign worktree collection with `gc.projects.<id>.foreign_worktrees = "merged-clean"`.

### Other

- Writer lanes using an Opus route print a one-line advisory suggesting a cheaper route in the same tier. Dispatch continues. Set `suppress_opus_writer_warning = true` under `[domains.routing]` in `config.toml` to silence it.
- OpenCode free-tier limit events that report `retryAfterMs` (OpenCode 2.1.2 and later) now cool the `opencode-free` pool until the stated reset time, then admission restores the pool across models. Retry timings are capped at 24 hours, and missing, negative, zero or non-numeric values keep the existing fallback cooldown.

## Additions

### Lane worktrees and delivery

- Writer dispatch can create and own its worktree with `--worktree-branch` and deliver with `--deliver none|push|integrate:BRANCH|pr`. Graph nodes share these modes, and a graph can open one integration PR.
- `lane deliver` picks up a settled writer with clean-tree and exact-head checks. Native linked worktrees can be adopted, and graph scratch is excluded locally through Git's `info/exclude`.
- Resume starts fresh with retained context when continuation is unavailable, unless `--no-fallback` is set. Attempts recorded before #1855 have no launch evidence of running under an owned tree, so continuation resumes them in place.
- Owned lane cleanup keeps unsafe or unmerged work and records why.
- `pr land NUMBER --head SHA` waits for CI, merges at that head, fast-forwards a clean local base, then removes the merged branch's worktree (after its declared build output) and deletes the branch. It deletes only while the branch is still at the merged head and not checked out, rebased or bisected in any worktree, and a fork's head leaves a same-named local branch alone. Each follow-up step refuses and reports rather than forcing, and a worktree holding commits the base lacks is kept with its branch.
- `pr open --from-attempt` builds the pull request body from the attempt's receipts into the repository template, and `pr status` prints one line per pull request.
- Graph nodes can declare `required_verdict`, an exact, case-sensitive result line (surrounding whitespace ignored), for example `"VERDICT: PASS"`. A successful lane without that line fails the node, blocks its dependants and withholds graph delivery. Nodes without the field and existing graph checkpoints are unaffected.

### Waiting and observing lanes

- `lanes` takes `--session LABEL`, `--host` works with `--wait`, and `lanes --watch` prints one line per state change for a background shell or monitor.
- A peer wait keeps every running lane tracked until it settles, even after newer dispatches push it off the peer's newest 100. `--since` selects by settlement time rather than queue order and scans up to 1000 lanes. A lane that settles while a peer is unreachable still counts.
- A poll shares one deadline across all its peer reads, and a hung `ssh` is gone by the deadline. Peer `lanes --wait` and `lanes --watch` report the last transient host read failure when no later read succeeds before the deadline.
- `output` accepts peer hosts and two-part attempt references, and clamps local tails to 500 lines. `route resolve` accepts a positional route or model name.
- Each attempt points at its provider transcript. `provenant lanes --json` gains a `transcript` object (`adapter`, `session` and, when retained provider state holds the file, its `path`), and telemetry attempt records carry the adapter and session. `provenant output <attempt> --part transcript --tail N` reads the redacted, bounded tail in place. Provenant stores a pointer, never a copy.

### Claude Code session hooks

- A new `hook claude session-start` handler (SessionStart on startup, resume and clear) and the existing `compact` handler print a bounded, read-only digest of the project's in-flight lanes, the lanes settled since the chair last saved the checkpoint, and `pr status` for the pull requests named in the checkpoint (`PR #N`). A section that cannot be read is named as unavailable rather than shown empty (#1843).
- `pre-compact` saves lane, PR and worktree state to `autosave.md` beside the session checkpoint, and a new `hook claude stop` handler refreshes it after ten quiet minutes. Neither writes the chair's `checkpoint.md`. When only `autosave.md` exists it is reported as such, so the chair still saves notes and authority references. Lane sessions only report (#1844).

### Quota and telemetry

- `provenant quota usage` shows the last seven days of recorded use across projects, grouped by account. `--days` changes the window and `--adapter` selects a provider. Lane rows show recorded token categories and missing measurements for registered projects, excluding transient workspace attempts. Chair rows show distinct sessions only, since chair tokens are not recorded. The counts are not provider quota percentages.
- Claude chair SessionStart hooks record the serving registered account, including when no account-switch handoff is pending. Repeated starts for the same session count once per account and project in the window. Historical chair tokens are not recovered and transcripts are not read.
- Chair observations store the serving account key and session ID. Project IDs are recorded only when `usage.project_attribution` is enabled; otherwise, or when no project identity is available, the report shows an unknown project. Attribution never registers projects and its failures do not block consuming an account-switch handoff.
- Claude lane attempts record input, output, cache read and cache write token counts from the provider's final result event. A settled Claude attempt with no provider usage records why.
- Cursor accounts register on CLI-only hosts using the CLI sign-in identity. Live quota stays unavailable without the desktop app's sign-in database.

### Skills

- The `tanstack` skill covers Form, Store, Pacer, Hotkeys, Charts, Devtools, DB and Router file routes, as well as Query, Router, Table and Virtual. It sends agents to version-matched API detail first, using read-only TanStack Intent `list` and `load` and the pinned TanStack CLI doc commands with telemetry disabled. It forbids Intent install and hooks and CLI scaffolding.
- The orchestrate skill's Fabric brief template tells writer lanes to batch targeted tests into one cargo invocation, lint in the lint target, and keep incremental builds on despite the sandbox's hard-link warning (#1853).

## Fixes

### Lane settlement and worktrees

- Lane settlement collects its declared ignored output and Cargo cache even when delivery pickup keeps the worktree. Settlement and landing share GC's lock, with the daily sweep as a backstop. Final worktree removal honours regenerable and keep settings when output is recreated, so regenerable build files no longer strand merged worktrees.
- Resume keeps edits in explicit unowned and adopted worktrees. Launch-time ownership evidence keeps previously owned lane trees fenced after pruning, reassignment or owner removal. When resume needs a replacement worktree, the fallback prompt states that prior history is unavailable instead of pulling in unrelated primary-checkout commits.
- Writer lanes can use a worktree recreated at a pruned path once the previous writer's custody has settled. Unsettled reservations stay fenced, a run keeps the worktree it held, and only the attempt that settled can be readmitted.
- Reboot recovery treats unavailable locks and unreadable or mismatched records as unproven custody, so cancellation reports an unobservable attempt with the cause instead of a recovery error. Attempts that already have a terminal outcome complete staging cleanup and verified settlement before their reservation is released.
- Delivery now refuses protected direct-push targets before admission for concise delivery, legacy flags and manifests. PRs can still target protected base branches.
- A retry recreates deleted graph publication refs when the sealed marker matches the same head; conflicting markers and refs still refuse. An accepted dispatch replays even when later repository state protects the publication branch, while new admission and actual delivery still check protection.
- Writer launch refusals on macOS name the hard-linked file and explain how to retry after inspecting and removing disposable build output.
- A `worktree-write` dispatch is no longer refused with "compiled profile exceeds its byte bound" once a worktree's lane build cache passes 100,000 entries. The limit is now 500,000 entries with the hard-link check kept, and entry, depth and grant-count overflows name their family and path.
- A `worktree-write` dispatch whose `--write-root` equals or contains its `--worktree` is refused up front, with an error that names the flag and says worktree-write already grants the worktree.
- A dispatch whose confinement plan cannot be built reports that confinement error instead of a disclosure denial.
- Writer lanes get `PROVENANT_LANE_CARGO_LINT_TARGET`, a `target-lint/` directory in their Cargo lane cache. Lint-only runs (`cargo check`, `cargo clippy`) can set it as both `CARGO_TARGET_DIR` and `CARGO_BUILD_BUILD_DIR` so they stop waiting on the build-directory lock. It is removed with the lane cache, and read-only lanes are unchanged.

### Garbage collection

- Large declared output no longer exhausts the idleness budget for explicit or foreign removal, and foreign output age uses directory-entry mtimes.
- Queued or pending submitted writers keep their managed trees under foreign GC. Foreign removal holds writer exclusion even when no state existed and clears its temporary state after removal or refusal.
- GC refuses bare-backed linked checkouts as primary collection roots.
- Provider-state GC repairs owned Claude configuration directories with permissive modes and continues other cleanup when a credential path is unsafe.
- Quota reports and coverage readings count registered accounts only, omitting unregistered cache records and unsupported provider source rows. Non-retaining adapters with no registered accounts drop stale records on tick, legacy-keyed duplicate `agy` records are dropped when their fingerprint matches a registered account, and empty orphan quota directories are removed on drop (#1810).

### Providers

- Read-only Claude lanes can read every `--read-root`, including roots outside their working directory, so a review briefed with a diff file outside the worktree no longer ends without a verdict (#1862).
- Codex resumes copy retained session directories without indexes that point to the previous attempt's rollout, so resume no longer tries to read session files outside its sandbox (#1790).
- OpenCode lanes launch when the project or an ancestor contains `.agents`, `.claude` or `.codex` directories. Discovery stays literal, grants no reads of configuration contents outside existing read roots, and still refuses symlinks and replaced held parents. Anchor refusals name the path and validation stage.
- OpenCode runs that emit their final text and exit cleanly succeed even when OpenCode omits the closing `step_finish` event. Error events, signals, non-zero exits and timeouts still prevent success.
- OpenCode lanes use the host-selected Git for repository discovery in read-only and writer modes, bypassing Apple's system shim. Read-only lanes permit only OpenCode and the selected Git binary to execute.
- Provider version-probe refusals report termination, timeout and stdout truncation details, or identify empty output, without including captured contents. The four-second timeout and 128-byte stdout limit are unchanged.
- Peer dispatch accepts prompts over 64 KiB within the launch and encoded peer frame limits. Large argv prompts are sealed on the peer, and rerunning with the same operation ID recovers the lane's outcome. Requests whose encoded frame exceeds 1 MiB are refused before submission with a size error.

### Hooks and sessions

- Claude Code session hooks repeat a non-default `--state-dir` in every command they print (the `Save:` line, the digest heading, the bounded-output marker, the `pr status` hint and the `workflow session show` pointer), so following a hint never replaces a checkpoint in the default store. A directory that cannot be shown safely gives a plain note instead of a command (#1829).
- A damaged or unreadable `autosave.md` no longer hides a readable chair checkpoint at session start. The hook adds one `Autosave unavailable` line instead (#1829).
- Session hooks recognise pull request references in text containing Unicode.
- Worktree removal hooks report path resolution errors instead of treating them as already removed.
