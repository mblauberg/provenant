# Provenant v1.2.0

Released 28 October 2026.

This release makes lanes self-managing (epic #1829). A writer dispatch now creates, owns and prunes its own worktree, `lanes --wait` and landing replace chair polling, and garbage collection runs on settlement and landing.

Provenant makes no stability promise; see [stability](README.md#stability).

## Breaking changes

- **The host admission ledger (`admission.sqlite3`) moves to schema version 2.** It upgrades in place on first use, and a binary from before this release refuses the upgraded ledger, so upgrade every host together. Each class waits one startup spacing once after the upgrade, and the upgrade is refused if the host's clock or boot identity cannot be read.
- **Rerun `provenant install --hooks on` after upgrading** to register the new Claude Code hook handlers (`hook claude session-start`, `hook claude stop`, `WorktreeCreate` and `WorktreeRemove`).

## Behaviour changes

### Admission and concurrency

- Lanes have a class: `writer` for a `worktree-write` lane, `read_only` for every other. Startup spacing is measured per class. Writers keep the 20 s gap. Read-only lanes wait 2 s and no longer queue behind writers, so eight start in about 14 s instead of 2 min 20 s. The memory (5 %) and disk (500 MiB) floors still apply to both.
- Startup spacing no longer changes when the system clock does, and a reboot resets it. A lane is refused with `startup spacing cannot be judged: host clock or boot identity unreadable` if neither can be read.
- The per-project active lane cap is 32, up from 16. The host cap stays at 64.
- A batch with no `worktree-write` lane runs 16 lanes at once by default, set by the new `lanes.max_concurrency_read_only` key (1 to 16; the `economy` preset sets 8). Batches with a writer keep the `lanes.max_concurrency` default of 8, and a `lanes.max_concurrency` you set also caps the read-only default unless you set the new key too.
- `--concurrency` and Fabric `concurrency` still win, with an upper bound of 16, and a value above the batch's task count is now accepted by peers as well as locally.
- `lanes` shows `lane_class` and `waiting_for` for queued and starting lanes, with the reason they wait: guardian handoff, run concurrency, startup spacing or host capacity. Older peers show neither.

### Lane access

- Lanes default to open network access on all adapters and modes, so read-only lanes can run `gh` or fetch documentation without `--network on`. `--network off` still restricts a lane to its provider endpoints, or to local network access when the Postgres capability is requested.
- Read-only Agy and Codex lanes can run system programs such as `git log -p` with the lane's network access, so read roots must not hold anything the lane may not see. Provider tool denials name the action in the terminal reason.
- Read-only Claude lanes have Bash, so a review lane can run `git log -p`, `git diff` and `grep`. The shell has a scrubbed environment and no keychain access, and writes to the worktree and other project paths stay denied.
- Read-only lanes with network access can read the GitHub CLI configuration, so `gh issue view` works.
- Provider processes start with umask 077, so run-store state they create is private.

### Worktrees, hooks and sessions

- `provenant install --hooks on` registers `WorktreeCreate` and `WorktreeRemove` hooks. Worktrees Claude creates for native agents are made by `provenant worktree create` on the branch `claude/<name>` with an owner, and removal goes through `provenant worktree remove`. The hooks never force: an unsupported name or a worktree the owner refuses to remove (dirty, live writer, primary or unlisted) fails the hook and leaves the worktree in place. Without `--hooks on`, Claude creates its own worktrees (#1845).
- Session checkpoints hold up to 256 KiB of Markdown, and the last 8 saves are kept as numbered revisions. Read them with `workflow session show --rev N`, `show --revisions` and `workflow session diff N`. `[retention] session_revisions` (1 to 64) sets the count, for `session save` and `workflow session handoff` alike.
- `lanes --wait` counts only lanes that were unsettled when the wait started or have settled since (or since `--since`), so an older settled attempt no longer ends a wait on a newer one. An attempt named by its exact ID still counts, and a wait on runs whose lanes all settled earlier is refused with the count.

### Garbage collection and retention

- Scheduled collection runs daily. It excludes stale, transient and non-Git project roots, and transient invocation roots no longer create persistent project registrations.
- Writer admission tries a five-second pressure collection before refusing for low disk, then rechecks all output volumes. Pressure sweeps skip network fetches and worktree deletion, honour `gc.schedule=false` and cover only the launching project. Manual pressure collection says why it has nothing to collect.
- `retention.logs_days` defaults to 30. Large stdout and stderr captures of closed runs expire with a 64 KiB tail kept, and disk reports show them separately as `attempt_logs`. Intermediate event-log rows expire under the same setting once a run's attempts are terminal, while terminal attempt records, result artefacts, exit evidence, digests and 64 KiB capture tails are kept, reported as `provider_state.expired_events`.
- GC can reclaim idle Git-ignored declared output from linked worktrees without ending a lane. Owned-lane cleanup retains unsafe or unmerged work and records why. Explicit worktree removal allows declared output and names undeclared ignored blockers such as `.env`. Projects can opt into collecting foreign worktrees with `gc.projects.<id>.foreign_worktrees = "merged-clean"`.

### Other

- Writer lanes on an Opus route print a one-line advisory suggesting a cheaper route in the same tier, and dispatch continues. Set `suppress_opus_writer_warning = true` under `[domains.routing]` to silence it.
- OpenCode free-tier limit events that report `retryAfterMs` (OpenCode 2.1.2 and later) cool the `opencode-free` pool until the stated reset, capped at 24 hours. Missing or invalid values keep the existing fallback cooldown.

## Additions

### Lane worktrees and delivery

- Writer dispatch can create and own its worktree with `--worktree-branch` and deliver with `--deliver none|push|integrate:BRANCH|pr`. Graph nodes share these modes, and a graph can open one integration PR.
- `lane deliver` picks up a settled writer after clean-tree and exact-head checks, and native linked worktrees can be adopted.
- Resume starts fresh with retained context when continuation is unavailable, unless `--no-fallback` is set. Attempts recorded before #1855 resume in place.
- `pr land NUMBER --head SHA` waits for CI, merges at that head, fast-forwards a clean local base, removes the merged branch's worktree and deletes the branch. Each step refuses and reports rather than forcing, and a branch that moved off the merged head, or a worktree holding commits the base lacks, is kept.
- `pr open --from-attempt` builds the pull request body from the attempt's receipts, and `pr status` prints one line per pull request.
- Graph nodes can declare `required_verdict`, an exact, case-sensitive result line such as `"VERDICT: PASS"`. A successful lane without it fails the node, blocks its dependants and withholds graph delivery. Nodes without the field are unaffected.

### Waiting and observing lanes

- `lanes` takes `--session LABEL`, `--host` works with `--wait`, and `lanes --watch` prints one line per state change for a background shell or monitor.
- Peer waits keep every running lane tracked until it settles, even past the peer's newest 100. `--since` selects by settlement time and scans up to 1000 lanes. A lane that settles while a peer is unreachable still counts, and one deadline covers all peer reads.
- `output` accepts peer hosts and two-part attempt references and clamps local tails to 500 lines. `route resolve` accepts a positional route or model name.
- Each attempt points at its provider transcript. `lanes --json` gains a `transcript` object (`adapter`, `session` and, when retained, `path`). `output <attempt> --part transcript --tail N` reads the redacted tail in place; Provenant stores a pointer, never a copy.

### Claude Code session hooks

- The `hook claude session-start` handler (on startup, resume and clear) and the `compact` handler print a read-only digest of in-flight lanes, lanes settled since the last checkpoint save, and `pr status` for the pull requests named in the checkpoint. Unreadable sections are named as unavailable (#1843).
- `pre-compact` saves lane, PR and worktree state to `autosave.md` beside the session checkpoint, and `hook claude stop` refreshes it after ten quiet minutes. Neither writes `checkpoint.md`, so the chair still saves notes and authority references (#1844).

### Quota and telemetry

- `provenant quota usage` shows the last seven days of recorded use across projects, grouped by account. `--days` changes the window and `--adapter` selects a provider. Chair rows show distinct sessions only, since chair tokens are not recorded. The counts are not provider quota percentages.
- Claude chair SessionStart hooks record the serving registered account. Project IDs are recorded only when `usage.project_attribution` is enabled; otherwise the report shows an unknown project.
- Claude lane attempts record input, output, cache read and cache write token counts from the provider's final result.
- Cursor accounts register on CLI-only hosts using the CLI sign-in identity. Live quota stays unavailable without the desktop app's sign-in database.

### Skills

- The `tanstack` skill covers Form, Store, Pacer, Hotkeys, Charts, Devtools, DB and Router file routes, as well as Query, Router, Table and Virtual. It sends agents to version-matched API detail through read-only TanStack Intent and CLI doc commands, and forbids Intent install, hooks and scaffolding.
- The orchestrate skill's Fabric brief template tells writer lanes to batch targeted tests into one cargo invocation, lint in the lint target, and keep incremental builds on despite the sandbox's hard-link warning (#1853).

## Fixes

### Lane settlement and worktrees

- Settlement collects a lane's declared ignored output and Cargo cache even when delivery pickup keeps the worktree, and settlement and landing share GC's lock.
- Resume keeps edits in explicit unowned and adopted worktrees. When it needs a replacement worktree, the fallback prompt says prior history is unavailable instead of pulling in unrelated commits.
- Writer lanes can use a worktree recreated at a pruned path once the previous writer's custody has settled.
- Reboot recovery treats unavailable locks and unreadable or mismatched records as unproven custody, so cancellation reports an unobservable attempt with the cause instead of a recovery error. Attempts with a terminal outcome finish staging cleanup and settlement before their reservation is released.
- Delivery refuses protected direct-push targets before admission. PRs can still target protected base branches.
- A retry recreates deleted graph publication refs when the sealed marker matches the same head, and an accepted dispatch replays even when the publication branch has since become protected.
- Writer launch refusals on macOS name the hard-linked file and say how to retry.
- A `worktree-write` dispatch is no longer refused with "compiled profile exceeds its byte bound" once a lane build cache passes 100,000 entries. The limit is now 500,000, and overflows name their family and path.
- A `worktree-write` dispatch whose `--write-root` equals or contains its `--worktree` is refused up front, with an error naming the flag.
- Writer lanes get `PROVENANT_LANE_CARGO_LINT_TARGET`, a `target-lint/` directory in the lane Cargo cache. Lint-only runs (`cargo check`, `cargo clippy`) can set it as both `CARGO_TARGET_DIR` and `CARGO_BUILD_BUILD_DIR` so they stop waiting on the build-directory lock.

### Garbage collection

- Queued or pending submitted writers keep their managed trees under foreign GC.
- Provider-state GC repairs owned Claude configuration directories with permissive modes and continues other cleanup when a credential path is unsafe.
- Quota reports count registered accounts only, omitting unregistered cache records and unsupported provider rows. Stale and duplicate `agy` records and empty orphan quota directories are dropped (#1810).

### Providers

- Read-only Claude lanes can read every `--read-root`, including roots outside their working directory, so a review briefed with a diff file outside the worktree no longer ends without a verdict (#1862).
- Codex resumes copy retained session directories without indexes that point at the previous attempt's rollout, so resume no longer reads session files outside its sandbox (#1790).
- OpenCode lanes launch when the project or an ancestor contains `.agents`, `.claude` or `.codex` directories. Refusals name the path and stage.
- OpenCode runs that emit their final text and exit cleanly succeed even without the closing `step_finish` event. Error events, signals, non-zero exits and timeouts still prevent success.
- OpenCode lanes use the host-selected Git for repository discovery instead of Apple's system shim, and read-only lanes may execute only OpenCode and that Git.
- Provider version-probe refusals report termination, timeout and truncation details without captured contents.
- Peer dispatch accepts prompts over 64 KiB within the launch and peer frame limits. Large argv prompts are sealed on the peer, and rerunning with the same operation ID recovers the lane's outcome. A request whose encoded frame exceeds 1 MiB is refused before submission.

### Hooks and sessions

- Claude Code session hooks repeat a non-default `--state-dir` in every command they print, so following a hint never replaces a checkpoint in the default store. A directory that cannot be shown safely gives a plain note instead (#1829).
- A damaged or unreadable `autosave.md` no longer hides a readable chair checkpoint at session start. The hook adds one `Autosave unavailable` line (#1829).
- Session hooks recognise pull request references in text containing Unicode.
- Worktree removal hooks report path resolution errors instead of treating the worktree as removed.
