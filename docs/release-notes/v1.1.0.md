# Provenant v1.1.0

**Date:** 27 October 2026

Every install's source digest changes once with this release. `check install`
reports existing installs as stale until they are reinstalled.

The source digest now covers shipped workspace source (each member's `src/`,
`assets/` and `build.rs`), manifests, the lockfile, the toolchain and Cargo
configuration, the release packager (`examples/package-release.rs`) and the
bundled assets. Edits under a member's `tests/`, `benches/` and other
`examples/` no longer change it.

## Stability

The v1.0.0 stability promise is withdrawn. Commands, flags, `--json` output,
`config.toml` keys, the state layout and Fabric MCP tool names and schemas can
change in any release, with no deprecation period or compatibility shims. Each
release's notes list its breaking changes. Upgrade every host together, since
peers on different versions are not supported.

## Breaking changes

- `route list --json` no longer reports each pool member's `readiness` and
  `factor_basis_points`. Listing never probes, so they were always
  `unknown_availability` and 10000. Resolve and dispatch receipts still record
  both for each candidate.
- Fabric tasks and messages no longer accept the retired `legacy` and
  `legacy_output_path` members, even as null. A store row or peer reply that
  carries one fails to decode. Migration 7 already strips them from stored
  data, so this affects only a binary from before migration 7 still writing to
  the store, or such a peer. Upgrade every host together.
- Graph checkpoints must record `launched` and `launch_actor` for each
  attempt. A checkpoint without them, written before they existed, is refused
  instead of being treated as launched and resumed under the current actor.
- `hosts doctor HOST` requires the remote report's `peer_agent` field. A
  remote build too old to report it is refused as an invalid report.
- `worktree remove NAME` now defaults to the fetched upstream default branch,
  falling back to the primary branch with a warning if fetching fails. An
  explicit `--integration` is honoured. Upstream Git calls time out after
  five seconds each.
- `gc` adds `--apply` for merged worktree and declared output deletion. Bare
  `gc` still deletes orphaned and idle caches while previewing these new
  classes; `--dry-run` previews all classes. Reinstall the scheduled agent to
  add `--apply` to its arguments.
- GC JSON adds `worktree_cleanup` and `alerts`. Each worktree cleanup includes
  its own `dry_run` flag, independent of cache cleanup. Preview output entries
  have `removed: false` and reason `would_remove`.
- `[gc]` adds `alert_below` and per-project `regenerable` and `keep` settings.
  Merged worktree deletion requires known-terminal lanes and merged commits
  of their own; fresh tips and first-parent ancestors remain.
- GC reports locked or prunable entries as `locked_or_prunable` and omits
  the primary checkout. Pruning or branch-settlement failures retain that
  entry and allow the sweep to continue.
- Fabric graph routes now accept optional `account` in `route` and every
  `routes` entry. Graph checkpoint envelopes under
  `fabric/graphs/<project>/graph-<id>.json` now require `execution.document`
  and `execution.directory`; their digest covers those host-only inputs.
  Existing checkpoints cannot be read or resumed by the new release. Finish
  active graphs with the previous release and archive their checkpoints
  before upgrading (#1712, #1713).
- Installer cut-over support is removed: the `--legacy-checkout` install flag,
  the `LEGACY_CHECKOUT` error code, pre-1.0 cleanup and Git launcher ownership
  are removed. `check install` no longer reports the finding rules
  `legacy_entry`, `legacy_hook_conflict`, `legacy_instruction_variable` or
  `legacy_checkout_unavailable`. A receipt's `legacy` record is now ignored and
  dropped on the next install write, so receipts from the cut-over installer
  upgrade normally. Any Git hook launchers that installer placed under the
  recorded `git_hooks_dir` are no longer managed; remove them by hand if wanted
  (#1571).
- Process custody is supported only on macOS. Linux provider launch and
  guardian setup return an explicit unsupported error. Linux subreaping,
  adopted-child signalling and kernel-children settlement proof are removed;
  existing `linux_kernel_children` settlement records are refused. Utility
  execution and process observation retain their Linux implementations. See
  the [supervisor spec](../specs/supervisor.md) (#1571).
- CI runs the macOS supervisor and confinement tests on main and on pull
  requests that change `tools/front-door/`, `apps/` or the CI workflow. It also
  runs them when the base commit is unavailable (#1571).
- Move OS operations from `provenant-supervisor` into `provenant-os`, below
  process supervision. Callers import the new crate directly.
- Replace the injectable filesystem traits with concrete `Directory` and
  `FileHandle` operations. Stable bounded reads and publication durability
  checks share one implementation. On-disk formats and command behaviour
  are unchanged.
- Stable file reads expose typed read-I/O errors. Callers share
  `Metadata::unchanged` when comparing read-relevant metadata.
- Every peer request and reply envelope now carries integer `protocol`.
  The host listing reports the protocol observed in the reply envelope. Calls
  use one SSH connection and reject any different version, naming both
  versions; upgrade peers together. Missing reply protocols and released
  peers' decode refusals identify protocol 1. There is no capability
  negotiation or support for older peers. Facade errors use distinct
  `not_terminal` and `operation_conflict` codes locally and on the peer wire,
  instead of `conflict` (#1631, #1571).
- The CLI reports an unavailable run owner as `OWNER_UNAVAILABLE`, replacing
  `UNSUPPORTED` so the refusal round-trips without changing its meaning.
- Terminal attempts now lose regenerable Codex caches at settlement, known
  credential entries after 24 hours, and resumable provider state after
  `retention.provider_state_days` (default 7). Existing attempts are eligible
  on the first GC sweep. Expired resumes return `PROVIDER_STATE_EXPIRED`
  locally and `provider_state_expired` over MCP and peer calls.
  Transcripts move to `provider-history/`; results, captures, exit evidence
  and digests remain. Unclassified provider payloads are archived
  conservatively (#1570).
- Manual `gc` reads `config.toml`; an invalid config now fails the command.
  GC returns `GC` when provider-state retention reports errors (#1570).
- `disk report` separates provider-state bytes into the `provider_state`
  class instead of `attempt_retained`. GC JSON adds `provider_state` with
  `removed`, `kept` and `errors`; `config show` adds the root `retention`
  section. New candidate state records its adapter in `provider.txt` (#1570).
- The `reason` of an `uncertain` result from `provenant reconcile` is now an
  object with a `kind` (for example `writer_custody_unconfirmed`,
  `custody_not_provably_absent` or `guardian_not_observable`) and, where it
  applies, the underlying `error` text or the `reservation` path. It used to be
  free text. The human line is unchanged. The disk report no longer counts a
  `logs` entry in an attempt directory as retained: nothing writes one (#1571).
- Codex senior routing pairs GPT-6.1 Sol at medium effort with a GPT-6.1 Terra
  trial at high effort, both at weight 4 and allowing low, medium and high.
  Junior adds a Terra trial at low effort and weight 2, allowing low and medium.
  Existing junior and senior members keep their weights. Principal pairs Sol
  at high effort and weight 1, allowing medium, high and xhigh, with Claude
  Opus 5.5 at weight 1. The retired Codex principal model has no alias or
  compatibility mapping; update explicit model selections and pool overrides.
- Terra and Sol retain exact-model efforts low, medium, high, xhigh and max.
  All pools exclude max: Sol gains one AA Intelligence Index point over xhigh
  at $0.72 versus $0.39 per task. The
  [model dossier](../model-dossier.md#solterra-benchmark-priors) records the
  AA and OpenAI-run benchmark priors, sources and 2026-10-27 read date.
  Terra high and xhigh are unmeasured; revisit both trials and the split using
  Provenant lane telemetry. Telemetry includes Terra's verified standard
  API-equivalent rates.
- Fabric MCP now exposes eight tools. Use `fabric_context` for identity and
  hosts, `fabric_lease` for `claim_*` and `landing_*` operations, and
  `fabric_run` with `op: submit` for submissions. The five superseded tool
  names are removed. Tool metadata advertises schema version 2.
- Request durations use seconds: `timeout_seconds`, `wait_seconds` and
  `lease_seconds`. CLI and MCP output parts are `prompt`, `result`, `stderr`
  and `events`; use bare attempt IDs or an unambiguous full
  `run/task/attempt` reference.
- Submissions and CLI manifest tasks use the same tagged route request:
  `kind: model` with `provider` and `model`, or `kind: named` with `name`.
  Both accept optional `effort` inside `route`. Manifest tasks require this
  object; flat `model`, string `route` and task-level `effort` are removed.
- Run and lane responses expose `provider_seconds` instead of `provider_ms`;
  fractional seconds preserve the observed millisecond precision.
- CLI `lanes --since`, `telemetry stats --since` and `telemetry trace --since`
  accept integer seconds, a date or an RFC3339 timestamp; suffixes such as
  `24h` and `7d` are removed. The config key `limits.graph_timeout_ms` is now
  `limits.graph_timeout_seconds` (1 to 14,400, default 14,400).
- CLI output now uses the same `bytes: {encoding: utf8|base64, data: ...}`
  payload as MCP, replacing separate `text` and `encoding` fields. All four
  output parts also work on peers. A clipped CLI or MCP page stops before a
  split UTF-8 character, and an MCP `events` page holds as many whole events
  as fit `max_bytes`.
- Fencing tokens use 32 lower-case hex digits. Binary output uses padded
  base64 with `encoding: base64` instead of JSON byte arrays.
- Fabric peer protocol is now 3. Upgrade peers together. Run operations share
  one typed service, with transport-specific errors rendered at the edge. The
  peer wire uses the MCP op names (`submit`, `hosts`, `claim_*` and
  `landing_*`), and a peer error reply carries only its typed error; only
  `launch_unknown` names an operation ID.
- Coordination operation receipts now store the public request and result,
  with seconds and hex tokens. Retrying a claim, landing or task-proof
  operation ID recorded by an earlier build is refused as a reused ID; use a
  fresh operation ID.
- CLI continuation refusals use `CONTINUATION_UNSUPPORTED` to distinguish
  an unavailable provider session from other refused execution controls.
- CLI and MCP share one category per run error. A corrupt run record or
  artefact is `STATE_CORRUPT` on the CLI, not `IO`, and an invalid run
  request is `invalid_input` on MCP, not `state_corrupt`.
- Task classes are removed. `config show` no longer takes `--task-class`, the
  knob registry's presets no longer carry `task_classes`, and Fabric routes
  and submission tasks no longer accept `task_class`: `fabric_run` with
  `op: submit` rejects it as invalid input, and the field is gone from its
  schema. Use a tagged model or named route instead. New dispatch profiles
  record no `task_class`; old runs stay readable, including requests and
  attempts sealed with that field. Upgrade every host together (#1571).
- The eight advisory knobs are removed from the registry, since no code read
  them: `effort.shift`, `context.ceiling_tokens`, `repair.max_cycles`,
  `council.junior_size`, `routing.pool_mode`, `writing.final_polish`,
  `context.summary_tokens` and `quota.pace_tolerance`. Their defaults are now
  chair judgement in `skills/orchestrate/SKILL.md`. A `[knobs]` entry
  or `--knob` override naming one is refused as an unknown key, and
  `config set` and `config unset` refuse them too, so delete any such line
  from `config.toml` by hand. The `economy` and `rigorous` presets keep only
  their wired knobs, and with no nullable knob left, `config set` no longer
  accepts `null` (#1571).
- Routing config lives only under `[domains.routing]`; the root `[routing]`
  alias is removed and a root `[routing]` table is refused as an unknown key.
  Move any such table under `[domains.routing]`. `route set`, `route remove`,
  `route reset` and `route pacing` now write there (#1571).
- `config set` and `config unset` use the same editor as the `route` verbs:
  they refuse to rewrite a `config.toml` that does not already validate, and
  report a domain error before writing rather than after. Route edits accept
  inline domain tables as well as table headers (#1571).

## Behaviour changes

- TDD guidance requires spec-derived expectations, specific rejection errors
  and reporting test/spec conflicts before proceeding. It names assertion
  weakening and test-input special cases, uses Rust examples and offers a
  fresh-context acceptance-test writer for crucial work. Review guidance adds
  a five-question test rubric; config rejection loops check error variants
  and codes.
- Install and check canonicalise `HOME` before resolving their targets. A
  symlinked home now resolves to its target, and a relative `HOME` is rejected.
- A child lane may name a different adapter or account than its parent. This
  is now documented as intended rather than left open (#1554).
- Dispatch now probes accounts only for adapters that the route, its pool or an
  explicit fallback can use. A broken login for an adapter that a dispatch
  cannot reach no longer shows a skip line or runs that provider's commands
  (#1571).
- Change specs live in issue bodies and expire with delivery, with evidence
  tags, explicit non-goals and a named post-delivery fate. Scratch citations
  receive advisory warnings. See the [work-item workflow](../runbooks/github-workflow.md).
- Scope offers a provisional advisory fresh-reader check for non-trivial
  specs. Its past-spec comparison is prepared for a separate evaluation.
- Agent filings require observed evidence and independent triage, record
  filer provenance and defer checklist-epic leaves until lease. Ready has an
  advisory cap; staleness follows evidence rather than timestamps.
- Run settlement advances pending Fabric graphs in the same project after
  releasing custody. Dependants start automatically; `graph resume` remains
  manual recovery after a crash when no later run settles (#1712).
- The engineering-docs skill amends live ADRs in place, moves process and
  deferrals to their owners, separates invariant specs from generated
  reference, and requires owner/anchor lines and short canonical instruction
  files. See [the skill](../../skills/engineering-docs/SKILL.md).
- `provenant output` on a terminal attempt that has no requested part now
  reports `NOT_FOUND` (exit 2). It used to report `NONTERMINAL` (exit 1)
  locally and `CONFLICT` over a peer. Over MCP the facade code is
  `not_found`. Active attempts still report `NONTERMINAL` (#1673).
- Host entries report `protocol` only when known. Mismatched peers remain in
  the list with `available: false`, their protocol and `reason: "peer_version"`.
- Completed writers with protected changes now end as `review_required`, retain
  their candidate `head` and `protected_paths` in CLI and MCP lane output, and
  await chair review without automatic delivery. The CLI accepts
  `lanes --state review_required`, and the menu bar attention view includes
  these lanes.
- Succeeded writers report their candidate `head` even without delivery.
- Protected-path checks exclude protected edits present at lane start and clean
  protected edits merged from upstream. Unresolvable delivery target refs or
  merge bases fall back to the lane's start head so quarantine can still finish.
- `provenant gc`, including the six-hour macOS schedule, collects terminal
  provider state as well as lane build caches. Set
  `[retention] provider_state_days = 7` in `config.toml` (range 1 to 3650).
  The key is reread at each sweep. `--dry-run` previews provider-state
  removals; active attempts, retained reservations and pending
  continuations are protected (#1570).
- Independent review briefs carry the target and rubric without the chair's
  hypothesis or expected verdict. An unreadable rubric returns `incomplete`.
- Writers may contest findings with evidence and one re-audit. Remaining
  disagreement is recorded as an accepted trade-off under existing authority
  and merge gates.
- Skill changes require two near-miss negative fixtures per skill and, for
  behaviour changes, recorded with-and-without runs. The new
  `scripts/check-skill-negatives` inventories negative routes; judgement-based
  results remain advisory. Orchestrate loads dispatch procedure from a
  reference and includes agent provenance in issue-filing briefs.
- Every peer request now carries a `trace` (sending host, actor and the
  operation the action names). Peer ingress refuses a request whose
  `trace.host` is not its `source_host`. A usage event under
  `usage.project_attribution` now records the project as `trace.project`
  instead of `project_id`. Earlier lines in `usage.jsonl` keep counting in the
  aggregate rows but no longer in the per-project rows (#1571).
- `provenant telemetry trace` now writes one Perfetto process per host rather
  than per task, with the task in each thread name and the attempt's `Trace` in
  the slice args. A flow arrow joins an attempt to its parent when both are in
  the file. `--peers` also reads the terminal attempts in each configured
  peer's newest 100 lanes, as `lanes --host` does, so Fabric and MCP
  submissions to a peer appear as well as `dispatch --host` runs; an
  unreachable peer is listed under `peers` in `--json` and skipped (#1571).
- A writer lane that succeeds but leaves uncommitted edits and no new commit
  now ends `uncommitted` instead of `succeeded`. The reason names the dirty
  paths; ignored paths and `.review-snapshots/` do not count. The outcome
  shows in `lanes`, the `dispatch` summary line and the attempt facts, and
  `output` reports the lane's `state` and `reason`. Host delivery does not
  run for it, and a graph node ends failed with no route fallback (#1740).

## Additions

- macOS default-state installs now include a per-user disk guard that checks
  space every two minutes. It warns and runs GC below 60 GiB, pauses matching
  build processes owned by the current user below 25 GiB and resumes them at
  50 GiB. Configure `[disk_guard]` in `config.toml` and rerun install to change
  its thresholds, process names or enable flag. Uninstall resumes saved paused
  processes before removing the owned agent (#1784).
- Generated [CLI](../reference/cli.md), [MCP tool](../reference/mcp-tools.md),
  [configuration key](../reference/config-keys.md) and Seatbelt references,
  with a required regeneration check in CI.
- Advisory documentation reference and owner/anchor checks, plus a weekly
  drift summary comment on the documentation epic.
- `provenant output RUN/TASK/ATTEMPT --trace` prints the attempt's trace (host,
  project, run, attempt, operation, actor and parent) and then each parent's,
  one line per hop, however long the chain; `--json` returns a `trace` array.
  A chain whose parents loop fails instead of printing. Attempt records, events
  and attempt facts now carry the same trace. A field the writer did not know
  is `null`. Older records show no trace. Peer-placed runs do not support
  `--trace` yet (#1571).
- `provenant output RUN/TASK/ATTEMPT --trace` now also lists the grants applied
  at launch: write grants, read-only exceptions and the Git grants digest (a
  `grants` object in `--json`). An attempt launched before grants were
  recorded lists none (#1564, #1571).

## Fixes

- Agy turns are no longer cut off at agy's own 15-minute print timeout. Agy
  runs with `--print-timeout 0s`, so a long turn runs until the lane deadline
  and is reported as timed out, not as an empty result (#1722).
- Read-only Agy lanes can now read a `--read-root` outside their working
  directory. Agy's headless mode auto-denied those reads and the lane failed
  with "provider result is empty or incomplete" (#1729).
- Failed Agy lanes retain partial response text. A headless permission denial
  now appears in the result and terminal reason, including when the provider
  produced no answer, so `lanes` and `output --json` explain which permission
  was denied (#1776).
- Agy writer lanes can now run commands. Every `run_command` failed with
  "fork/exec /bin/zsh: operation not permitted", because the profile did not
  allow the shell to run. Agy now runs with `SHELL=/bin/zsh`, and writers get
  the exec grants Codex and Claude writers have: `/bin`, `/usr/bin`,
  `/usr/libexec`, Cargo, rustup, Git helpers, Homebrew and the working
  directory (#1695).
Claude dispatch now reports credential read failures with a non-secret reason,
without suggesting another sign-in or starting an OAuth refresh that could
revoke a token used by other running lanes. Corrupt stored credential JSON is
also a read failure and does not trigger refresh. A token that has already
expired is still refreshed, since no running lane can be using it. Quota
refresh continues to use file-backed credentials when that is the login's
credential source (#1789).
- An unknown key inside the `install`, `gc` or `retention` config sections now
  reports schema rule `unknown_key` at the key's location instead of `type`. A
  wrong value type still reports `type`.
Fix disk exhaustion safeguards (#1780). Scheduled GC runs at load and hourly,
with a default free-space floor of 10% of the state volume, at least 50 GiB.
GC reclaims terminal attempts' temporary directories after one day, reports
paths and best-effort byte estimates, and honours dry runs. Temporary cleanup
failures leave credential expiry and provider-cache pruning eligible to run.
Writer dispatch and resume check the minimum available space across the
worktree, state and lane-cache volumes against the floor, while read-only lanes
remain available. Graph runs and MCP submissions report the disk refusal's
volume, available bytes, floor and GC remedy. Concurrent writers can each pass
this check; it reserves no space. GC alerts when space stays below the floor
after collection.
`gc.alert_below` can only raise the alert threshold above that floor.
Rerun `provenant install` to update the agent.
- Correct runbook commands and authority, remove history from living docs,
  and shorten skill entrypoints by moving detail to references.
- `gc --dry-run` now lists a merged worktree that would stay dirty after its
  output is pruned as retained with reason `dirty`, as `gc --apply` does. It
  was previously left out of the report (#1723).
- A failed automatic graph advance is now visible: `fabric graph status`
  reports `advance_error` in human and JSON output until a later advance
  succeeds. An unreadable writer reservation stalls only the attempt whose
  writer directory holds it, not graph advancement for other attempts in the
  project, and `graph resume` from a different directory in the same project
  no longer conflicts (#1712).
- OpenCode lanes no longer see the entries of `~/.claude` or `~/.codex`. Their
  discovery probes along the working directory now stop below the user's home,
  so they grant nothing at or above it. This also stops lanes in projects
  under `/Users/<name>` being refused before launch as too broad.
- Invalid-path refusals now read "path is not a permitted absolute, normalised
  path", which also fits paths refused for their scope, name or breadth.
- OpenCode lanes no longer fail before launch because discovery grants require
  a forbidden filesystem-root anchor. Invalid-path refusals now name the path.
- The free-route guidance now says to omit `--effort` on OpenCode free models,
  whose recorded controls do not support it.
- `lanes` now shows the review line for any `review_required` lane, including
  one with no protected paths (#1747).
- A writer left off its lane branch now fails with "writer HEAD is not the
  lane branch" instead of "writer head changed during quarantine" (#1747).
- When a writer's delivery remote has no `HEAD`, protected-path attribution
  now uses the lane's base branch on that same remote, so protected edits
  merged from it no longer count as the writer's own. It never borrows another
  remote's refs; if neither resolves, the lane start is the baseline and review
  is required (#1747).
- `provenant reconcile` and `provenant cancel` now settle writer attempts left
  running across a machine reboot as `lost` and release their reservations.
  Worktree contents and attempt telemetry are preserved for a resume (#1781).
- `output --host` now carries the attempt's `state` and `reason`, so a remote
  attempt that ended `uncommitted` shows its outcome and dirty paths (#1748).
- The peer protocol is now version 4. Hosts on different versions refuse each
  other with an "upgrade both" error, so upgrade every host together (#1748).
- Fabric writer submissions now report `worktree_unregistered` with the worktree
  path when `git worktree add` created the tree without Provenant's custody
  registration. An advisory claim does not register a writer. Use
  `provenant worktree create <new-branch> --base <branch>` to create a
  registered writer at the existing branch's tip.
  Submit I/O errors retain their operation and relevant absolute path when
  known. Writer errors now name Git runtime and executor setup, utility budget
  setup, project discovery, repository opening, HEAD reading and decoding,
  branch parsing and resolution, and base decoding and parsing. Git utility
  timeouts (5 s) retain the name of the operation that timed out. Writer
  reservation, snapshot, quarantine and terminal check failures also have
  operation names. The peer's exact bare `io` failure was not reproduced;
  filesystem fault injections demonstrate the diagnostic loss (#1777).
- The changed peer error payload uses Fabric protocol 5. Upgrade peers
  together; protocol 4 peers are refused before action decoding.
- `worktree create` now skips Git worktree registrations already marked
  prunable, so a deleted checkout does not block new worktree creation. It leaves
  the stale registration intact. Removal reports stale registrations with
  `git worktree prune` guidance, and merged branch pruning skips missing checkouts
  when checking whether a branch is still in use (#1783).
- `worktree create --base <remote>/<branch>` fetches an unresolved branch from
  a configured remote even when the repository fetches only `main`, without
  changing its fetch refspec. Unresolved base errors name the requested base
  (#1782).
