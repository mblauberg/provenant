# Provenant v1.1.0

Released 27 October 2026.

This release removes the v1.0.0 stability promise and moves the Fabric MCP and CLI to one set of names and units. It also adds disk-pressure and provider-state cleanup, and changes how writer lanes report results.

Provenant makes no stability promise; see [stability](README.md#stability).

**Upgrade.** Upgrade every host together: the peer protocol is now 5, and peers on different protocol versions refuse each other. Every install's source digest changes once, so `check install` reports existing installs as stale until you reinstall them. Rerun `provenant install` to update the scheduled GC agent.

## Breaking changes

### Fabric MCP and CLI interface

- **Fabric MCP exposes eight tools.** Use `fabric_context` for identity and hosts, `fabric_lease` for `claim_*` and `landing_*` operations, and `fabric_run` with `op: submit` for submissions. The five superseded tool names are removed, and tool metadata advertises schema version 2.
- **Request durations use seconds.** Use `timeout_seconds`, `wait_seconds` and `lease_seconds`. Responses report `provider_seconds` instead of `provider_ms`, and the config key `limits.graph_timeout_ms` is now `limits.graph_timeout_seconds` (1 to 14,400, default 14,400).
- **`--since` takes seconds, a date or an RFC3339 timestamp** in `lanes`, `telemetry stats` and `telemetry trace`. Suffixes such as `24h` and `7d` are removed.
- **Route requests are tagged.** Submissions and CLI manifest tasks use `route` with `kind: model` (plus `provider` and `model`) or `kind: named` (plus `name`), with an optional `effort` inside `route`. Flat `model`, string `route` and task-level `effort` are removed. Graph routes also accept an optional `account`.
- **Output parts and payloads changed.** CLI and MCP output parts are `prompt`, `result`, `stderr` and `events`, and all four work on peers. Address attempts by bare ID or an unambiguous `run/task/attempt` reference. CLI output now uses the MCP payload `bytes: {encoding: utf8|base64, data: ...}` instead of separate `text` and `encoding` fields, and binary output is padded base64 instead of JSON byte arrays. Fencing tokens are 32 lower-case hex digits.
- **`route list --json` no longer reports `readiness` and `factor_basis_points`.** Listing never probes, so they were always `unknown_availability` and 10000.
- **The CLI and MCP share one error category per run error.** A corrupt run record is `STATE_CORRUPT` on the CLI (not `IO`), an invalid run request is `invalid_input` on MCP, an unavailable run owner is `OWNER_UNAVAILABLE`, an unavailable provider session on continuation is `CONTINUATION_UNSUPPORTED`, and facade errors use `not_terminal` and `operation_conflict` instead of `conflict` (#1631, #1571).
- **`provenant output` on a terminal attempt with no part requested reports `NOT_FOUND` (exit 2),** and `not_found` over MCP. Active attempts still report `NONTERMINAL` (#1673).
- **The `reason` of an `uncertain` result from `provenant reconcile` is an object** with a `kind` (for example `writer_custody_unconfirmed`, `custody_not_provably_absent` or `guardian_not_observable`) and, where relevant, an `error` or `reservation` path. It was free text. The human line is unchanged (#1571).
- **Task classes are removed.** `config show` no longer takes `--task-class`, presets no longer carry `task_classes`, and routes and submission tasks reject `task_class`. Use a tagged model or named route. Old runs stay readable (#1571).

### Peer protocol and Fabric state

- **The Fabric peer protocol is 5.** Every envelope carries an integer `protocol`, calls use one SSH connection and reject any other version, and there is no negotiation or support for older peers. Protocol 4 peers are refused, and released peers identify as protocol 1 (#1631, #1571, #1748, #1777).
- **The peer wire uses the MCP operation names** (`submit`, `hosts`, `claim_*` and `landing_*`).
- **Every peer request carries a `trace`** (sending host, actor and operation), and ingress refuses a request whose `trace.host` is not its `source_host`. Usage events record the project as `trace.project`, so earlier `usage.jsonl` lines count in aggregate rows but no longer in per-project rows (#1571).
- **Fabric tasks and messages no longer accept `legacy` and `legacy_output_path`.** Migration 7 already strips them, so this affects only a pre-migration-7 binary still writing to the store, or such a peer.
- **Coordination receipts store the public request and result.** Retrying a claim, landing or task-proof operation ID recorded by an earlier build is refused as a reused ID; use a fresh one.
- **Graph checkpoints must record `launched` and `launch_actor` for each attempt,** and checkpoint envelopes require `execution.document` and `execution.directory`. Existing checkpoints cannot be read or resumed. Finish active graphs with the previous release and archive their checkpoints before upgrading (#1712, #1713).
- **`hosts doctor HOST` refuses a remote build that does not report `peer_agent`.**

### Configuration

- **Eight advisory knobs are removed** because no code read them: `effort.shift`, `context.ceiling_tokens`, `repair.max_cycles`, `council.junior_size`, `routing.pool_mode`, `writing.final_polish`, `context.summary_tokens` and `quota.pace_tolerance`. A `[knobs]` entry, `--knob` override, `config set` or `config unset` naming one is refused as an unknown key, so delete any such line from `config.toml`. `config set` no longer accepts `null` (#1571).
- **Routing config lives only under `[domains.routing]`.** A root `[routing]` table is refused, so move it. `route set`, `route remove`, `route reset` and `route pacing` now write there (#1571).
- **`config set` and `config unset` refuse to rewrite a `config.toml` that does not validate** and report a domain error before writing. Route edits accept inline domain tables as well as table headers (#1571).
- **Manual `gc` reads `config.toml`, and an invalid config fails the command.** `gc` returns `GC` when provider-state retention reports errors (#1570).

### Garbage collection and retention

- **`gc` adds `--apply`** for merged worktree and declared output deletion. Bare `gc` still deletes orphaned and idle caches and previews these classes, and `--dry-run` previews everything. Reinstall the scheduled agent to add `--apply` to its arguments.
- **GC JSON adds `worktree_cleanup`, `alerts` and `provider_state`** (with `removed`, `kept` and `errors`). Each worktree cleanup has its own `dry_run` flag.
- **`[gc]` adds `alert_below` and per-project `regenerable` and `keep` settings.** Merged worktree deletion requires known-terminal lanes and merged commits of their own. GC reports locked or prunable entries as `locked_or_prunable` and omits the primary checkout.
- **Terminal attempts lose provider state on a schedule.** Regenerable Codex caches go at settlement, known credential entries after 24 hours, and resumable provider state after `retention.provider_state_days` (default 7), starting at the first sweep for existing attempts. Expired resumes return `PROVIDER_STATE_EXPIRED` locally and `provider_state_expired` over MCP and peers. Transcripts move to `provider-history/`; results, captures, exit evidence and digests remain (#1570).
- **`disk report` counts provider state separately.** Its bytes move from `attempt_retained` to a `provider_state` class. `config show` adds the root `retention` section (#1570, #1571).

### Install, platform and routing

- **The source digest covers shipped source only:** each workspace member's `src/`, `assets/` and `build.rs`, manifests, the lockfile, toolchain and Cargo configuration, `examples/package-release.rs` and bundled assets. Edits to tests and benches no longer change it.
- **Installer cut-over support is removed:** the `--legacy-checkout` flag, the `LEGACY_CHECKOUT` error code, pre-1.0 cleanup and Git launcher ownership. `check install` no longer reports the `legacy_*` findings, and a receipt's `legacy` record is dropped on the next install write. Remove any Git hook launchers the cut-over installer placed under `git_hooks_dir` by hand (#1571).
- **Process custody is supported only on macOS.** Linux provider launch and guardian setup return an unsupported error, and existing `linux_kernel_children` settlement records are refused. See the [supervisor spec](../specs/supervisor.md) (#1571).
- **`worktree remove NAME` defaults to the fetched upstream default branch,** falling back to the primary branch with a warning if the fetch fails. An explicit `--integration` is honoured, and upstream Git calls time out after five seconds.
- **Codex routing uses GPT-6.1 Sol and Terra.** Senior pairs Sol at medium effort with a Terra trial at high effort, both at weight 4. Junior adds a Terra trial at low effort (weight 2). Principal pairs Sol at high effort (weight 1) with Claude Opus 5.5 (weight 1). The retired Codex principal model has no alias, so update explicit model selections and pool overrides.
- **Terra and Sol keep exact-model efforts low to max, but every pool excludes max.** Sol gains one AA Intelligence Index point over xhigh at $0.72 versus $0.39 per task. The Terra trials will be revisited from lane telemetry. See the [model dossier](../model-dossier.md#solterra-benchmark-priors).

## Behaviour changes

- A writer lane that succeeds but leaves uncommitted edits and no new commit ends `uncommitted` instead of `succeeded`, with the dirty paths as the reason. Host delivery does not run, and a graph node ends failed with no route fallback. `output --host` carries the attempt's `state` and `reason` (#1740, #1748).
- Completed writers with protected changes end as `review_required`, keep their candidate `head` and `protected_paths` in lane output, and wait for chair review with no automatic delivery. `lanes --state review_required` works and the menu bar attention view includes these lanes. Succeeded writers report their candidate `head` even without delivery.
- Protected-path checks exclude protected edits present at lane start and clean ones merged from upstream.
- Run settlement advances pending Fabric graphs in the same project, so dependants start automatically. `graph resume` remains the manual recovery after a crash (#1712).
- Dispatch probes accounts only for adapters the route can use (#1571).
- Host entries report `protocol` only when known. Mismatched peers stay in the list with `available: false`, their protocol and `reason: "peer_version"`.
- Install and check canonicalise `HOME`, and reject a relative one.
- `provenant gc`, including the six-hour macOS schedule, also collects terminal provider state. `[retention] provider_state_days` accepts 1 to 3650 and is reread at each sweep. Active attempts and pending continuations are protected (#1570).
- `provenant telemetry trace` writes one Perfetto process per host, with the task in each thread name and a flow arrow from an attempt to its parent. `--peers` also reads each peer's newest 100 lanes and lists unreachable peers under `peers` in `--json` (#1571).
- Skills and workflow guidance tighten. TDD requires spec-derived expectations and reporting of test and spec conflicts. Independent review briefs omit the chair's hypothesis. Change specs live in issue bodies and expire with delivery (see the [work-item workflow](../runbooks/github-workflow.md)). Skill changes require two near-miss negative fixtures, inventoried by `scripts/check-skill-negatives`. The engineering-docs skill amends live ADRs in place (see [the skill](../../skills/engineering-docs/SKILL.md)).

## Additions

- On macOS, default-state installs include a per-user disk guard that checks space every two minutes. It warns and runs GC below 60 GiB, pauses matching build processes you own below 25 GiB, and resumes them at 50 GiB. Configure `[disk_guard]` and rerun install to change thresholds, process names or the enable flag (#1784).
- `provenant output RUN/TASK/ATTEMPT --trace` prints the attempt's trace (host, project, run, attempt, operation, actor and parent) and each parent's, one line per hop, plus the grants applied at launch: write grants, read-only exceptions and the Git grants digest. `--json` returns `trace` and `grants`. Peer-placed runs do not support `--trace` yet (#1564, #1571).
- Generated [CLI](../reference/cli.md), [MCP tool](../reference/mcp-tools.md), [configuration key](../reference/config-keys.md) and Seatbelt references.

## Fixes

### Disk pressure

- Scheduled GC runs at load and hourly, with a default free-space floor of 10% of the state volume, at least 50 GiB. GC reclaims terminal attempts' temporary directories after one day, reports paths and byte estimates, and honours dry runs (#1780).
- Writer dispatch and resume check the lowest available space across the worktree, state and lane-cache volumes against the floor, while read-only lanes stay available. Refusals report the volume, available bytes, floor and GC remedy. GC alerts when space stays below the floor after collection, and `gc.alert_below` can only raise the threshold above it (#1780).
- `gc --dry-run` lists a merged worktree that would stay dirty after its output is pruned as retained with reason `dirty`, as `gc --apply` does (#1723).
- `provenant reconcile` and `provenant cancel` settle writer attempts left running across a reboot as `lost` and release their reservations. Worktree contents are kept for a resume (#1781).

### Providers

- Agy turns are no longer cut off at agy's 15-minute print timeout and run until the lane deadline (#1722).
- Read-only Agy lanes can read a `--read-root` outside their working directory (#1729).
- Failed Agy lanes keep partial response text, and a headless permission denial appears in the result and terminal reason (#1776).
- Agy writer lanes can run commands, which previously failed with "fork/exec /bin/zsh: operation not permitted". Writers get the exec grants Codex and Claude writers have (#1695).
- Claude dispatch reports credential read failures with a non-secret reason and no longer starts an OAuth refresh that could revoke a token used by other lanes. Corrupt stored credential JSON counts as a read failure. An expired token is still refreshed (#1789).
- OpenCode lanes no longer see entries of `~/.claude` or `~/.codex`, are no longer refused for projects under `/Users/<name>`, and no longer fail before launch on a filesystem-root grant anchor.

### Lanes, graphs and worktrees

- `lanes` shows the review line for any `review_required` lane, including one with no protected paths. A writer left off its lane branch fails with "writer HEAD is not the lane branch" (#1747).
- When a writer's delivery remote has no `HEAD`, protected-path attribution uses the lane's base branch on that remote. If nothing resolves, the lane start is the baseline and review is required (#1747).
- A failed automatic graph advance is visible: `fabric graph status` reports `advance_error` until a later advance succeeds. An unreadable writer reservation stalls only its own attempt, and `graph resume` from another directory in the project no longer conflicts (#1712).
- Fabric writer submissions report `worktree_unregistered` with the path when `git worktree add` created the tree without custody registration. Use `provenant worktree create <new-branch> --base <branch>` to create a registered writer at an existing branch's tip. Submit I/O errors and setup failures name the failing operation and path, and Git utility timeouts (5 s) name the operation (#1777).
- `worktree create` skips prunable Git registrations, so a deleted checkout no longer blocks new worktrees. Removal reports stale registrations with `git worktree prune` guidance (#1783).
- `worktree create --base <remote>/<branch>` fetches an unresolved branch from a configured remote even when the repository fetches only `main`, and unresolved base errors name the base (#1782).

### Configuration and documentation

- An unknown key in the `install`, `gc` or `retention` config sections reports schema rule `unknown_key` at the key's location instead of `type`.
- Invalid-path refusals read "path is not a permitted absolute, normalised path", cover paths refused for scope, name or breadth, and name the path.
