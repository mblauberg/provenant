# Provenant v1.1.0

**Date:** 27 October 2026

This release removes the v1.0.0 stability promise, narrows the Fabric MCP and CLI surface to one set of names and units, adds disk-pressure and provider-state cleanup, and changes how writer lanes report results. Every install's source digest changes once, so `check install` reports existing installs as stale until they are reinstalled.

Provenant makes no stability promise; see [stability](README.md#stability). Upgrade every host together: peers on different Fabric protocol versions refuse each other, and the peer protocol is now 5.

## Breaking changes

### Fabric MCP and CLI interface

- **Fabric MCP exposes eight tools.** Use `fabric_context` for identity and hosts, `fabric_lease` for `claim_*` and `landing_*` operations, and `fabric_run` with `op: submit` for submissions. The five superseded tool names are removed. Tool metadata advertises schema version 2.
- **Request durations use seconds.** Use `timeout_seconds`, `wait_seconds` and `lease_seconds`. Run and lane responses report `provider_seconds` instead of `provider_ms`, with fractional seconds keeping millisecond precision. The config key `limits.graph_timeout_ms` is now `limits.graph_timeout_seconds` (1 to 14,400, default 14,400).
- **`--since` takes seconds, a date or an RFC3339 timestamp.** This applies to `lanes`, `telemetry stats` and `telemetry trace`. Suffixes such as `24h` and `7d` are removed.
- **Route requests are tagged.** Submissions and CLI manifest tasks use `route` with `kind: model` (plus `provider` and `model`) or `kind: named` (plus `name`), and both accept optional `effort` inside `route`. Manifest tasks require this object; flat `model`, string `route` and task-level `effort` are removed. Graph routes also accept an optional `account` in `route` and every `routes` entry.
- **Output parts and payloads changed.** CLI and MCP output parts are `prompt`, `result`, `stderr` and `events`, and all four also work on peers. Use bare attempt IDs or an unambiguous full `run/task/attempt` reference. CLI output now uses the MCP payload `bytes: {encoding: utf8|base64, data: ...}` instead of separate `text` and `encoding` fields, and binary output uses padded base64 instead of JSON byte arrays. A clipped page stops before a split UTF-8 character, and an MCP `events` page holds as many whole events as fit `max_bytes`.
- **Fencing tokens use 32 lower-case hex digits.**
- **`route list --json` no longer reports `readiness` and `factor_basis_points`.** Listing never probes, so they were always `unknown_availability` and 10000. Resolve and dispatch receipts still record both for each candidate.
- **The CLI and MCP share one error category per run error.** A corrupt run record or artefact is `STATE_CORRUPT` on the CLI (not `IO`), and an invalid run request is `invalid_input` on MCP (not `state_corrupt`). An unavailable run owner is `OWNER_UNAVAILABLE` (not `UNSUPPORTED`). Continuation refusals for an unavailable provider session use `CONTINUATION_UNSUPPORTED`. Facade errors use `not_terminal` and `operation_conflict` instead of `conflict`, locally and on the peer wire (#1631, #1571).
- **`provenant output` on a terminal attempt with no requested part reports `NOT_FOUND` (exit 2).** It reported `NONTERMINAL` (exit 1) locally and `CONFLICT` over a peer. Over MCP the code is `not_found`. Active attempts still report `NONTERMINAL` (#1673).
- **The `reason` of an `uncertain` result from `provenant reconcile` is an object.** It has a `kind` (for example `writer_custody_unconfirmed`, `custody_not_provably_absent` or `guardian_not_observable`) and, where it applies, the underlying `error` text or the `reservation` path. It was free text. The human line is unchanged (#1571).
- **Task classes are removed.** `config show` no longer takes `--task-class`, presets no longer carry `task_classes`, and Fabric routes and submission tasks reject `task_class` (`fabric_run` with `op: submit` returns invalid input). Use a tagged model or named route. Old runs stay readable (#1571).

### Peer protocol and Fabric state

- **The Fabric peer protocol is 5.** Every request and reply envelope carries an integer `protocol`. Calls use one SSH connection and reject any other version, naming both; there is no capability negotiation and no support for older peers. Protocol 4 peers are refused before action decoding, and released peers' decode refusals and missing reply protocols identify protocol 1. The host listing reports the protocol observed in the reply (#1631, #1571, #1748, #1777).
- **The peer wire uses the MCP operation names** (`submit`, `hosts`, `claim_*` and `landing_*`). A peer error reply carries only its typed error; only `launch_unknown` names an operation ID.
- **Every peer request carries a `trace`** (sending host, actor and operation), and peer ingress refuses a request whose `trace.host` is not its `source_host`. Usage events under `usage.project_attribution` record the project as `trace.project` instead of `project_id`, so earlier `usage.jsonl` lines count in aggregate rows but no longer in per-project rows (#1571).
- **Fabric tasks and messages no longer accept `legacy` and `legacy_output_path`,** even as null. A store row or peer reply that carries one fails to decode. Migration 7 already strips them, so this affects only a pre-migration-7 binary still writing to the store, or such a peer.
- **Coordination receipts store the public request and result.** Retrying a claim, landing or task-proof operation ID recorded by an earlier build is refused as a reused ID; use a fresh one.
- **Graph checkpoints must record `launched` and `launch_actor` for each attempt.** A checkpoint without them is refused instead of being treated as launched and resumed under the current actor. Checkpoint envelopes under `fabric/graphs/<project>/graph-<id>.json` also require `execution.document` and `execution.directory`, which their digest covers. Existing checkpoints cannot be read or resumed. Finish active graphs with the previous release and archive their checkpoints before upgrading (#1712, #1713).
- **`hosts doctor HOST` requires the remote report's `peer_agent` field.** A remote build too old to report it is refused as an invalid report.

### Configuration

- **Eight advisory knobs are removed** because no code read them: `effort.shift`, `context.ceiling_tokens`, `repair.max_cycles`, `council.junior_size`, `routing.pool_mode`, `writing.final_polish`, `context.summary_tokens` and `quota.pace_tolerance`. A `[knobs]` entry or `--knob` override naming one is refused as an unknown key, as are `config set` and `config unset`. Delete any such line from `config.toml`. The `economy` and `rigorous` presets keep only their wired knobs, and `config set` no longer accepts `null`. The former defaults are chair judgement in `skills/orchestrate/SKILL.md` (#1571).
- **Routing config lives only under `[domains.routing]`.** A root `[routing]` table is refused as an unknown key. Move it, and note that `route set`, `route remove`, `route reset` and `route pacing` now write there (#1571).
- **`config set` and `config unset` use the `route` editor.** They refuse to rewrite a `config.toml` that does not already validate and report a domain error before writing. Route edits accept inline domain tables as well as table headers (#1571).
- **Manual `gc` reads `config.toml`, and an invalid config fails the command.** GC returns `GC` when provider-state retention reports errors (#1570).

### Garbage collection and retention

- **`gc` adds `--apply`** for merged worktree and declared output deletion. Bare `gc` still deletes orphaned and idle caches and previews these new classes; `--dry-run` previews all classes. Reinstall the scheduled agent to add `--apply` to its arguments.
- **GC JSON adds `worktree_cleanup` and `alerts`.** Each worktree cleanup has its own `dry_run` flag, independent of cache cleanup. Preview entries have `removed: false` and reason `would_remove`.
- **`[gc]` adds `alert_below` and per-project `regenerable` and `keep` settings.** Merged worktree deletion requires known-terminal lanes and merged commits of their own; fresh tips and first-parent ancestors remain.
- **GC reports locked or prunable entries as `locked_or_prunable` and omits the primary checkout.** A pruning or branch-settlement failure retains that entry and the sweep continues.
- **Terminal attempts lose provider state on a schedule.** Regenerable Codex caches go at settlement, known credential entries after 24 hours, and resumable provider state after `retention.provider_state_days` (default 7). Existing attempts are eligible on the first sweep. Expired resumes return `PROVIDER_STATE_EXPIRED` locally and `provider_state_expired` over MCP and peer calls. Transcripts move to `provider-history/`; results, captures, exit evidence and digests remain. Unclassified provider payloads are archived conservatively (#1570).
- **`disk report` counts provider state separately.** Its bytes move from `attempt_retained` to a `provider_state` class, and it no longer counts a `logs` entry in an attempt directory as retained, since nothing writes one. GC JSON adds `provider_state` with `removed`, `kept` and `errors`, `config show` adds the root `retention` section, and new candidate state records its adapter in `provider.txt` (#1570, #1571).

### Install, platform and routing

- **The source digest covers shipped source only.** It covers each workspace member's `src/`, `assets/` and `build.rs`, manifests, the lockfile, the toolchain and Cargo configuration, `examples/package-release.rs` and the bundled assets. Edits under a member's `tests/`, `benches/` and other `examples/` no longer change it.
- **Installer cut-over support is removed.** This covers the `--legacy-checkout` flag, the `LEGACY_CHECKOUT` error code, pre-1.0 cleanup and Git launcher ownership. `check install` no longer reports `legacy_entry`, `legacy_hook_conflict`, `legacy_instruction_variable` or `legacy_checkout_unavailable`. A receipt's `legacy` record is ignored and dropped on the next install write. Remove any Git hook launchers the cut-over installer placed under the recorded `git_hooks_dir` by hand, as they are no longer managed (#1571).
- **Process custody is supported only on macOS.** Linux provider launch and guardian setup return an explicit unsupported error, and existing `linux_kernel_children` settlement records are refused. Utility execution and process observation keep their Linux implementations. See the [supervisor spec](../specs/supervisor.md) (#1571).
- **`worktree remove NAME` defaults to the fetched upstream default branch,** falling back to the primary branch with a warning if fetching fails. An explicit `--integration` is honoured. Upstream Git calls time out after five seconds each.
- **Codex routing uses GPT-6.1 Sol and Terra.** Senior pairs Sol at medium effort with a Terra trial at high effort, both at weight 4, allowing low, medium and high. Junior adds a Terra trial at low effort and weight 2, allowing low and medium. Principal pairs Sol at high effort and weight 1, allowing medium, high and xhigh, with Claude Opus 5.5 at weight 1. Existing junior and senior members keep their weights. The retired Codex principal model has no alias, so update explicit model selections and pool overrides.
- **Terra and Sol keep exact-model efforts low to max, but every pool excludes max.** Sol gains one AA Intelligence Index point over xhigh at $0.72 versus $0.39 per task. Terra high and xhigh are unmeasured, so both trials and the split are to be revisited using lane telemetry. Benchmarks and sources are in the [model dossier](../model-dossier.md#solterra-benchmark-priors).

## Behaviour changes

### Writer lanes and delivery

- A writer lane that succeeds but leaves uncommitted edits and no new commit ends `uncommitted` instead of `succeeded`. The reason names the dirty paths (ignored paths and `.review-snapshots/` do not count). Host delivery does not run for it, and a graph node ends failed with no route fallback. `output --host` carries the attempt's `state` and `reason` (#1740, #1748).
- Completed writers with protected changes end as `review_required`, keep their candidate `head` and `protected_paths` in CLI and MCP lane output, and wait for chair review with no automatic delivery. `lanes --state review_required` works, and the menu bar attention view includes these lanes. Succeeded writers report their candidate `head` even without delivery.
- Protected-path checks exclude protected edits present at lane start and clean protected edits merged from upstream. If a delivery target ref or merge base cannot be resolved, the lane's start head is used so quarantine can finish.
- Run settlement advances pending Fabric graphs in the same project after releasing custody, so dependants start automatically. `graph resume` remains manual recovery after a crash when no later run settles (#1712).
- A child lane may name a different adapter or account than its parent. This is documented as intended (#1554).
- Dispatch probes accounts only for adapters the route, its pool or an explicit fallback can use. A broken login for an unreachable adapter no longer shows a skip line or runs that provider's commands (#1571).
- Host entries report `protocol` only when known. Mismatched peers stay in the list with `available: false`, their protocol and `reason: "peer_version"`.
- Install and check canonicalise `HOME` before resolving targets. A symlinked home resolves to its target, and a relative `HOME` is rejected.

### Garbage collection and tracing

- `provenant gc`, including the six-hour macOS schedule, also collects terminal provider state. Set `[retention] provider_state_days` (1 to 3650, default 7); it is reread at each sweep. `--dry-run` previews provider-state removals, and active attempts, retained reservations and pending continuations are protected (#1570).
- `provenant telemetry trace` writes one Perfetto process per host instead of per task, with the task in each thread name and the attempt's `Trace` in the slice args. A flow arrow joins an attempt to its parent when both are in the file. `--peers` also reads terminal attempts in each configured peer's newest 100 lanes, as `lanes --host` does, so Fabric and MCP submissions appear as well as `dispatch --host` runs. An unreachable peer is listed under `peers` in `--json` and skipped (#1571).

### Skills and workflow guidance

- TDD guidance requires spec-derived expectations and specific rejection errors, and requires reporting test and spec conflicts before proceeding. It names assertion weakening and test-input special cases, uses Rust examples and offers a fresh-context acceptance-test writer. Review guidance adds a five-question test rubric.
- Independent review briefs carry the target and rubric without the chair's hypothesis or expected verdict, and an unreadable rubric returns `incomplete`. Writers may contest findings with evidence and one re-audit; remaining disagreement is recorded as an accepted trade-off under existing authority and merge gates.
- Change specs live in issue bodies and expire with delivery, with evidence tags, explicit non-goals and a named post-delivery fate. Scratch citations get advisory warnings. See the [work-item workflow](../runbooks/github-workflow.md).
- Scope offers a provisional advisory fresh-reader check for non-trivial specs. Agent filings require observed evidence and independent triage, record filer provenance and defer checklist-epic leaves until lease. Ready has an advisory cap, and staleness follows evidence rather than timestamps.
- Skill changes require two near-miss negative fixtures per skill and, for behaviour changes, recorded with-and-without runs. `scripts/check-skill-negatives` inventories negative routes, and judgement-based results stay advisory. Orchestrate loads dispatch procedure from a reference and includes agent provenance in issue-filing briefs.
- The engineering-docs skill amends live ADRs in place, moves process and deferrals to their owners, separates invariant specs from generated reference, and requires owner and anchor lines and short canonical instruction files. See [the skill](../../skills/engineering-docs/SKILL.md).

## Additions

- On macOS, default-state installs include a per-user disk guard that checks space every two minutes. It warns and runs GC below 60 GiB, pauses matching build processes owned by the current user below 25 GiB, and resumes them at 50 GiB. Configure `[disk_guard]` in `config.toml` and rerun install to change thresholds, process names or the enable flag. Uninstall resumes saved paused processes before removing the agent (#1784).
- `provenant output RUN/TASK/ATTEMPT --trace` prints the attempt's trace (host, project, run, attempt, operation, actor and parent), then each parent's, one line per hop; `--json` returns a `trace` array. It also lists the grants applied at launch: write grants, read-only exceptions and the Git grants digest (a `grants` object in `--json`). A chain whose parents loop fails instead of printing. Attempt records, events and facts carry the same trace, with `null` for a field the writer did not know. Older records show no trace or grants, and peer-placed runs do not support `--trace` yet (#1564, #1571).
- Generated [CLI](../reference/cli.md), [MCP tool](../reference/mcp-tools.md), [configuration key](../reference/config-keys.md) and Seatbelt references, with a required regeneration check in CI.
- Advisory documentation reference and owner and anchor checks, and a weekly drift summary comment on the documentation epic.

## Fixes

### Disk pressure

- Disk exhaustion safeguards (#1780): scheduled GC runs at load and hourly, with a default free-space floor of 10% of the state volume, at least 50 GiB. GC reclaims terminal attempts' temporary directories after one day, reports paths and best-effort byte estimates, and honours dry runs. A temporary cleanup failure leaves credential expiry and provider-cache pruning eligible to run.
- Writer dispatch and resume check the lowest available space across the worktree, state and lane-cache volumes against the floor, while read-only lanes stay available. Graph runs and MCP submissions report the refusal's volume, available bytes, floor and GC remedy. Concurrent writers can each pass the check, which reserves no space. GC alerts when space stays below the floor after collection, and `gc.alert_below` can only raise the threshold above the floor. Rerun `provenant install` to update the agent.
- `gc --dry-run` lists a merged worktree that would stay dirty after its output is pruned as retained with reason `dirty`, as `gc --apply` does. It was previously omitted (#1723).
- `provenant reconcile` and `provenant cancel` settle writer attempts left running across a reboot as `lost` and release their reservations. Worktree contents and attempt telemetry are kept for a resume (#1781).

### Providers

- Agy turns are no longer cut off at agy's 15-minute print timeout. A long turn runs until the lane deadline and is reported as timed out, not as an empty result (#1722).
- Read-only Agy lanes can read a `--read-root` outside their working directory. These lanes previously failed with "provider result is empty or incomplete" (#1729).
- Failed Agy lanes keep partial response text. A headless permission denial appears in the result and terminal reason, even when the provider produced no answer, so `lanes` and `output --json` say which permission was denied (#1776).
- Agy writer lanes can run commands. Every `run_command` previously failed with "fork/exec /bin/zsh: operation not permitted". Agy now runs with `SHELL=/bin/zsh`, and writers get the exec grants Codex and Claude writers have: `/bin`, `/usr/bin`, `/usr/libexec`, Cargo, rustup, Git helpers, Homebrew and the working directory (#1695).
- Claude dispatch reports credential read failures with a non-secret reason. It no longer suggests another sign-in or starts an OAuth refresh that could revoke a token used by other running lanes. Corrupt stored credential JSON counts as a read failure and does not trigger refresh. An already expired token is still refreshed, and quota refresh keeps using file-backed credentials where that is the login's source (#1789).
- OpenCode lanes no longer see the entries of `~/.claude` or `~/.codex`. Discovery probes stop below the user's home, which also stops lanes in projects under `/Users/<name>` being refused as too broad. They also no longer fail before launch on a forbidden filesystem-root grant anchor.
- The free-route guidance says to omit `--effort` on OpenCode free models, which do not support it.

### Lanes, graphs and worktrees

- `lanes` shows the review line for any `review_required` lane, including one with no protected paths (#1747).
- A writer left off its lane branch fails with "writer HEAD is not the lane branch" instead of "writer head changed during quarantine" (#1747).
- When a writer's delivery remote has no `HEAD`, protected-path attribution uses the lane's base branch on that remote, so protected edits merged from it no longer count as the writer's own. It never uses another remote's refs; if neither resolves, the lane start is the baseline and review is required (#1747).
- A failed automatic graph advance is visible: `fabric graph status` reports `advance_error` until a later advance succeeds. An unreadable writer reservation stalls only its own attempt, not graph advancement for other attempts in the project, and `graph resume` from a different directory in the same project no longer conflicts (#1712).
- Fabric writer submissions report `worktree_unregistered` with the worktree path when `git worktree add` created the tree without Provenant's custody registration. An advisory claim does not register a writer; use `provenant worktree create <new-branch> --base <branch>` to create a registered writer at an existing branch's tip. Submit I/O errors keep their operation and the relevant absolute path when known, writer setup and check failures name the failing operation, and Git utility timeouts (5 s) name the operation that timed out (#1777).
- `worktree create` skips Git worktree registrations already marked prunable, so a deleted checkout does not block new worktrees, and leaves the stale registration intact. Removal reports stale registrations with `git worktree prune` guidance, and merged branch pruning skips missing checkouts (#1783).
- `worktree create --base <remote>/<branch>` fetches an unresolved branch from a configured remote even when the repository fetches only `main`, without changing its fetch refspec. Unresolved base errors name the requested base (#1782).

### Configuration and documentation

- An unknown key inside the `install`, `gc` or `retention` config sections reports schema rule `unknown_key` at the key's location instead of `type`. A wrong value type still reports `type`.
- Invalid-path refusals read "path is not a permitted absolute, normalised path", which also covers paths refused for scope, name or breadth, and they name the path.
- Runbook commands and authority are corrected, history is removed from living docs, and skill entrypoints are shorter, with detail moved to references.
