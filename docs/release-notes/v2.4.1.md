# Provenant v2.4.1

Released 19 November 2026.

This release restores the stale-artifact protection from v2.4.0 (#3561), which Cargo 1.100's new build layout had silently disabled. It also makes `run smoke` and `wait --pr` dependable on fresh heads and keeps system Git configuration out of sandboxed lanes.

## Fixes

- Age seeded Cargo dep-info under every build layout. Cargo 1.100 moved fingerprints from `.fingerprint/<unit>/` to `build/<package>/<hash>/fingerprint/`, so the aging pass found nothing and a seeded worktree could again reuse another branch's artifacts (#3561). The pass is now driven by the fingerprints: it finds them in a bounded walk, reads which dep-info each unit checks and ages exactly those files, so units of any kind and any layout are covered. A fingerprint it cannot read, a named dep-info that is missing, or a seed that names none is not published: the lane builds cold and reports `seed_layout_unrecognised`. A test builds with the pinned Cargo, including a member with a build script and a member that depends on another, and checks that all of them rebuild while registry-style dependencies stay fresh. (#3578)
- Make `provenant worktree seed-target PATH` work outside a lane. It resolves the toolchain as cargo and rustup do for that checkout (`rust-toolchain.toml`, with `RUSTUP_HOME` and `CARGO_HOME` defaulting to `$HOME/.rustup` and `$HOME/.cargo`), verifies it with the rules lanes use, and seeds from the newest compatible host seed. Every `not seeded` reason now says what differed, for example `toolchain_mismatch; expected rustc 1.100.0, found rustc 1.99.1`, and the command prints a repair step: build a seed with `provenant worktree seed-build` or wait for tick. The command also prints where its Cargo home came from. Differences are recorded in `cargo-target-setup.json` without paths or environment values. (#3578)
- Restore the macOS Cargo seed tests that #3581 left failing on `main`; seeding itself was unaffected. Their fixtures now match what `provenant worktree seed-build` publishes: a sealed, read-only generation whose target names its dep-info from Cargo fingerprints. The toolchain-override refusal test now runs on every Unix host and checks that the refusal names the variable, never its value. Pull requests that change the seed code, or another file a native macOS test group targets by package, now run those native tests, and `scripts/check-ci-suites` refuses a CI manifest that leaves such a package unwatched. (#3589)
- `scripts/collate-release-notes --check` now fails, naming file and line, on a fragment with a second section heading or content before its first heading, which collation used to drop or misfile; `scripts/prepare-release` runs the check before it changes anything. (#3574)
- A refused attempt whose record names no cause now reads `unrecorded` in `result` and `status`, instead of being reported as an access-policy refusal the host never observed. This covers refusals withdrawn before launch, queued proposals the host refuses, and graph attempts that were never launched. (#3569)
- A sandboxed lane no longer reads system Git configuration or inherits command-scope Git configuration. Its Git wrapper exports `GIT_CONFIG_NOSYSTEM` even when it supplies an identity config, launch no longer strips it, and the lane environment drops `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_*`, `GIT_CONFIG_VALUE_*` and `GIT_CONFIG_PARAMETERS` in favour of the token helper's own entries, so a system helper such as `osxkeychain` is not reached. The host global Git configuration is still included in full (#3584), and a lane that is not sandboxed keeps the host's helpers. (#3569)
- `provenant run smoke` and `provenant upgrade --verify` run from a primary checkout as well as a linked worktree. A node whose `when` condition does not hold is no longer inspected for writer scope, so the skipped write node cannot refuse a launch it takes no part in. Smoke runs its read-only nodes by default and its receipt names the node it skipped and why; `--worktree PATH`, or `--branch B --base REF`, also runs the write node. `upgrade --verify` provisions its write worktree on a scratch branch. (#3575)
- Every refusal of a graph launch input names the field that caused it, and `plan`, `patch` and `write_scope` fields are named too; the composite launch-control refusal names the first control given. The same holds for graph document, worktree, limit, target and host refusals on the peer, owner and graph-execution paths. (#3575)
- `wait --pr` no longer settles on the first pass of a fresh head before its Actions workflows exist. A reading that would settle stays pending until an Actions run is reported for the head or `domains.wait.actions_grace_seconds` (default 60; 0 disables) passes. Unavailable Actions runs warn once per wait, a timed-out `--until complete` wait keeps its last known line, failure lines bound and sanitise check names and links, and the spec says that runs stuck in `waiting` hold a complete wait until its timeout. (#3569)
