# Provenant v2.6.0

Released 21 November 2026.


## Breaking changes

- The `build_admission` port is removed. Action: move a repository wrapper to `build.strategy = "command"` with `build.command`. A leftover key warns as unknown. (#3655)

## Behaviour changes

- Build jobs now use a priority queue with aging. The `build.overflow` default is now `auto`, and the `build.clean` default is now `untracked`. (#3657)
- This repository runs build slots. (#3661)
- Credential-root overlaps warn and proceed with host access; isolated access retains credential denials and refusals. (#3712)
- Host-access lanes inherit the host environment, including credentials, whether sandboxed or not; isolated lanes retain the previous filtering. (#3712)
- `lanes.access=host` uses native provider homes, sessions and login for every adapter, including OpenCode; isolated lanes retain private homes. (#3712)
- OpenCode's profile now follows `lanes.access`: host-access lanes use the host XDG profile and service, isolated lanes use a private per-attempt profile. `providers.opencode.profile` is removed; a stored value is ignored with a warning that names `lanes.access`. (#3712)
- Host-access lanes can use the host SSH agent, including under a sandbox. (#3712)
- Host access accepts ordinary Git transport and linked continuation files, and warns when a sandbox backend is unavailable (#3712)

## Additions

- Warm verify slots are available, opt-in with `build.strategy = "slots"`. Admitted compiler jobs are capped at `[admission.build].slots`, and unchanged units are reused. Lanes, the chair and landing share one strategy. (#3656)
- `verify --commit` and `verify --affected` are available, and the landing Commands gate runs through the build strategy. (#3658)
- `provenant build status|report|reset|maintain` inspects and maintains build slots, and `build report` gives the soak verdict. (#3659-3660)
- Record the resolved lane access model and its source for each provider attempt. (#3712)

## Fixes

### CLI and install

- Every setting a domain accepts now has field metadata and a `config/harness-knobs.json` entry, including the account registration fields (adapter, label, key, directory and their limits, plans and directories) and the land override composition and branch fields. A parity test derives settings from the typed schemas and fails, naming any key metadata or the registry omits. (#3691)
- A read-only launch now selects the checked-out branch's fetched upstream, falling back to the remote default with a warning when no tracking configuration resolves, and names the tree it actually reads: an upstream pin reads the fetched commit while an unpinned launch reads the local checkout (#3714)
- `pr status` and `wait --pr` now embed the shared per-job CI digest in human and JSON output; compact CI output keeps non-test errors with their job, failed step and classification; and aggregate-gate cancellation is derived from job conclusions rather than a dependency field the jobs API does not return (#3647)
- The configuration completeness probe records every declared field even when an earlier value cannot be constructed, so a setting added after an unprobeable field can no longer hide from metadata or the registry; stranded-work reports now include interrupted merges and rebases with edits, dirty detached worktrees and changed lines beginning with `++` or `--` (#3691 #3650)
- `ci failures` reads each job log with `--allow-escape-sequences` and strips terminal control sequences before parsing, so a failed job is listed with its failed step and failing tests instead of being silently dropped; when a log genuinely cannot be read, the gh message is reported as unreadable evidence rather than as zero failures. The aggregate gate also checks every declared matrix member, so a missing member keeps the gate a failure with uncertain cause instead of a cancellation (#3727)
- `provenant config path` now reports the ProjectId binding directory used by the host-project ports reader, so following the path no longer creates a stray directory under `projects/`; the 64-hex target-seed key is used only for target-seed ownership. The binding inventory warns and skips an unrecognised entry instead of refusing every project, and the malformed-port and custody-inventory warnings it caused degrade to that single clear warning, while a corrupt recognised binding still refuses (#3732)

### Lanes and settlement

- A read-only task launched from a checkout behind its fetched upstream now reviews that upstream head by default instead of the stale local tree. The launch names the source ref and commit it used and why, and keeps the behind warning; `--source local` still reads the local checkout on purpose. (#3714)
- `provenant run review --pr N` now accepts `--head SHA` to pin the expected PR head. When the forge still reports a different head just after a push, the host re-reads it within a bounded wait and refuses with both SHAs named if the mismatch persists, so a review can no longer silently run against the previous commit. Without `--head`, a local remote-tracking tip ahead of the forge head adds a warning naming both commits. The launch receipt reports the pinned base and head. (#3728)
- Build admission no longer fails spuriously when another participant's queue
  lock or ticket disappears during a scan. A vanished entry is now treated as
  departed at every listing, stat and lock step; a waiter refuses a lock whose
  path was unlinked and replaced after it was taken, and recreates its own
  ticket lock if a reaper removes it before the flock lands. Real I/O failures
  still surface. (#3737)

### Accounts, quota and routing

- A model ID written without its provider segment, such as `opencode/hy4-flash-free` for the catalogued `opencode/opencode/hy4-flash-free`, now warns with the full catalogued ID (or every matching candidate) instead of claiming the model is not in the catalogue. When no registered account can serve such a model, the refusal names the unresolved account rather than reporting unverified readiness. (#3724)
- A recorded free-pool refusal no longer holds every lane on the account for a
  whole provider retry-after after the provider has recovered. A later
  successful launch on the same pool clears it with source `observed_success`,
  and `provenant quota tick` re-checks a free-pool refusal older than a bounded
  interval with the adapter's registered quota probe, keeping a refusal that
  the re-check confirms. (#3725)

### Pipelines and graphs

- `ci failures` now reports each failed job's failed step, failing tests with panic locations, and error lines from the job's own log as soon as that job ends, classifies cancelled and dependency-cancelled jobs separately from real failures, and labels failures in files the pull request did not touch as possibly unrelated; `pr status` and `wait --pr` point at the same digest (#3647)
- `pr status` reports a member whose head is contained in an open batch's head as superseded, shows the batch's CI and attributes the batch's changed files to the member that last touched them; a member whose head moved after batching is flagged. (#3648)

### Chair, inbox and console

- `provenant status` and `provenant worktree list` now report stranded work: a registered or project worktree with uncommitted edits and no live holder, named by branch and linked issue or PR where the branch carries one, with changed file and line counts, the age of the newest edit and the `run implement --worktree` command that adopts it. `gc` keeps and names the same work instead of letting a stopped lane's edits disappear during cleanup. A clean worktree, one held by a live lane and one whose holder cannot be determined are never called stranded; the report only observes state and never refuses. (#3650)
