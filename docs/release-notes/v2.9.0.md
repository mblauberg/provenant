# Provenant v2.9.0

Released 24 November 2026.

Provenant 2.9.0 lands the next-batch refactor. The JSON envelope moves to version 2, with typed warnings and typed `next` commands. Git remotes and default branches are declared or detected, never assumed to be `origin` and `main`. Writer settlement keeps a lane's unfinished Git operation and publishes its committed tip. OpenCode lanes report usage, retries and capacity correctly. This release also adds `provenant init`, `run implement --pr`, layered brief preambles, sourced read-only lane trees and `worktree locate`. Upgrade every host together.

## Breaking changes

- The JSON envelope is version 2 and carries a `warnings` array; warnings no
  longer print to stderr under `--json`. Repeated configuration and root
  warnings show once per change, and the state root's `config-warning-*` and
  `root-warning-*` marker files are removed on upgrade. Read warnings from the envelope's `warnings` array and accept `schema_version` 2. (#3778 #3813 #3812)
- Suggested next commands are typed `next` entries in the JSON envelope, each
  with an `argv` array of literal arguments and a `why` sentence. Command owners
  build these values, and the binary edge renders the human `next:` line from the
  same array, so JSON and human output cannot diverge. Flags equal to the
  caller's environment defaults (`--state-dir`, `--project`) are omitted from the
  printed command. Read suggested commands from the `next` arrays instead of
  scraping the printed line. (#3814)
- There is no compiled `main` or `master` default branch. The default comes
  from the port table's `git.default_branch`, then the remote's recorded HEAD
  (`refs/remotes/<remote>/HEAD`, which `git clone` sets), then the forge.
  A checkout with none of these refuses forge commands with
  `FORGE_CONTEXT_UNRESOLVED`, and GC retires no merged lane there. Declare
  `git.default_branch`, or run `git remote set-head <remote> --auto`.
  (#3288)

## Behaviour changes

- Port tables now declare `schema_version: 3`. A repository `.provenant/ports.json` that still declares 2 is read with the current schema after a `CONFIG_MALFORMED` warning: set `"schema_version": 3` in that file, or rerun init to regenerate it. The install migration updates state copies only, not repository files. (#3849)
- Unknown model, adapter, template and knob names now list close matches
  ranked by one shared ranker; names typed with capitals are lower-cased with
  a warning instead of being refused. (#3808)
- Limit, port, lane-access and sandbox receipts report their source with one
  shared layer vocabulary; upgrade rewrites stored spellings once. (#3777)
- `config show` reports the source of each setting leaf: its layer and origin.
  Port-table leaves such as `verify.remote` and `verify.base` report their own
  source rather than the port-level label, and `--full` also shows the layers
  each leaf shadowed. (#3777)
- Unknown graph, node, attempt, host, adapter and help targets now list close
  matches ranked by the shared ranker. (#3808)
- Approval carry now runs the port table's declared `verify.format` command
  instead of guessing a formatter from the verify tiers. With no declaration,
  stack detection supplies a default and the carry receipt names whether the
  command was detected or configured; setting `verify.format` to `none` turns
  format carry off and says so. (#3540)
- `output`, `result` and `status --full` now lead with what the harness observed
  and the verdict, then the lane's own claims. (#3444 #3807)
- A writer launched on an unheld worktree with uncommitted changes commits them as WIP and proceeds, by default; the adoption is reported with `WORKTREE_ADOPTED_DIRTY` naming the commit. A worktree another lane holds is still refused, and an explicit `lanes.writer_dirty = refuse` still refuses. (#3649)
- An existing branch behind its base now warns `BRANCH_BEHIND_BASE` and proceeds at its current tip instead of refusing; `--base` records the merge target and never resets the branch. (#3644)
- Every command resolves account references the same way and lists close
  matching labels on a miss. (#3506)
- Steering a lane that has just settled no longer refuses with `steer_target_refused`: by default the note is recorded for the lane's next follow-up and the follow-up is named in the output, while `lanes.steer_settled=warn` warns with the sourced setting and exits 0 without effect. (#3809)
- Token usage merges per adapter-declared semantics instead of the last report
  winning, and the usage ledger moves to v4 on upgrade. (#3709)

## Additions

- `provenant init` sets up a repository's port table from the detected remote,
  default branch and toolchain, printing each choice with its source. An
  existing `ports.json` is left untouched. (#3814)
- `provenant run implement --pr N` repairs a pull request from its CI failures: it resolves the PR's head branch and base through the forge, locates or creates the worktree, and appends the failing check names and bounded log tails to the brief. (#3500)
- A layered `lanes.brief_preamble` file carries standing lane rules, so briefs
  carry only the task. Host, project (`.provenant/config.toml`) and launch
  (`--preamble-file`) layers concatenate in that order with their sources shown;
  a layer may scope itself to writer, review or read-only, and a missing file
  warns while the launch proceeds. Writers' preambles also name the project's
  no-build `verify.static_checks` port entries to run before pushing, without
  refusing the push on failure. (#3498 #3652)
- A read-only lane's tree is now a sourced setting: `lanes.read_source` takes `auto` (the default advisory pin), `checkout`, `default_branch` or an explicit ref, with `lanes.read_source_fetch_first` fetching before the ref is read and `--source local|upstream` mapping onto the same resolver. The commit read is named in the warning and in `read_source` on the launch status and result, and the plan node of `implement --plan` reads the launch's `--base`. (#3512, #3360)
- The Git remote and protected branches can be declared in the port table;
  detection follows the branch upstream instead of assuming `origin`, and the
  configured forge policy now reaches every forge call. (#3288 #3505)
- `provenant land` can publish with the owner's admin authority when a ruleset
  demands a review the authenticated owner cannot give, if the host config
  grants `domains.pr.land.admin_publication = "when_review_unavailable"`; the
  retry runs only after land's gate passed and the receipt records the grant
  and its source. Batches derive their target from the members and pin a
  reviewed head per member with `--head N=SHA`. (#3191)
- Worktree layout roots may lie outside the checkout: the layout port accepts
  absolute and parent-relative roots from the repository or host port table,
  `config ports` reports each root with its source, and creation, listing,
  custody and GC treat a declared root like the default one. (#3285)
- Added `provenant worktree locate`, which resolves a branch, lane, attempt or
  pull request to its checkout path; `worktree list` and `status --json` rows
  now carry the checkout path, lane and base; `worktree remove` records the
  removed tip in `removed.jsonl` and prunes a branch merged into its base. (#3810)

## Fixes

- Attempt records written by v2.8.2 decode again after upgrade. A writable open
  of the run store now runs the base-13-to-14 migration once, which rewrites the
  stored records the provenance and usage renames made unreadable: flat
  provider-usage buckets move under `tokens` with their numbers preserved and
  the free-form source maps to the typed `stream` source; `route_policy` becomes
  `route`, a sandbox `restriction` or `platform` becomes a `constraint` beside
  the `host` layer and a `knob` becomes `host`, and resource-fact,
  setting-origin and port-binding spellings become their shared layer names;
  the `lane_ports` and `pacing_reserve` facts keep their `PortSettingSource` and
  `PacingSettingSource` names unchanged.
  Without this, status, resume and settlement failed to decode those rows. A
  malformed row is skipped and still fails only its own decode; a row already in
  the new shape is left byte-identical. No decoder accepts a retired spelling.
  (#3849, #3777, #3709)
- Host-project overlay and admission settings are read from the same directory
  project binding writes; upgrade moves any written under the other key.
  (#3777)
- Writer settlement checks for an in-progress Git operation in every directory
  the lane writes — its private Git and its candidate common directory — before
  it imports objects or publishes the branch. A lane's own unfinished operation
  warns, names its commit and retained directory, and publishes the committed
  tip without resetting it; only a host checkout left mid-operation refuses,
  before import, with its bytes unchanged. (#3407)
- Handoff, delivery, cloud and gc work with a remote that is not named `origin`
  and a default branch that is not `main`. (#3288)
- OpenCode lanes record per-step token usage and provider-stated cost, end on
  endless provider retries at the adapter's bound instead of the wall timeout,
  and treat upstream 5xx as capacity rather than a generic error. (#3706 #3708 #3709)
- An OpenCode route whose effort the model does not offer is refused at
  resolution with the valid variants listed, and the provider's
  "Variant unavailable" failure is classified as a route refusal with guidance
  instead of a model outage. (#3707)
- GC records the remote's advertised default as its HEAD after fetching it,
  including for a project bound at a bare repository, so merged lanes are
  retired against the real default branch. (#3288)
- `output --full` prints the host-fact header lines (changed files, stopped
  work, planner fallback, lane access) above the whole result; before, it
  printed only the result text. (#3444 #3807)
