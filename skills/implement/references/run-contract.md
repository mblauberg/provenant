# Software delivery contract

Delivery acceptance requires objective checks and tier-required independent
review. The chair records accepted scope, authority, exact artifact identity,
checks, reviews and any required user decision through the Rust workflow
owner. Promotion needs separate authority against that same accepted artifact.

## Receipt portability

Keep operational output in the selected state root and curate durable facts
into the owning project document and PR. Link the exact Git commit/tree and
review evidence. Do not recreate the retired RUN.json scaffold or Python binder.

## Terminalisation

Rust run records own attempts and terminal publication. Supervisor retains
custody until settlement; receipt failure never becomes a provider stop request.
No run-directory finaliser or driver lease is required.

## Post-merge continuity

The chair verifies the merged commit's required `ci-status` result and records
its relationship to the reviewed head before reporting acceptance. Do not
switch or update the frozen live primary checkout during the rewrite.
